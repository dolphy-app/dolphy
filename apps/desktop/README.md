# @dolphy/desktop

Настольное приложение: Electron + Vue 3 + Vite. Слой бизнес-логики (`@dolphy-app/engine`) живёт в `utilityProcess`, UI видит его как `LearningEngine` из `@dolphy-app/engine-contract`. Проект: `engine-ts/design/engine-ts-electron.md` (§9–§14).

## Архитектура

```
renderer (Vue, sandbox)      preload (CJS, sandbox)     main                         utilityProcess «dolphy-engine»
src/**  ─ LearningEngine ─►  window.dolphy.{engine,platform} shells + supervisors        electron/host
        ◄─ MessagePort (RpcRequest / RpcResponse / RpcPush) ─ порт выдаёт main ─►     dispatcher + engine
        ◄─ dolphy-ext://<id>/view.mjs (элементы ввода ответа) ─ протокол в main         SQLite (engine.db)
                                                                                        ExerciseTypes: каталог + клиент
                                                                                          │ MessageChannelMain (host-link)
                                                                                          ▼
                                                                                      utilityProcess «dolphy-ext-host»
                                                                                        electron/ext-host: рантайм расширений
                                                                                        dolphy.sql: fork воркера → ELECTRON_RUN_AS_NODE
```

Сборка (`vite build`) даёт `dist/` (renderer) и `dist-electron/{main,preload,host}`. Preload собирается в CJS (`index.cjs`): при `sandbox: true` Electron не грузит ESM-preload. Хост — ESM-бандл со всеми workspace-пакетами; снаружи остаётся только нативный `better-sqlite3` (N-API prebuild, в упаковке — `asarUnpack`). Вход `ext-host.js` (хост расширений) собирается тем же вызовом.

**Расширения.** Плагин Vite `dolphy:extensions` собирает `packages/ext-*` (`pnpm -F <пакет> build` → `dist-ext/`) и кладёт каталоги в `<outRoot>/extensions/<id>/` (в упаковке — `extraResources` → `Resources/extensions`, вне asar: `import()` и `fork` воркера SQL читают настоящие файлы). Пользовательские расширения — `<userData>/extensions/<id>/`, побеждают по `id`. Устройство, манифест и API — `docs/design/extensions.md`. CSP допускает скрипты только `'self'` и `dolphy-ext:`; протокол `dolphy-ext` отдаёт `.js`/`.mjs` из каталогов расширений с CORS (renderer грузится с `file://`).

**Настройки и вклады расширений.** «Настройки → Внешний вид»: плитки тем из расширений (`themes`) рядом со встроенными «Как в системе», «Светлая», «Тёмная». «Настройки → Обучение»: «Правило оценки» — встроенное Pass@N или правило из расширения (`gradePolicies`); сбой правила или пропавшее расширение — оценка по Pass@N. «Настройки → Расширения»: список расширений (поставка, пользовательское, разработка) с их вкладами по восьми точкам и причиной, по которой расширение не загрузилось или перекрыто. Блоки кода в Markdown заданий выводят рендереры содержимого (`markdownRenderers`, например `dolphy.math`); при сбое остаётся исходный текст и заметка.

**Живое применение расширений** (`docs/design/extensions.md`, «Живое применение»). Вклады в окне — реактивное хранилище (`shared/api/engine/contributions.ts`, `createContributionsStore`): читаются при запуске и после каждого `contributions-changed`; `ContributionsDto.generation` отбрасывает устаревший ответ, после перезапуска хоста движка (`connectEngine().onReconnect`) счётчик начинается заново. Хранилище раздаётся через `CONTRIBUTIONS_KEY` и читается реактивно (`useContributions()`): темы Vuetify регистрируются и удаляются на лету (`bindExtensionThemes`, `shared/lib/theme-registry.ts`; пропавшая выбранная тема — «Как в системе», сохранённое значение не меняется), `MarkdownView` перевыводит блоки, параметры правил оценки реактивны, `AnswerElement` и `IsolatedFrame` ключуются ревизией только у расширений `dev`. Модуль доверенного расширения грузится по адресу `?v=<revision>` (`shared/lib/extension-url.ts`). Уже определённый в окне custom element не заменить: `ensureAnswerElement`/`staleAnswerElements` (`shared/lib/answer-element.ts`) находят единственный такой случай, и «Настройки → Расширения» показывают баннер «Обновление применится после перезагрузки окна» (`pages/settings/model/reload-required.ts`).

**Изоляция расширений** (`docs/design/extensions.md`, «Права и изоляция»). Расширения не из поставки (пользовательские и из `DOLPHY_DEV_EXTENSIONS`) изолированы, пока пользователь не нажал «Доверять». Код исполняет ограниченный дочерний процесс: хост расширений запускает `process.execPath` с `ELECTRON_RUN_AS_NODE=1` и флагами режима разрешений Node; вход процесса — артефакт сборки `restricted/ext-restricted.mjs` (плагин Vite `dolphy:restricted-child`, `electron/ext-host/restricted-child.ts` → `<outRoot>/restricted/`; в упаковке — запись `{ "from": "restricted", "to": "restricted" }` в `extraResources` в `electron-builder.json`, вне asar: режим разрешений сверяет настоящие пути файлов). Интерфейс (элемент ввода ответа и рендерер содержимого) — в `<iframe sandbox="allow-scripts">`, страницу рамки отдаёт протокол `dolphy-ext` (`/__dolphy/frame.html`); CSP окна содержит `frame-src dolphy-ext:`. «Настройки → Расширения» у расширений не из поставки показывает заявленные разрешения, метку «Изолировано»/«Доверено» и переключатели «Включено» и «Доверять (без изоляции)» (состояние — в `engine.db`; для кода действует сразу, интерфейс, темы и рендереры — после «Перезагрузить окно»). Расширения из поставки не переключаются.

**Каталог и установка расширений** (`docs/design/extensions.md`, «Установка и каталог»). «Настройки → Расширения» — две вкладки, «Установленные» и «Каталог» (`pages/settings/ui/InstalledExtensions.vue`, `CatalogExtensions.vue`, диалог `InstallDialog.vue`; модели `pages/settings/model/{catalog,install,extensions}.ts`). Каталог: поиск, фильтр по виду вклада, карточка с разрешениями и вкладами, «Установить» → диалог → итог «Установлено. Расширение уже работает.» (перезагрузки нет); на «Установленных» — баннер «Доступно обновлений: N», «Обновить»/«Обновить все», флажок «Проверять обновления при запуске», «Удалить» (расширения с происхождением `user`), предупреждение об отзыве. Установщик живёт в процессе движка: `electron/host/installer.ts` (`createDesktopInstaller`: глобальный `fetch`, `<userData>/extensions`; `DEFAULT_EXTENSION_CATALOG_URL` — `https://dolphy-app.github.io/dolphy-extensions/index.json`), сеть из окна не ходит, CSP не менялась. Установка, удаление, «Включено», «Доверять» и правка в режиме разработчика применяются на лету (см. «Живое применение расширений» ниже): моста `window.dolphy.extensions.apply` и перезапуска хостов нет. Фоновая проверка обновлений при запуске — не чаще раза в 24 часа.

**Данные, настройки и события расширений** (`docs/design/extensions.md`, «Данные, настройки и события», ADR 0007). У включённого расширения с точкой `settings` в «Настройки → Расширения → Установленные» есть кнопка «Настройки»: диалог (`pages/settings/ui/ExtensionSettingsDialog.vue`, поля — `ExtensionSettingField.vue`, модель `pages/settings/model/extension-settings.ts`) рисует форму по определениям (переключатель, строка, число, список), значение уходит в движок сразу при изменении, отказ движка (граница, длина, вариант) показывается под полем и объявляется читалкой, «Сбросить» возвращает значения по умолчанию, работающее расширение видит изменение без перезагрузки. Блок «Данные» в карточке (`ExtensionData.vue`, модель `model/extension-data.ts`) показывает занятое (ключи и размер) и «Очистить данные» с подтверждением; в диалоге удаления флажок «Удалить данные расширения» (по умолчанию данные остаются). Разрешение «События обучения» (`learning.events`) и точки `settings` и `events` видны в диалоге установки, карточке каталога и списке установленных. Конец сессии окно сообщает движку один раз (`practice.finishSession`, `pages/session/model/session.ts`).

**Команды и панели расширений** (`docs/design/extensions.md`, «Команды», «Панели», ADR 0008). Палитра команд (`widgets/command-palette`, `features/extension-commands`) смонтирована в `App.vue`, поэтому открывается Ctrl/⌘+K на любой странице, включая сессию, и кнопкой «Команды» в боковом меню (`ShellLayout`, группа «Дополнительно»). Поиск без учёта регистра по названию, категории и id расширения; поле — `combobox`, список — `listbox` (`aria-activedescendant`), Escape возвращает фокус. Список команд берётся из реактивных вкладов (`contributions-changed`), выбранная строка держится за ключом команды. Команда выполняется одним вызовом `extensions.invokeCommand` (вне очереди движка); `notify` показывается уведомлением приложения (`role="status"`), `openPanel` открывает панель, ошибка — сообщением, текст расширения выводится как текст. Панели расширений — группа «Панели расширений» в боковом меню и страница `/ext/:extensionId/:panelId` (`pages/extension-panel`): «Назад», `h1` с фокусом при входе, рамка на всю высоту; пропавшая панель показывает пустое состояние со ссылкой на план дня. Рамка панели — тот же `PanelFrame.vue` и `frame-bridge.ts`, что у элемента ввода, в режиме `panel`: `iframe sandbox="allow-scripts"` даже у доверенного расширения; высоту задаёт приложение (рантайм `size` не шлёт); рамку к расширению привязывает приложение (`PanelBinding`), идентификатор из сообщения не читается; `ctx.call` — до 20 вызовов в секунду и 4 одновременных, срок 15 с; родителю уходит только Ctrl/⌘+K (`shortcut`). Рамка живёт под ключом `extensionId:panelId:revision`, поэтому обновление расширения пересоздаёт её без перезагрузки окна.

## UI

Интерфейс — Feature-Sliced Design (`app` → `pages` → `widgets` → `features` → `entities` → `shared`; `features` и `entities` заводятся, когда код нужен нескольким экранам: выбранный курс читают план дня и «Курсы», данные курсов — переключатель и «Курсы»). Алиас `@` → `src`. Компоненты — Vuetify 4, тема «индиго + бирюзовый» (светлая и тёмная). Renderer грузится через `file://`, поэтому роутер — на hash-истории. CSP разрешает шрифты (`font-src 'self' data:`) — без этого не грузятся иконки MDI.

**Локализация** — `vue-i18n` (Composition API), языки `ru` и `en`. Сообщения лежат в слайсе (`pages/<слайс>/i18n/{ru,en,index}.ts`), общие — в `shared/i18n`, оболочка — в `app/i18n`; `app/i18n/messages.ts` собирает каталог, `app/i18n/vue-i18n.d.ts` типизирует ключи по каталогу `ru` (опечатка в `t('…')` — ошибка `vue-tsc`, `en: typeof ru` не даёт разойтись наборам ключей). Русские формы — четыре варианта `ноль | один | несколько | много` (`russianPluralRule`), английские — три. Языки и тема выбираются в «Настройках → Внешний вид»; `system` берёт язык системы (неподдерживаемый — английский). Встроенные строки Vuetify берутся из того же каталога (адаптер `createVueI18nAdapter`). Не переводятся данные движка: названия курсов, уроков и упражнений, `feedback` раннера, тексты ошибок движка.

**Хранение настроек** — в `engine.db` (SQLite), не в файлах и не в `localStorage`: опции планировщика (только отличия от умолчаний), предпочтения, сохранённые фильтры и сессии, тема и язык интерфейса. Устройства не синхронизируют настройки друг с другом.

Прежние настройки в JSON (`dataDir/settings`: `user_preferences.json`, `filters/`, `study_sessions/`) при первом запуске переносятся в БД одной транзакцией (`importLegacySettings`, вызывается из `electron/host/boot.ts`). Отметка `legacy_settings_imported` в таблице `setting` делает перенос одноразовым; записи, уже лежащие в БД, не перезаписываются; битый файл — предупреждение в лог без частичного переноса, перенос повторится после исправления. Файлы остаются на месте и больше не читаются.

Layout берётся из `assets/wireframes-screens.pdf`, палитра — своя. Экраны реализуются по важности; данные — только из контракта `LearningEngine`, поэтому элементы wireframes без данных в движке (серия дней, время, «Reschedule», ИИ-действия) не рисуются.

**Визуальная система.** Цвета — только токены темы Vuetify (`app/providers/vuetify.ts`): акцентный градиент плана дня — токены `hero-start`/`hero-end`, а не hex в компоненте; у карточек нет `variant="outlined"` (он красит рамку в `currentColor` — белую в тёмной теме и почти чёрную в светлой): рамка мягкая, из глобального `VCard`. Заголовки страниц — `PageHeader` (`headline-large`), заголовки секций внутри страницы — `title-large`; отступы у `h1–h6` сброшены глобально (`app/styles/global.css`). Статус несёт значок и нейтральный текст (цвет только у значка): цветной 12-пиксельный текст статуса давал контраст 2.4–3.0:1. У `v-btn` нельзя использовать `block` во flex-колонке (`flex: 1 0 auto` растягивает кнопку): вместо него `w-100`. Настройки — вкладки сверху (`v-tabs`), а не второе боковое меню: контенту хватает ширины при узком окне. «Внешний вид»: тема — радио-группа плиток с образцом (`ThemeTile`: нативные `input type="radio"` — стрелки, `aria-checked` и focus без своего кода; образец рисуется из цветов самой темы, «Как в системе» — диагональ светлой и тёмной), язык — строка «название и описание слева, список справа», как в остальных настройках. Проверено в настоящем Electron: axe без нарушений на «Курсах» и «Внешнем виде», контраст текста ≥ 5.7:1 (светлая) и ≥ 6.3:1 (тёмная), окно 760 px без обрезанных элементов.

**Граф знаний** (`pages/graph`). Уроки выбранных курсов (`getGraph({rootIds: курсы, depth: 1, kinds: ['lesson'], limit: 2000})`) склеиваются с прогрессом (`getProgress({scope: {courseId}})`) в вид-модель (`lib/view.ts`: `buildGraphView`, `applyProgress`). Курс — контейнер-заголовок, узлы — уроки, упражнения не рисуются; рёбра `superseded` скрыты. Раскладка — `@dagrejs/dagre` слева направо (`lib/layout.ts`) **только по рёбрам `dependency`**: `encompassed` поверх пунктиром с подписью веса (переключатель «Показать охват») в ранжирование не идёт. Уроки без зависимостей лежат сеткой под связной частью. Раскладка считается в Web Worker (`lib/layout.worker.ts`, `model/use-layout.ts`): на графе в сотни уроков она занимает сотни миллисекунд и не должна блокировать интерфейс; она зависит только от структуры, поэтому событие `progress` обновляет статусы, оценки и счётчики (`model/graph.ts`) без повторной загрузки графа и без новой раскладки, а `library-reloaded` и `state-rebuilt` перестраивают структуру. Рендер, pan/zoom и `onlyRenderVisibleElements` — `@vue-flow/core`; узлы — Vue-компоненты, тема Vue Flow переопределена токенами Vuetify (`--v-theme-*`). Vue Flow совместим с CSP «запретить всё» (он не создаёт `<style>`, `eval` и воркеров, а стили узлов ставит атрибутами `style`, которые разрешает `style-src 'unsafe-inline'`), поэтому CSP не ослаблена; встроенную английскую подсказку клавиатурной доступности Vue Flow отключает `disable-keyboard-a11y`, вместо неё у узла `role="button"`, `aria-label` из vue-i18n, roving tabindex (в граф входит один Tab) и переход стрелками к ближайшему уроку. Курс берётся из `useCourseScope`, `?course=` выбирает курс при переходе и убирается из адреса. «Учить» ведёт в `session` с `?course=` урока: сессия строится по курсу, отдельного урока в её параметрах нет.

## Курсы и параллельное обучение

Несколько курсов изучаются параллельно и не смешиваются: выбранный курс сужает план дня, повторения и учебную сессию до себя. Курс не «включается» и не «завершается» — прогресс каждого хранится отдельно и не теряется при переключении.

- **Область (scope) — параметр запроса.** `plan.getDay` и `practice.getDue` принимают `courseIds` (пусто или нет поля — все курсы, неизвестный курс — `NOT_FOUND`); вне области упражнения не попадают ни в повторения, ни в новое, ни в закрепление основ. Переключение курса **ничего не пишет в журнал**, поэтому не влияет на другие устройства; для этого не годится blacklist — он журнальный и синхронизируется. Семантика — в `engine-ts/design/engine-ts-api.md` §4.1.
- **Выбранный курс** хранится в настройках движка (`UiSettingsDto.activeCourseId`, `engine.db`) и переживает перезапуск. Пропавший из библиотеки курс сбрасывается на «все курсы» (с записью в настройки), но только если в библиотеке есть курсы: пустая (сломанная) библиотека сохранённый выбор не стирает. `createCourseScope` создаётся в `app/main.ts` до монтирования и раздаётся через `provide`/`useCourseScope`.
- **План дня.** Под заголовком дата и «Всего в плане: N» (дата и план обновляются после полуночи), ниже переключатель курса («Все курсы» и по чипу на курс, с переносом строки; при одном курсе не показывается). Экран — одна колонка: акцентная карточка первого упражнения, затем список «Ближайших» (до пяти, «и ещё N»); у повторений в списке — значок и «запомнено» в процентах (цвет только у значка: цветной 12-пиксельный чип не проходит контраст; для упражнений вне очереди повторений процента нет). Отдельного списка «К повторению» нет: план уже содержит повторения. «Начать сессию» передаёт курс плана в `?course=`, поэтому сессия строится по тому же (`seed`, курс), что виден на экране. Пока курс в фокусе, повторения остальных курсов не подмешиваются, а показаны контурными чипами («Git · 3»): клик переключает на этот курс. Пустой план — одна карточка; в ней те же чипы, а если ждать нечего — кнопка «К курсам». Списки без действий не участвуют в Tab (`tabindex="-1"`), ссылки бокового меню — обычные остановки Tab. В светлой теме `medium-emphasis` — 0.7 (0.6 давало 4.29:1 у подзаголовков). Окно имеет минимальный размер 900×600 (`createWindowOptions`): при меньшей ширине боковое меню оставляет странице меньше 660px.
- **Экран «Курсы»** (образец — Vault из `assets/wireframes-screens.pdf`: карточки в сетке, поиск, списки состояния и сортировки). Колонки сетки считаются по ширине содержимого (`auto-fill, minmax(20rem, 1fr)`), а не окна. Карточка: плитка с инициалом (цвета темы по кругу), название, число уроков и попыток, описание, прогресс — доля освоенных уроков (одна метрика; статус «пройден» — все уроки освоены, поэтому «Освоен» при неполном прогрессе невозможен), состояние и число повторений. Единственная заливная кнопка на экране — у курса в фокусе («План курса») или, пока фокуса нет, у рекомендованного (`recommendCourse`: больше всего повторений → начатый последним → первый неначатый); у остальных «Учить» приглушена. Курс в фокусе выделен рамкой `primary`, вверху «Показывать все курсы» снимает фокус. Карточка «Add New Source» и потоковая загрузка не рисуются (нет данных в движке).
- **Dev-курсы:** `pnpm dev:seed` кладёт в библиотеку SQL-курс `sql_kb`, проверяемый курс `sql_analytics` и `git_kb`, `http_kb`, `js_kb` из `dev-library/`; `pnpm dev:reset` сбрасывает прогресс всех курсов (настройки, включая выбранный курс, остаются).
- **Курсы из git.** «Добавить из Git» на экране «Курсы» (`pages/courses/ui/AddRepositoryDialog.vue`, модель — `model/add-repository.ts`) принимает URL публичного `http(s)`-репозитория и необязательную ветку или тег; индикатор идёт по событиям `repository-progress`, «Отмена» вызывает `repositories.cancel` (id операции берётся из первого события, отмена до него откладывается). «Настройки → Библиотека → Репозитории» (`pages/settings/ui/RepositoriesCard.vue`) показывает URL, ветку, коммит, дату, число курсов и состояние, даёт «Обновить» («Уже актуально», если коммит на сервере совпал) и «Удалить» (прогресс в журнале сохраняется). Общие хелперы — `entities/repository` (проверка URL и ветки, разбор ошибок по `code` и `details.reason`, редьюсер прогресса). Движок (`repositories.*`, `@dolphy-app/engine-git`) держит на диске снимок коммита без `.git` в `<userData>/library/repositories/<id>/`, реестр — в таблице `repository` в `engine.db`; контракт — `engine-ts/design/engine-ts-api.md` §3.1. Приложение ходит в сеть только по действию ученика, автообновления нет.

## Dev-данные

Каталог `userData` dev-запуска — `~/Library/Application Support/@dolphy/desktop` (macOS), `$XDG_CONFIG_HOME` или `~/.config/@dolphy/desktop` (Linux), `%APPDATA%\@dolphy\desktop` (Windows; пути Linux и Windows заданы по документации Electron и не проверялись). Библиотека лежит в `library/`, журнал и настройки — в `data/engine.db`. Другой каталог задаёт `--user-data <каталог>`, например для упакованного приложения (`Dolphy`).

- `pnpm dev:seed` — курсы: `sql_kb` (образцовый, фикстура движка), `sql_analytics` и `git_kb`, `http_kb`, `js_kb` из `dev-library/`. `sql_analytics` («SQL: аналитика данных») — «настоящий» курс: 18 уроков, 72 упражнения на двух учебных базах (сотрудники/отделы и магазин), плотный граф `encompassed`, материал к каждому уроку; ответ пишется как `SELECT` и проверяется раннером на фикстуре с эталонным CSV (свои `fixtures/`, `checks/`, `solutions/` лежат внутри каталога курса, `engine-cli validate <каталог> --run-checks` прогоняет эталонные решения). `git_kb`, `http_kb`, `js_kb` — по 3 урока × 3 упражнения с самооценкой, на русском (раннера для Git/HTTP/JS нет). Повторный запуск перезаписывает эти файлы, чужие курсы не трогает. Приложение подхватит курсы при запуске или по «Настройки → Библиотека → Перечитать». Проверка библиотеки: `pnpm -F @dolphy-app/engine engine-cli validate <каталог>`.
- `pnpm dev:reset` — удаляет строки `log_entry`, `log_conflict`, `imported_segment`, `study_session`; `setting`, `saved_filter` и `meta` (id устройства) остаются. Правка БД в обход движка: журнал append-only и синхронизируется, поэтому команда только для dev-данных. Приложение должно быть закрыто: на macOS и Linux скрипт отказывается работать, если `SingletonLock` указывает на живой процесс (на Windows этой проверки нет).

## Смоук

Код смоука (шелл в main, мост в preload, сценарии в renderer, лог раннера в хосте) существует **только в смоук-сборке**: `DOLPHY_SMOKE_BUILD=1 vite build` выставляет через `define` константу `__DOLPHY_SMOKE_BUILD__` в `true` и пишет в `dist-smoke/`. В обычной сборке константа `false`, код за ней вырезается, а все имена смоука собраны в `shared/smoke.ts` и недостижимы: релизный `dist/` и `dist-electron/` не содержат ни `smoke` (без учёта регистра), ни id упражнения сценариев. Это проверяет `test/release-bundle.test.ts`: он сам собирает релизный вариант `vite build` во временный каталог (`DOLPHY_BUILD_OUT`) и ищет маркеры, а для смоук-варианта проверяет, что те же маркеры находятся (детектор не слепой). Сборка в упакованный `.app` идёт только из `dist-smoke/`, штатный `pnpm build` его не касается.

Режим включается `DOLPHY_SMOKE=1` в окружении (и только в смоук-сборке). Запуск — со скрытым окном, временным `userData` и копией библиотеки `sql-course` (`packages/engine/test/fixtures/libraries/sql-course/lib_kb`). Renderer выполняет сценарии через настоящий путь renderer → preload → main → хост → движок и сообщает итог main, тот печатает `DOLPHY_SMOKE_RESULT …` (в том числе `packaged`) и выходит с кодом 0 или 1:

1. `basic` — `library.getInfo`, `recordAttempt`, повторный `recordAttempt` (`duplicate: true`), событие `progress`;
2. `sql` — `beginAttempt` / `submitAnswer` (неверный и верный SQL) / `completeAttempt`; проверку выполняет расширение `dolphy.sql` в хосте расширений (воркер раннера порождён из `utilityProcess`);
3. `choice` — то же для расширения `dolphy.choice` (`view` содержит варианты, неверный и верный ответ);
4. `renderer` — скрипты элементов ввода (`dolphy.sql`, `dolphy.choice`) грузятся в renderer по `dolphy-ext://` под CSP и CORS `file://` и определяют свои теги (`ensureAnswerElement`);
5. `isolated` — упражнение «враждебного» расширения (`e2e/fixtures/hostile-extension`, копируется в `<userData>/extensions`): проверка идёт в ограниченном процессе, чтение `/etc/hosts`, запись, запуск процесса и поток запрещены, переменная `HOME` не видна. Сценарий и процессный тест `restricted.test.ts` — стражи на случай, если после обновления Electron режим разрешений перестанет применяться;
6. `crash` — убийство хоста, перезапуск супервизором, переподключение клиента, повтор идемпотентного вызова, `duplicate: true` после рестарта (журнал на диске), `progress` после переподключения.

- `pnpm smoke` — смоук-сборка и запуск неупакованного приложения (`electron dist-smoke/dist-electron/main/index.js`).
- `pnpm smoke:packaged` — та же сборка, упакованная `electron-builder --dir` без подписи (`CSC_IDENTITY_AUTO_DISCOVERY=false`) во временный каталог вне репозитория; запускается бинарник `.app`: хосты грузятся из `app.asar`, расширения — из `Resources/extensions` (вне asar), `better-sqlite3` — из `app.asar.unpacked`, воркер раннера SQL стартует с `ELECTRON_RUN_AS_NODE`. Скрипт сверяет `packaged` в отчёте, наличие `app.asar` и `app.asar.unpacked` и после выхода ждёт до 5 с, затем убивает и считает ошибкой любые оставшиеся процессы из каталога упакованного приложения. Проверено на macOS arm64; пути бинарника для Linux и Windows заданы по раскладке electron-builder и не проверялись.
- `--verbose` печатает stderr хоста и main и вывод сборки.

## E2E

`e2e/` — сценарии от лица ученика: настоящий Electron, клики и чтение экрана (Playwright `_electron` под vitest, `vitest.e2e.config.ts`); в корневой `pnpm test` не входят. `pnpm -F @dolphy/desktop e2e` сам собирает релизный бандл в `dist-e2e` (`DOLPHY_BUILD_OUT`, `dist` запущенного `pnpm dev` не трогается; `DOLPHY_E2E_SKIP_BUILD=1` переиспользует сборку) и гоняет каждый тест на временном `userData` с теми же курсами, что кладёт `dev:seed`. Приложение запускается с `--user-data-dir` и `--lang=ru` (селекторы — по русским строкам интерфейса), поэтому не конфликтует с dev-запуском. Окна показываются на экране.

- «Проходят дни»: приложение закрывается, `shiftJournalBack` сдвигает `at`/`recorded_at` всех записей `log_entry` временной БД в прошлое, приложение открывается снова — движок видит забывание, план дня заполняется повторениями. Так курс проходится целиком за один прогон.
- Журнал и настройки проверяются прямым чтением `engine.db` (`better-sqlite3`, read-only): число и оценки попыток, `source`, непрерывный `seq`, `ui.activeCourseId`.
- Сценарии: каталог курсов; «Учить» и фокус курса; Git до «Пройден 3 из 3» (оценки «5», с повторами через дни); один проход урока не открывает следующий; оценки «1» возвращаются в план через сутки; SQL и `dolphy.choice` — неверный ответ не пишется в журнал, верный пишется с `source=runner`, «Сдаться» даёт оценку 1; пользовательское расширение `acme.echo` (`e2e/fixtures/echo-extension`) грузится с диска через `dolphy-ext://`; пользовательская копия `dolphy.choice` побеждает расширение из поставки.
- Живое применение: `live-apply.e2e.test.ts` открывает второе окно (`DolphyApp.openWindow`: то же приложение и движок, своё соединение) и меняет расширения в нём, пока первое открыто на своём экране. Сценарии: тема, рендерер блоков, правило оценки и вид задания, установленные в другом окне, действуют в открытом без перезагрузки (блок `good` перевыводится рамкой, «Повторить» открывает упражнение, у которого вида ещё не было); удаление расширения выбранной темы — сразу «Как в системе», выбор возвращается с расширением; обновление при смонтированном элементе — введённый ответ и рамка целы, проверка идёт в новую версию, новое монтирование берёт новые файлы; R7 — баннер «Обновление применится после перезагрузки окна» только для доверенного расширения с уже определённым элементом, после «Перезагрузить окно» действует новая версия. Остальные e2e расширений проверяют то же тем, что `window.__marker`, поставленный до операции (`Client.markWindow`), пережил её: окно не перезагружалось.
- Перезапуск хоста движка: `engine-restart.e2e.test.ts` (расширение `acme.midnight` с темой из `userData`, две темы из каталога): после двух установок (поколение 2) хост убивается `SIGKILL` по `pid` из `app.getAppMetrics()` (`DolphyApp.killEngineHost`, без тестового кода в приложении); супервизор поднимает новый, окно переподключается без перезагрузки (`__marker` цел), выбранная тема действует, вклады перечитаны, а удаление расширения новым движком (поколение 1, меньше прежнего виденного) применяется сразу — защита от «виденного» поколения, не сброшенного в `createContributionsStore().reconnected()`.

## Режим разработчика

`DOLPHY_DEV_EXTENSIONS=<каталог>` в окружении процесса приложения (работает и для `pnpm dev`, и для упакованной сборки) добавляет каталог корнем расширений с происхождением `dev`. Он читается последним и побеждает пользовательский и поставляемый корни при совпадении id; обычно это выходной каталог `dolphy-ext build --watch` (`<проект>/dist-ext`, внутри `<id>/extension.json`). Расширения, не прошедшие проверку, видны в «Настройки → Расширения» как `invalid`.

`DOLPHY_APP_VERSION=x.y.z` задаёт версию приложения в несобранном режиме (`pnpm dev`, e2e): иначе проверка `minAppVersion` расширений не выполняется. В упакованной сборке переменная игнорируется, версию даёт приложение.

`DOLPHY_EXTENSION_CATALOG_URL=<адрес index.json>` подменяет адрес каталога расширений (`http(s)`). Читается только в несобранном приложении (`pnpm dev`, e2e); в упакованной сборке игнорируется, используется официальный. Неверное значение — предупреждение в логе движка и официальный адрес. Для локального каталога: `dolphy-ext catalog build --src <src> --ids <id> --out <site>`, статический сервер над `<site>` и `DOLPHY_EXTENSION_CATALOG_URL=http://localhost:<порт>/index.json pnpm dev` (см. `docs/design/extensions.md`, «Настройка для разработки»).

Main наблюдает за каталогом (`fs.watch` с `recursive`). Правка любого файла (кроме имён, начинающихся с `.`, и `node_modules`) отправляет хосту движка сообщение `reload-extensions`: движок перечитывает набор, хост расширений заменяет его, окно получает `contributions-changed`. Хосты не перезапускаются, окно не перезагружается (скрипты `dolphy-ext://` отдаются с `Cache-Control: no-cache`, у модулей окна в адресе ревизия файлов). Серия изменений (сборка пишет много файлов) объединяется задержкой 300 мс в одно применение; пока хост движка запускается, запрос повторяется после `ready`. Открытая сессия остаётся: смонтированные элементы ввода расширений с происхождением `dev` пересоздаются (состояние элемента может быть потеряно), блоки содержимого `dev` выводятся заново.

Ограничение: если каталога нет при запуске, в лог пишется предупреждение и наблюдение не включается; каталог, созданный позже, не наблюдается — приложение нужно перезапустить.

Расширение из `DOLPHY_DEV_EXTENSIONS` изолировано так же, как пользовательское, и получает объявленные в манифесте разрешения автоматически. Чтобы на время разработки снять ограничения, включите для него «Доверять» в «Настройки → Расширения»: изменение действует сразу.

## Безопасность

`sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`; навигация запрещена, `window.open` отклоняется; CSP — «запретить всё», скрипты `'self'` и `dolphy-ext:`, рамки — `frame-src dolphy-ext:` (в dev добавляется websocket для HMR); протокол `dolphy-ext` отдаёт только `.js`/`.mjs` из каталога расширения (выход за каталог — 404); расширения не из поставки изолированы: код — в ограниченном процессе (режим разрешений Node — «ремень безопасности», а не граница безопасности), интерфейс — в `iframe sandbox="allow-scripts"`; доверенные расширения и расширения из поставки не ограничены (`docs/design/extensions.md`, «Права и изоляция», «Пределы»); `ipcMain` принимает только от верхнего фрейма; мост не отдаёт `ipcRenderer`; аргументы RPC валидируются zod на хосте.
