# DDL и DML: проверка до изменения

**DDL** описывает структуру (`CREATE TABLE`, `CREATE VIEW`, `CREATE INDEX`), **DML** меняет данные (`INSERT`, `UPDATE`, `DELETE`). Проверяющий пускает в ответ только `SELECT`, поэтому в этом уроке вы учитесь тому, что делают профессионалы перед опасной командой: запрашиваете **то, что она затронет**.

- Перед `DELETE FROM t WHERE cond` выполняют `SELECT * FROM t WHERE cond` — то же условие, те же строки. Условие с `NULL` даёт UNKNOWN, и такие строки **не удаляются и не обновляются**.
- Перед `UPDATE t SET x = expr` выполняют `SELECT id, expr AS new_x FROM t WHERE ...`. В выражении действуют правила целочисленной арифметики: `salary * (1 + 10 / 100)` не меняет зарплату, потому что `10 / 100 = 0`.
- Структуру читают без чтения данных: `SELECT * FROM pragma_table_info('t')` (столбцы: `name`, `type`, `notnull`, `dflt_value`, `pk`), `sqlite_master` (таблицы, индексы, представления).
- Представление (`VIEW`) — сохранённый запрос; обращаются к нему как к таблице. Если внутри `LEFT JOIN` и `sum`, у пустой группы будет `NULL`.
