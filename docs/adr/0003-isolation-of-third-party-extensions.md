# 0003. Изоляция сторонних расширений: ограниченный процесс и изолированная рамка

Один ADR — одно решение. Уточняет ADR 0002 (простота автора важнее изоляции): риск, принятый там, снижается там, где платформа даёт настоящие механизмы. ADR 0001 (виды заданий — расширения в отдельном процессе) остаётся в силе.

## Контекст

После ADR 0002 сторонний код расширения исполнялся с правами пользователя в общем процессе хоста расширений, а его элементы интерфейса — в JS-контексте окна, рядом с `window.dolphy`. Продукту нужен каталог расширений от сторонних авторов; до открытия каталога требовалось ограничить ущерб от ошибочного и недобросовестного кода, не отказываясь от простой установки и простого авторинга.

Эксперименты в Electron 44.4.5 (Node 24) показали:
- `utilityProcess.fork(..., { execArgv: ['--permission'] })` флаг принимает, но не применяет: `process.permission` не определён, чтение, запись, запуск процессов и потоки разрешены;
- тот же бинарник, запущенный как Node (`ELECTRON_RUN_AS_NODE=1`) с `--permission --allow-fs-read=<каталог>`, режим разрешений применяет; IPC работает.

Документация Node называет режим разрешений «ремнём безопасности»: он защищает от непреднамеренного доступа доверенного кода и «не даёт гарантий при вредоносном коде».

## Решение

1. Расширение не из поставки, которому пользователь не доверил, исполняется в отдельном процессе, запущенном как Node с режимом разрешений: чтение только из каталога расширения (и файла входа), остальное запрещено, если не объявлено в манифесте (`permissions`: `library.read`, `process.spawn`, `worker.threads`, `native.addons`, `network`). Окружение процесса — одна переменная. Доступ к библиотеке курсов — через посредника в родителе, который сам проверяет разрешение.
2. Элементы ввода и рендереры содержимого таких расширений исполняются в `<iframe sandbox="allow-scripts">` без `allow-same-origin`, со страницей и CSP от протокола `dolphy-ext`; связь — `postMessage` с проверкой источника и формы сообщения.
3. Расширения из поставки не изолируются и не отключаются. Остальным пользователь в «Настройки → Расширения» может отключить или доверить расширение; доверие снимает обе изоляции (код — сразу, интерфейс — после перезагрузки окна). Режим разработчика изолирован так же, автор доверяет своё расширение переключателем.
4. Разрешения применяются автоматически по объявленному, без запроса у пользователя (простота установки, ADR 0002); пользователь видит их заранее.

## Рассмотренные варианты

- `utilityProcess` с `--permission` — не работает (см. выше).
- `--allow-fs-read=<корень библиотеки>` для `library.read` — давал бы чтение всего дерева; выбран посредник с `isSafePath`.
- Изоляция только расширений с опасными разрешениями — безопасное умолчание важнее экономии процесса.
- WASM/QuickJS как у Figma, отдельный origin через `allow-same-origin` — сложнее автору и платформе; не нужны для целей этой работы.
- Запрашивать разрешения у пользователя при каждом действии — противоречит простоте установки.

## Последствия

- Код расширения из каталога не читает чужие файлы, не пишет на диск, не запускает процессы и потоки без объявления; нарушение даёт ошибку внутри расширения (`ERR_ACCESS_DENIED`/`PermissionError`), хост и остальные расширения работают; зависший или падающий процесс убивается по дедлайну, при повторных падениях не запускается заново в течение минуты.
- Интерфейс недоверенного расширения не видит `window.dolphy`, DOM окна и хранилище приложения и не имеет сети (CSP рамки).
- Это уменьшение ущерба, а не граница безопасности:
  - режим разрешений Node не защищает от злонамеренного кода (документация Node);
  - сеть кода расширения не ограничена, `network` только информирует;
  - исчерпание CPU и памяти ограничено лишь дедлайном запроса;
  - `script-src dolphy-ext:` в CSP рамки разрешает скрипты любого расширения, не только своего;
  - доверенные расширения и расширения из поставки не ограничены;
  - подписи, проверки издателя и обзора кода нет.
- Применение `--permission` держится на запуске через `ELECTRON_RUN_AS_NODE`; при обновлении Electron это нужно перепроверять. Защита от тихой регрессии: сценарий смоука `isolated` (в том числе упакованной сборки) и процессный тест `restricted.test.ts` на реальном дочернем процессе.
- Открытый вопрос остаётся для каталога и автообновления: подпись и проверка релизов, ограничение сети (прокси/брандмауэр ОС), квоты ресурсов. Они потребуют нового ADR.
- Контракт `@dolphy-app/engine-contract` — версия 6 (настройки `extensions`, `isolated` в DTO).

## Проверка

Юнит-тесты `packages/extension-host` (таблица разрешений, раннер с подменой `spawn`, маршрутизация), процессный `restricted.test.ts` (враждебное расширение: чтение, запись, запуск процесса, поток, окружение, библиотека), `apps/desktop/test` (мост и рантайм рамки, протокол `dolphy-ext`), e2e `isolation-code`, `isolation-ui`, `extension-settings`, сценарий смоука `isolated` (распакованная и упакованная сборки; файл-маркер записи не должен появиться).
