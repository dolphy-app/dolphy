# 0004. Каталог расширений: репозиторий с CI-сборкой и статический индекс

Один ADR — одно решение. Опирается на ADR 0002 (простота автора и установки) и 0003 (изоляция сторонних расширений); не отменяет их.

## Контекст

Расширения ставились копированием каталога. Для сторонних авторов и пользователей нужны обзор, установка одним нажатием, совместимость версий и обновления. У продукта нет серверной части, нет учётной записи в npmjs (пакеты для авторов публикуются в GitHub Packages), а безопасность сторонних расширений ограничена изоляцией, которая не является границей безопасности (ADR 0003).

Образцы: Obsidian (индекс в GitHub-репозитории, релиз автора из фиксированного набора файлов, `versions.json`) и Vicinae (`vicinaehq/extensions`: исходники расширений в репозитории каталога, PR как заявка, CI проверяет, собирает и публикует).

## Решение

1. **Каталог — отдельный репозиторий** `dolphy-app/dolphy-extensions`. Исходники расширений лежат в `extensions/<id>/`; заявка — pull request; CI проверяет (`dolphy-ext catalog check`), собирает (`dolphy-ext catalog build`) и после слияния в `main` публикует результат в ветку `gh-pages`. Автор не выпускает релизы сам: публикуется ровно то, что было в PR.
2. **Индекс — статический `index.json`** на GitHub Pages, без сервера. Запись расширения хранит до пяти последних версий с `apiVersion`, `minAppVersion`, `permissions`, относительным `baseUrl` и списком файлов с размером и sha256 (надмножество `versions.json` Obsidian). Схема живёт в `@dolphy-app/extension-catalog` и общая для приложения и сборщика. Список `revoked` отзывает версии по диапазону.
3. **Единица установки — набор файлов**, а не архив: проверка sha256 и размера каждого файла, нет распаковки. Приложение ходит только на origin индекса, отклоняет редиректы на другой origin, ограничивает файлы (50 файлов, 10 МБ, допустимые расширения, безопасные пути), сверяет манифест установленного каталога с записью индекса и заменяет каталог расширения атомарно с откатом (`.staging` → `.trash`).
4. **Доверие:** ревью PR + сборка в CI из проверенного кода + sha256 в индексе. Подписи автора нет. Установка не автоматическая: обновления проверяются при запуске (раз в 24 часа, отключаемо) и ставятся по нажатию; отозванная версия отключается без возможности включить.
5. **Изменения вступают в силу после перезагрузки:** установка не подменяет реестр «на лету»; окно вызывает единый механизм перезапуска хостов и перезагрузки (тот же, что в режиме разработчика).
6. **Пакеты для авторов** (`extension-api`, `extension-sdk`, `extension-tools`, `create-extension`) публикуются в GitHub Packages под scope `@dolphy-app` вместе с релизом приложения; закрытые пакеты монорепозитория вшиваются в сборку.

## Рассмотренные варианты

- Собственный сервер каталога (поиск, статистика, модерация) — инфраструктура и эксплуатация, которых нет; статический индекс ищется на клиенте (Vicinae делает то же при лимите 500 записей).
- Релизы авторов как у Obsidian — публикуемый код может отличаться от того, что ревьюили; CI каталога убирает этот зазор.
- Архив `.zip` на версию — нужна библиотека распаковки и защита от path traversal; набор файлов проще проверять.
- Подпись пакетов ключом автора — нужна инфраструктура ключей и инструменты для авторов; отложено.
- Автообновление — чужой код менялся бы без ведома пользователя; выбрано уведомление.
- npmjs для пакетов авторов — у владельца продукта нет учётной записи; выбран GitHub Packages.

## Последствия

- Цепочка доверия держится на мейнтейнерах каталога и CI: кто может влить PR в `main` каталога, тот публикует код, который у пользователей будет работать в изоляции, но изоляция не является границей безопасности (ADR 0003).
- Индекс, как и файлы версий, защищены только HTTPS и контролем репозитория `gh-pages`; подписи индекса нет. Защита от отката: приложение отвергает индекс старее закэшированного.
- GitHub Packages требует токен (classic, `read:packages`) даже для установки публичных пакетов. Для авторов вне организации это порог входа, которого нет в npmjs. Перед открытием сообщества нужен новый ADR (публичные пакеты в npmjs или иной способ раздачи SDK).
- Репозиторий каталога должен быть публичным для работы Pages и анонимного чтения индекса приложением (бесплатный план организации). До публикации первых расширений он приватный и пустой по содержимому; CI каталога заработает после первого релиза приложения, опубликовавшего пакеты.
- Отзыв действует на расширения из каталога (origin `user` с метаданными установки); скопированные вручную и поставляемые не блокируются.
- Контракт `@dolphy-app/engine-contract` — версия 8 (сервис `extensions.catalog/install/uninstall/updates/setCheckUpdates`, событие `extensions-changed`).

## Проверка

`packages/extension-catalog` (схема, семвер, выбор версии), `packages/extension-install` (установщик на реальном `node:http`: кэш, ETag, офлайн, каждый отказ, откат замены, параллельные установки), `packages/extension-tools` (`catalog check|build`, интеграционный тест «сборщик → установщик»), `apps/desktop/e2e/catalog.e2e.test.ts` (установка, обновление, отзыв, офлайн, подмена файла), `tools/verify-packages.mjs` и workflow `packages.yml` (tarball'ы ставятся в чистый проект, генератор создаёт расширение, которое собирается и проходит проверку).
