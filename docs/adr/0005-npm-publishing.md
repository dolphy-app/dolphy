# 0005. Публикация пакетов авторов в npmjs

Один ADR — одно решение, до страницы. Принятый ADR по существу не меняется: отмена — новый ADR, в старом правится только `status` (`superseded by ADR-NNNN`). Правила — скилл `spec-workflow`.

## Контекст

ADR 0004 (п. 6) выбрал GitHub Packages для `extension-api`, `extension-sdk`, `extension-tools` и `create-extension`, потому что у владельца не было учётной записи npm. GitHub Packages требует персональный токен `read:packages` даже для установки публичных пакетов, а scope обязан совпадать с организацией GitHub. Теперь у продукта есть организация `dolphy-app` на npmjs и токен для автоматизации; репозиторий приватный.

## Решение

Мы публикуем четыре пакета в npmjs под scope `@dolphy-app` с `access: public` вместе с релизом приложения. Версия общая и равна версии релиза (`semantic-release` в корне). Публикация идёт из `release.yml` по токену `NPM_TOKEN`; провенанс и trusted publishing не используются, пока репозиторий приватный. Авторы ставят пакеты без токена и `.npmrc`.

## Рассмотренные варианты

- Оставить GitHub Packages — порог входа для авторов (токен даже для чтения), scope привязан к организации GitHub.
- Независимые версии пакетов (`multi-semantic-release`, Changesets) — лишняя инфраструктура, пока `extension-api` не расходится с приложением; вернёмся отдельной спекой.
- Trusted publishing (OIDC) — привязка к репозиторию и workflow, настраивается у существующего пакета; можно включить позже вместо токена.

## Последствия

- Пункт 6 ADR 0004 заменён этим ADR; остальные пункты 0004 в силе, а следствие про токен GitHub Packages снято.
- Ранее опубликованные версии в GitHub Packages остаются там; на них никто не ссылается.
- Токен `NPM_TOKEN` — секрет репозитория; его срок действия ограничен, истёкший токен ломает `publish-packages` (публикация пропускается с ошибкой job, релиз приложения не страдает).
- Имена `@dolphy-app/*` в npmjs принадлежат организации `dolphy-app` на npm; владелец организации отвечает за 2FA и доступ.

## Проверка

`pnpm build:packages && pnpm verify:packages` (tarball'ы ставятся без токена и `.npmrc`); `packages.yml` на PR делает `npm publish --dry-run` без токена.
