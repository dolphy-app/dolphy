# 0006. Живое применение расширений: общий снимок в движке и событие `contributions-changed`

Один ADR — одно решение. Опирается на ADR 0003 (изоляция) и 0004 (каталог); не отменяет их.

## Контекст

Раньше установка, обновление, удаление, «Включено», «Доверять» и правки в режиме разработчика перезапускали оба хоста и перезагружали окно: терялись открытая сессия и введённый ответ. Расширения обнаруживались дважды (хост движка и хост расширений), политика, каталог, реестр и установщик держали снимок по значению, окно читало вклады один раз при старте.

## Решение

Мы применяем изменения расширений на лету. Обнаружение принадлежит движку: `DiscoveryHolder` — изменяемый общий снимок, который читают политика, каталог видов, реестр и установщик; `reload()` перечитывает корни, заменяет снимок и отправляет весь набор хосту расширений (`replaceExtensions` с подтверждением, также после каждого подключения порта). Хост расширений сам расширения не ищет; `ExtensionRuntime.replace` атомарно меняет каталог и выводит из обращения активации изменившихся расширений после завершения вызовов в полёте. Код в процессе хоста обновляется загрузкой модуля с `?v=<версия>`. После применения движок публикует `{ type: 'contributions-changed', generation }`; `ContributionsDto.generation` — монотонный счётчик, по которому окно отбрасывает устаревшие ответы. Контракт — версия 9, новых RPC-методов нет.

Единственное исключение, требующее перезагрузки окна: расширение с интерфейсом в окне (из поставки или доверенное) обновлено до версии с другими файлами, а его элемент ввода уже определён — `customElements.define` повторить нельзя. Окно показывает баннер «Обновление применится после перезагрузки окна». Подмена тега (версионные имена) нарушила бы контракт `defineAnswerElement`, а изоляция по умолчанию отменила бы доверенный режим.

## Рассмотренные варианты

- Перезапуск хостов и перезагрузка окна (прежнее поведение) — теряет сессию и ответ, баннер «Перезагрузить сейчас» на каждую операцию.
- Версионные имена тегов — ломает контракт `defineAnswerElement` и стабильность стилей и тестов авторов.
- Принудительно изолированные рамки при обновлении — меняет модель доверия (ADR 0003), доверенный код теряет доступ к окну ради редкого случая.
- Независимое обнаружение в каждом хосте — наборы расходятся во время применения.

## Последствия

- Новая точка вклада не добавляет путь применения: всё идёт через `reload()`.
- `Supervisor.restart()` и `ExtSupervisor.restart()` удалены; хост расширений перезапускается только при сбое или по дедлайну `restart-ext-host`.
- Память старых версий кода в процессе хоста не освобождается до его перезапуска; зависимости доверенного кода из нескольких файлов обновляются после перезапуска хоста.
- Остаётся один случай перезагрузки окна (R7).

## Проверка

Юнит-тесты `extension-host`, `engine`, окна; e2e `apps/desktop/e2e` (`live-apply`, `catalog`, `extension-settings`, `dev-extensions`, `isolation-*`): маркер окна переживает операцию.
