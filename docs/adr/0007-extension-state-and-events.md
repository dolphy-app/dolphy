# 0007. Состояние расширений: данные в движке, настройки по манифесту, события обучения за разрешением

Один ADR — одно решение. Опирается на ADR 0003 (изоляция) и 0006 (живое применение); не отменяет их.

## Контекст

Расширение умело проверять ответы своего вида и считать оценку, но не помнило ничего между запусками, не имело настроек и не знало, что происходит в обучении. Любое расширение с состоянием («серия дней», статистика, настраиваемый вид задания) требовало правки ядра. При этом в приложении лежит личный журнал обучения, а сторонний код работает в ограниченном процессе без доступа к файлам и к `engine.db`.

## Решение

Мы даём расширению три возможности контекста `ctx` — `storage`, `settings` и `events` — и принимаем пять правил.

- **Данные принадлежат движку.** Хранилище кода (`extension_storage`) и значения настроек (`extension_setting`) лежат в `engine.db` (миграция 4) за портом `ExtensionDataStore` (адаптеры memory и sqlite, общий набор контрактных тестов). Хост расширений базу не открывает: он отправляет движку запросы `storage.*` и `settings.all` по тому же каналу, по которому движок вызывает хост; ограниченный процесс ходит через IPC раннера.
- **Хранилище защищают потолки, а не разрешение.** Ключ — до 128 символов, значение — до 64 КиБ, ключей — не более 256, всего — до 1 МиБ; превышение бросает `StorageQuotaError`, запись не происходит. Собственные данные расширения безобидны, а лишнее разрешение шумело бы в диалоге установки. Значения настроек считаются отдельно с теми же числами.
- **События обучения — данные ученика, поэтому за разрешением `learning.events`.** `session.started`, `session.finished` и `attempt.closed` несут только идентификаторы, оценку, исход и время: ответы, `spec`, обратная связь и текст упражнения в них не попадают, журнал расширению недоступен. Манифест с `contributes.events` без разрешения отклоняется; разрешение показано в диалоге установки, карточке каталога и списке установленных. Доставка асинхронная, по порядку, не более одного раза, с очередью 100 событий на расширение; сбой обработчика не влияет на запись попытки, оценку и ответ команды.
- **Настройки декларативны, форму рисует приложение.** `contributes.settings` описывает поля (`boolean`, `string`, `number`, `enum`), диалог «Настройки» строится по определениям, движок проверяет значения, изменение доходит до работающего расширения без перезагрузки. Расширение не получает интерфейса для настроек.
- **События идут отдельным внутренним приёмником, не `EngineEvent`.** `EngineEvent` — контракт, который видит окно; события обучения буферизуются тем же циклом `flush`, но уходят хосту сообщением `deliverEvent`. Приёмник не ждёт расширение и не может уронить команду; нет хоста — событие теряется.

Жизненный цикл данных: обновление и отключение их не трогают; удаление по умолчанию сохраняет (данные возвращаются при повторной установке), а флажок «Удалить данные расширения» в диалоге удаляет их вместе с расширением; «Очистить данные» в карточке стирает данные у установленного. Контракт `engine-contract` — 10.

## Рассмотренные варианты

- Файлы данных, которыми владеет хост — хост получает доступ к диску, данные расходятся с `engine.db`, нет единых квот и очистки; ограниченный процесс файлов писать не может.
- Разрешение на хранилище — шум в диалоге установки при безобидных данных; защита потолками надёжнее согласия, которое пользователь не может оценить.
- Показать расширению журнал обучения — раскрывает личные данные целиком; поток событий с минимальными полями закрывает задачи «серия» и «статистика».
- Императивный интерфейс настроек, который рисует расширение — нужна ещё одна рамка и ещё один канал, формы разнятся; декларативные поля проще проверить и локализовать приложением.
- События через `EngineEvent` — расширяет видимый окну контракт, смешивает потребителей и позволяет медленному расширению задерживать шину.

## Последствия

- Канал движок ↔ хост двусторонний; запросы хоста не взводят таймер перезапуска. Новые сообщения: `storage.*`, `settings.all`, `settingChanged`, `deliverEvent`.
- `practice.finishSession` — новая идемпотентная команда: движок не знал о конце сессии. Попытки `placement.finish`, дубликаты, импорт и синхронизация событий не дают.
- Подписи настроек — данные расширения, не локализуются приложением (как у тем).
- Данные расширений локальные: в журнал, синхронизацию и экспорт не попадают.
- Старые приложения 0.2.x отвергнут индекс каталога с ключами `settings` и `events` целиком; публичный каталог пока пуст, терпимый разбор записи — отдельная задача.
- Команды и панели расширений остаются вне границ.
