# 0009. Единая точка входа расширения: один `src/index.ts`, манифест статичен, типы строятся из него

Один ADR — одно решение. Уточняет ADR 0002 (простота авторинга): способ собрать и описать код автора меняется, а граница «манифест — данные, код — только в среде расширения» (ADR 0002, 0003, 0004) остаётся прежней.

## Контекст

Расширение с интерфейсом требовало россыпи исходников по числу контекстов исполнения: `src/main.ts` (процесс расширений), `src/view.ts`, `src/panel.ts`, `src/markdown.ts` (окно и рамка). Идентификаторы видов, панелей, команд и настроек автор переписывал вручную в манифесте и в коде, расхождение находилось только при запуске. `defineAnswerElement` регистрировал custom element при импорте, поэтому файл вида нельзя было импортировать в тестах в Node. Раскладка результата (`main.mjs`, `view.mjs`, `panel.mjs`, `markdown.mjs`) при этом уже определена манифестом и читается приложением, каталогом и установщиком.

## Решение

Мы принимаем четыре правила.

- **Автор пишет один `src/index.ts`** с именованными экспортами `host` (`defineExtension`), `views`, `panels`, `markdown`. Сборка выдаёт прежние файлы с прежними именами из манифеста: для каждого выходного файла создаётся виртуальная обвязка, импортирующая из `src/index.ts` только нужный экспорт, и собирается своим вызовом bundler. Общие файлы диспетчеризуются по id, общих чанков нет. Код хоста не попадает в браузерные файлы, а `node:*` в них — ошибка сборки.
- **Манифест остаётся статичным, id в коде типизируются по нему.** `extension.json` — единственное объявление и читается без исполнения кода. `dolphy-ext types` пишет из него `.dolphy/ids.d.ts`; записи `defineExtension`, `views`, `panels`, `markdown`, `ctx.settings`, `ctx.commands`, `ctx.events` требуют ровно объявленные id. Сборка дополнительно сверяет ключи записей с манифестом, ключи читаются статически (литерал, константа, `as const`/`satisfies`, относительный реэкспорт; спред, вычисляемый ключ и импорт из пакета — ошибка).
- **Код автора исполняется только в среде автора.** Сборка, `types`, `validate`, установка и `dolphy-ext catalog check` код расширения не исполняют; побочных эффектов при импорте нет (`define…` — чистые описания, регистрация custom element — в сгенерированной обвязке браузерного файла).
- **Чистый переход.** Старая раскладка (`src/main.ts`, `src/view.ts`, `src/panel.ts`, `src/markdown.ts`) не собирается и не определяется автоматически; ошибка сборки называет найденные старые файлы и шаги переноса. `defineAnswerElement` заменён на `defineAnswerView` без алиаса. Пакеты авторов ещё не опубликованы (ADR 0005), поэтому совместимость не нужна.

Контракт `engine-contract`, протокол хоста, каталог и установщик не меняются. Меняется публичная поверхность `extension-sdk`, `extension-tools`, `create-extension`, `extension-api` (типы описаний видов переименованы вместе с функцией, `ExtensionContext` и `PanelContext` SDK сужены до объявленных id).

## Рассмотренные варианты

- Генерировать `extension.json` из кода — требует исполнять код автора при сборке и при проверке каталога, то есть чужой код непроверенных PR; ломает самоописываемость каталога исходников (`CHECK-001`…`CHECK-016`) и дублирует JSON Schema в TypeScript. Отвергнуто.
- Автоопределение обеих раскладок — две поддерживаемые формы, двойная документация и тесты, а совместимость нужна только пакетам, которых нет в npmjs.
- Отдельные default-экспорты по файлам — прежняя россыпь и прежнее ручное дублирование id; ничего не решает.
- Один default-экспорт `defineExtensionApp({ host, views, … })` — вызов не помечается чистым без потери отсечения кода по контекстам, а сборка не может прочитать ключи, не исполняя вызов. Именованные экспорты читаются статически.
- Только регистрация при выполнении (`ctx.registerView(...)` и т. п.) — типы по манифесту невозможны, сверка с манифестом — только при запуске, браузерные файлы потянули бы код хоста.

## Последствия

- Типы id требуют генерации: `as const`-импорт JSON не сохраняет литеральные типы, поэтому в проекте есть сгенерированный `.dolphy/ids.d.ts` (в `tsconfig` указан по имени файла, в git не хранится).
- Правила для авторов: верхний уровень `src/index.ts` — только объявления; библиотека, которую тянет код хоста, объявляет `"sideEffects": false`; ключи записей читаются статически.
- Отмена потребует вернуть раскладку по файлам или менять формат манифеста: поэтому решение оформлено ADR.
