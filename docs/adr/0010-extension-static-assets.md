# 0010. Статические ресурсы расширений: файлы через каталог, два индекса, CSP рамки на расширение

Один ADR — одно решение. Дополняет ADR 0004 (каталог: набор файлов версии, допустимые расширения и потолки п. 3 расширены ресурсами) и снимает известный предел №5 ADR 0003 («`script-src dolphy-ext:` в CSP рамки разрешает скрипты любого расширения»).

## Контекст

- Каталог принимал только `json`, `js`, `mjs`, `md`, `txt`, протокол `dolphy-ext` отдавал только `.js`/`.mjs`, значка у расширения не было. Панели, элементы ввода и рендереры в рамке не могли подключить таблицу стилей, изображение или шрифт.
- Выпущенные приложения разбирают индекс строго (`strictObject`, `schemaVersion: 1`): любой неизвестный ключ, тип файла или значение разрешения делает каталог недоступным целиком (тот же эффект ADR 0007 назвал отдельной задачей).
- Идентичность каталога — адрес `index.json`: он записан в `.dolphy-install.json` установленных расширений, по нему идут обновления и отзыв. Другой адрес оставил бы их без обновлений.
- CSP рамки называла схему `dolphy-ext:` целиком, поэтому рамка могла загрузить скрипт, стиль, изображение или шрифт чужого расширения. CSP окна (`img-src 'self' data:`) не рассчитана на ресурсы расширений, а каталог читает движок, не окно.

## Решение

Мы принимаем пять правил.

- **Ресурсы — обычные файлы версии.** К прежним типам добавлены `css`, `svg`, `png`, `webp`, `jpg`, `jpeg`, `woff2` с потолками на файл (`ASSET_LIMITS`), до 100 файлов и 10 МБ на версию; единица установки по-прежнему набор файлов с `sha256`, не архив. Это статические данные: код в них не исполняется.
- **Совместимость — два индекса.** `dolphy-ext catalog build` всегда пишет вместе, с одним `generatedAt`, `index.json` (формат 1: подмножество, которое разбирает выпущенное приложение) и `index.v2.json` (формат 2: полный, со значком и ресурсами). Новое приложение читает `index.v2.json` рядом с адресом каталога и при 404 берёт `index.json`; идентичность каталога остаётся адресом `index.json`. Разбор в приложении терпим: неизвестные ключи отбрасываются, непонятная запись или версия пропускается с предупреждением, а не отвергает каталог (кроме `revoked`: непонятный отзыв отвергает индекс).
- **Проверка дважды.** Статически при публикации: один модуль (`extension-tools/src/catalog/assets.ts`) служит `catalog check`, `catalog build` и `dolphy-ext build` — тип по содержимому, потолки, пиксели, SVG по белому списку, CSS без внешних адресов. И при выдаче: протокол не доверяет каталогу (режим разработчика и скопированные вручную каталоги его проверок не проходили) — `realpath` внутри каталога, запрет ссылок для ресурсов, потолок размера по типу, `nosniff`, SVG с CSP `sandbox`.
- **CSP рамки строится на расширение.** `script-src`, `style-src`, `img-src` и `font-src` называют только `dolphy-ext://<id>` этого расширения. Предел №5 ADR 0003 снят для скриптов, стилей, изображений и шрифтов. Это проверено в Electron 44.4.5 (Chromium 152.0.7977.130): на схеме `standard + secure + supportFetchAPI + corsEnabled` и непрозрачном origin рамки свой хост загружается, чужой блокируется до запроса к протоколу, а CSP на уровне схемы пропускает чужой (контроль).
- **Значок — растровая производная манифеста.** `icon` в `extension.json` (`.png` или `.webp`, квадрат 64–512 px, до 16 КиБ); `catalog build` кладёт его в версию `index.v2.json` как `data:`-URI, установщик сверяет его с файлом версии. Окно показывает его 32 px и не получает других ресурсов расширений: CSP окна не меняется.

## Рассмотренные варианты

- Повысить `schemaVersion` на том же адресе — выпущенное приложение отвергает индекс целиком и теряет каталог.
- Новый адрес каталога — осиротит установленные расширения: `catalogUrl` совпадает с адресом `index.json`, обновления и отзыв перестанут действовать.
- Только встроенные ресурсы (`?inline`, `data:`) без новых типов файлов — шрифты и большие изображения раздувают код, не кэшируются отдельно; значок так не решается. Встроенный путь остаётся для мелочи.
- Отдавать ресурсы окну (расширить CSP окна) — окно доверенное, и расширенная CSP сделала бы ресурсы всех расширений частью его поверхности; темы с CSS и шрифтами откладываются.
- SVG-значок — SVG остаётся документом; в рамке его безопасность держит белый список, а окно рисует значок до установки, поэтому значок только растровый.
- Значок отдельным файлом по сети из окна — сеть есть только у движка, а окну значок нужен до установки и на каждую карточку.
- Чёрный список SVG и CSS — всегда неполон; принимается только перечисленное.

## Последствия

- Публикующий конвейер обязан выкладывать оба индекса вместе; без `index.json` ломаются выпущенные приложения, без `index.v2.json` новое приложение не видит значков и ресурсов. `index.json` — подмножество: версии с новыми типами файлов, значком, более чем 50 файлами, разрешением `learning.events` и записи со сводкой `settings`, `events`, `commands`, `panels` выпущенные приложения не увидят.
- Индекс вырос до 16 МБ (значок до ~22 КБ на версию). Новые типы файлов и потолки — только в общих константах `@dolphy-app/extension-catalog`; тип ресурса затрагивает проверки, протокол и CSP вместе.
- Узкий источник в CSP опирается на поведение Chromium для нестандартной схемы: при обновлении Electron это проверяют e2e «враждебное расширение» и тест заголовка. Если проверка начнёт падать, откат — CSP на уровне схемы с возвратом предела №5 и новой записью в ADR.
- Окно ресурсы расширений по протоколу не получает: темы с CSS и шрифтами, значок панели в меню и палитре, подпись индекса — отдельные решения. Доверенные расширения и расширения из поставки в окне не ограничены (п. 6 ADR 0003).
- Отмена потребует менять формат индекса, протокол и CSP рамки: поэтому решение оформлено ADR.
