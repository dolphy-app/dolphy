# 0011. Fuses Electron и `RunAsNode`: оставить, компенсировать остальными мерами

Один ADR — одно решение. Дополняет [ADR 0003](0003-isolation-of-third-party-extensions.md) (ограниченный процесс запускается как `ELECTRON_RUN_AS_NODE`).

## Контекст

- Ограниченный процесс расширений и рабочий процесс `dolphy.sql` запускаются как Node: `process.execPath` с `ELECTRON_RUN_AS_NODE=1`. Без fuse `RunAsNode` `child_process.fork` бросает ошибку, Electron советует `utilityProcess`; нам он не подходит: `--permission` через `utilityProcess.execArgv` в Electron 44 игнорируется (ADR 0003).
- До работы ни один fuse не был настроен (умолчания Electron 44). Документация Electron ([fuses](https://www.electronjs.org/docs/latest/tutorial/fuses), [security](https://www.electronjs.org/docs/latest/tutorial/security)) называет `nodeOptions` и `nodeCliInspect` безопасными к отключению для большинства приложений и рекомендует проверку целостности asar.
- Прирост риска от `RunAsNode` — локальный атакующий, который уже исполняет код от имени пользователя: подписанный бинарник приложения даёт ему интерпретатор (living-off-the-land; на macOS — наследование разрешений TCC; корпоративные списки разрешённых программ).
- Решение владельца (2026-10-02): не усложнять, «делать как в Obsidian и других наблюдаемых системах» — без песочницы кода расширений сверх существующей, плюс стандартный чек-лист Electron и fuses. Obsidian запускает плагины без песочницы в рендерере (Restricted Mode и проверка релизов); VS Code запускает расширения в хосте расширений без песочницы безопасности (модель доверия). Конфигурацию fuses VS Code, Slack, Notion и других проверить не удалось — утверждений о ней нет.
- Попутно найдено: упакованное приложение на `develop` не запускалось из-за отсутствия зависимости `zod` (внесено этапом 5 расширений, не выпускалось; v0.2.0 не затронут). Поломку поймал только `smoke:packaged`, которого в CI нет.

## Решение

Мы оставляем `RunAsNode` включённым и компенсируем остальным. Итоговая схема fuses (`electron-builder.json`, `electronFuses`):

| Fuse | Значение |
| --- | --- |
| `RunAsNode` | включён (обязательный компромисс) |
| `EnableNodeOptionsEnvironmentVariable` | выключен |
| `EnableNodeCliInspectArguments` | выключен |
| `EnableEmbeddedAsarIntegrityValidation` | включён |
| `OnlyLoadAppFromAsar` | включён |
| `EnableCookieEncryption` | выключен |
| `GrantFileProtocolExtraPrivileges` | **включён**: измерено, что с выключенным fuse упакованное приложение не загружает `index.html` из `app.asar` (`ERR_FILE_NOT_FOUND`); пересмотр — при переносе окна на собственный протокол |

Остальные меры: охрана любого `webContents` (навигация, окна, `<webview>`), отклонение всех запросов разрешений сеанса, `Permissions-Policy` у страниц рамок `dolphy-ext`, проверка схемы fuses готового бинарника в `pnpm smoke:packaged`.

## Рассмотренные варианты

- Отдельный бинарник Node в поставке — 50–120 МБ на платформу, подпись и сопровождение; переносит риск «чужого интерпретатора», не снимает.
- Node SEA — те же затраты и сопровождение, режим разрешений для него не проверен.
- `utilityProcess` с `--permission` — флаг игнорируется в Electron 44.
- Песочница ОС (macOS sandboxed helper, задания Windows, bubblewrap на Linux) — единственный путь к сети и квотам; дорого, три платформы; отложено.
- Среда WASM/QuickJS (стиль Figma) — смена модели авторинга расширений.

## Последствия

- Сеть кода расширения не ограничивается: на Node 24 нет `--allow-net` (появился в Node 25), Electron 44–46 встраивают Node 24. Квот процессора и памяти нет. `process.spawn` равнозначен полному доверию. Режим разрешений Node — «ремень безопасности».
- Не сделано по решению владельца: пробники побега из ограниченного процесса. Открытый непроверенный риск: по документации Node 24 `process._debugProcess` не входит в модель разрешений; на нашем стеке не проверено. Мера: `EnableNodeCliInspectArguments` выключен. Также не сделаны: лимиты дочернего процесса (куча, вывод, IPC), отклонение символических ссылок у расширений, положенных вручную, задание CI для `smoke:packaged`.
- Рекомендуемое продолжение: задание `smoke:packaged` в CI — без него поломка упаковки вроде `zod` остаётся незамеченной до релиза.
- Девятую запись схемы fuses Electron 44 (по документации — `wasmTrapHandlers`) `@electron/fuses` 1.8.0 не знает; смоук её не проверяет.
- Пересмотреть при: открытии каталога сторонним авторам, требованиях корпоративных списков разрешённых программ, выходе Electron с Node 26+ (флаг сети), инциденте, переносе окна на собственный протокол (для `GrantFileProtocolExtraPrivileges`).

## Проверка

`pnpm -F @dolphy/desktop smoke:packaged` читает схему fuses из собранного бинарника и падает при расхождении; сценарии `isolated` и `sql` проходят на упакованной сборке (проверено на macOS arm64). Юнит-тесты оболочек: охрана `webContents`, обработчики разрешений, `Permissions-Policy`.
