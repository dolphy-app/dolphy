# 0015. Реестр сочетаний клавиш: привязки — данные в `engine.db`, `when`, три источника, замена набора команды

Один ADR — одно решение. Заменяет пункт «Сочетания клавиш — только у команд приложения, один диспетчер» и вариант «пользовательские сочетания» ADR 0012; остальное в ADR 0012 и ADR 0008 остаётся в силе.

## Контекст

После ADR 0012 сочетания задавались в коде: одна строка у команды приложения, диспетчер с зашитыми правилами («не в поле ввода, не при открытом диалоге»), `Mod` считался «Ctrl или ⌘» на любой платформе, раздел «Сочетания клавиш» был только для чтения, а `keybinding` расширения оставался подсказкой. Пользователь не мог переназначить клавишу, расширение — привязать свою команду, а пересечения никто не искал. Исследование (`docs/research/keybindings.md`) показало: TanStack Hotkeys привязывает клавишу к колбэку и DOM-узлу (нет данных, `when`, источников, хранения, пакет в alpha); VS Code, Theia и Joplin хранят привязки как данные команды с приоритетом источников.

## Решение

Мы вводим реестр привязок как данные и принимаем пять правил.

- **Привязка — запись `{ команда, клавиши, when }`; логика — в пакете `@dolphy-app/keybindings`** (без DOM и зависимостей; публикуется вместе с пакетами расширений, чтобы авторы расширений могли проверять привязки тем же кодом). Запись: `Mod` строго по платформе, `[KeyK]` — физическая клавиша, цепочка до двух нажатий; сопоставление события — по `key` с запасом по `code` (раскладки, AltGr, IME). Свои алгоритмы по мотивам TanStack Hotkeys, зависимости от него нет.
- **Три источника с приоритетом `user` > `default` > `extension`**, внутри источника позднее выше. Расширение привязывает только собственные команды (вклад лежит внутри `commands`, ссылки на другие команды нет) и не может перебить клавишу приложения — в отличие от VS Code, где внешнее расширение весит больше ядра.
- **Пользовательский набор команды заменяет привязки команды из кода и расширений целиком**; пустой набор — «снято», удалённая запись — «по умолчанию». Записей «удалить» (`-command`) нет: не нужна сверка с умолчаниями по ключу и `when`.
- **Условия — `when`** (`!`, `&&`, `||`, `==`, `!=`, скобки) над контекстными ключами окна; два условия пересекаются, только если существует контекст, где истинны оба (нормальная дизъюнктивная форма). Привязка, которая печатает или правит текст без Ctrl и Meta, обязана быть неактивной при `inputFocus`.
- **Хранение и проверка.** Пользовательские наборы — группа `keybindings` настроек в `engine.db` (`settings.getKeybindings/setKeybindings`, контракт 19, событие `settings-changed` со `scope: 'keybindings'`). Движок отклоняет неверные записи, лимиты, повторы и пересечения **пользовательских** привязок разных команд (`INVALID_ARGUMENT`, `details.reason`); пересечения с привязками приложения и расширений решает приоритет, окно показывает предупреждение и при записи сочетания перечисляет пересечения до сохранения.

## Рассмотренные варианты

- `@tanstack/hotkeys` как зависимость — колбэки и DOM вместо данных, нет `when`, источников и хранения, alpha; разбор записи нужен движку и хосту расширений без DOM.
- Записи «удалить» в стиле VS Code — перекрёстная сверка с умолчаниями, молчаливые промахи по `when`; замена набора проще и лучше ложится на интерфейс.
- Расширения привязывают любые команды (как VS Code) — нарушает ADR 0012 (расширение управляет приложением) и позволяет перехватывать клавиши приложения; если понадобится, это отдельное решение с явным флагом на команде.
- Новая точка вклада `keybindings` рядом с `commands` — меняла бы индекс каталога (ключ `contributes`, ADR 0013) и позволяла бы ссылаться на чужие команды; привязки внутри команды структурно привязывают только свою.
- Запрет любого пересечения (как Joplin) — расширения и умолчания не знают друг о друге, отклонять было бы нечего; запрет только внутри пользовательского набора защищает данные, которыми владеет движок.
- Файл `keybindings.json` для правки руками — второй источник правды рядом с `engine.db` (AGENTS.md: настройки только в БД).

## Последствия

- Новая команда приложения — регистрация с `keybindings` и строки `ru` и `en`; привязки расширения — поле `keybindings` команды в манифесте (ADR 0008 «`keybinding` — подсказка» больше не действует: поле стало действующей привязкой).
- `Mod` строго по платформе: Ctrl+K на macOS больше не открывает палитру (было «Ctrl или ⌘»); привязка `Ctrl+K` назначается отдельно.
- У команды с пользовательским набором не появляются новые умолчания после обновления приложения; сброс команды возвращает актуальные.
- Рамка расширения по-прежнему пересылает родителю только Ctrl/⌘+K (ADR 0008, 0012): смена клавиши палитры не меняет того, что работает внутри рамки.
- Старое приложение отвергнет манифест, где у команды есть `keybindings`, как неизвестный ключ (как при прежних дополнениях манифеста).
- Пакет `@dolphy-app/keybindings` публикуется в npmjs вместе с `extension-api`, `extension-sdk`, `extension-tools`, `create-extension` (ADR 0005): его API — часть поддерживаемой поверхности.
- Вне границ: глобальные сочетания и меню Electron, `args` в привязке, контекстные ключи расширений (`setContext`), операции `when` сверх перечисленных, экспорт и синхронизация наборов.
