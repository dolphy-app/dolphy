# 0017. Vue и Vuetify в бандле расширения для UI-кита

Один ADR — одно решение. Дополняет решение `extension-api-breadth-2` о корневом экспорте `@dolphy-app/extension-ui` без зависимостей: оно сохраняется для корня, подпути его не отменяют.

## Контекст

- Панели, виджеты и виды ответа расширений работают в изолированной рамке: `sandbox="allow-scripts"`, непрозрачный origin, CSP `script-src dolphy-ext://<id>` (ADR 0003, `extension-assets.ts`). Модулей приложения (Vue, Vuetify) рамка не видит.
- Рамка получает тему приложения как CSS-переменные `--v-theme-*` на `<html>`; других связей с Vuetify приложения нет.
- Ванильный набор `@dolphy-app/extension-ui` (семь функций, без зависимостей, до 10 КиБ gzip) повторяет вид Vuetify средствами CSS. Нужных компонентов в нём нет (radio, checkbox, вкладки, оверлеи, таблицы), а писать их вручную значит дублировать поведение Vuetify.
- Замер (esbuild, tree-shaking, production): ядро Vue и Vuetify с одной кнопкой — 126 КиБ (48 КиБ gzip) JS; полный набор из спеки — 431 КиБ (149 КиБ gzip) JS и 153 КиБ (21 КиБ gzip) CSS. Ограничения размера скриптов расширения в загрузчике нет.
- Vuetify импортирует CSS по компонентам; сборщик расширений (`assets-plugin.ts`) отклоняет любой такой импорт.

## Решение

Мы собираем Vue и Vuetify внутрь файла расширения (`view.mjs`, `panel.mjs`, `widget.mjs`) через подпути `@dolphy-app/extension-ui/vuetify/*`, по одной группе компонентов на подпуть. Корневой ванильный экспорт остаётся как есть. Тема и язык Vuetify строятся из переменных и `lang` рамки; CSS зависимостей собирается сборщиком в строку и добавляется в рамку одним `<style>`. Оверлеи в рамках фиксированной высоты поддерживаются сообщением рамки `overlay` с потолком высоты на стороне приложения.

## Рассмотренные варианты

- Расширять ванильный набор компонентами «как у Vuetify» — размер остался бы малым, но поведение (клавиатура оверлеев, таблицы, поле даты) пришлось бы писать и поддерживать самим; вид расходился бы с Vuetify при каждом обновлении.
- Отдельный пакет `extension-ui-vue` — те же размер и сборка, но второй UI-пакет с тем же назначением и пересечение имён; подпути одного пакета проще для авторов и для `verify:packages`.
- Брать Vue и Vuetify из приложения (общий модуль, import map) — CSP рамки и непрозрачный origin это запрещают; ослабление изоляции перечёркивает ADR 0003.
- Показывать оверлеи только в панелях — не требует протокола, но делает компоненты неполными в видах ответа и виджетах; отвергнуто владельцем.

## Последствия

- Каждое расширение, использующее подпуть, несёт собственную копию Vue и нужной части Vuetify: от 48 КиБ gzip ядра до около 150 КиБ gzip на полный набор. Расширения без подпутей не меняются.
- Версия Vuetify в расширении закреплена версией пакета `extension-ui`; визуальный дрейф относительно приложения при обновлении Vuetify проверяется при подъёме версии (e2e в двух темах, axe).
- Корневое правило «пакет без зависимостей и до 10 КиБ gzip» теперь относится только к корневому экспорту; подпути проверяются отдельными потолками (`verify:packages`).
- Сборщик расширений различает CSS автора (по-прежнему ошибка с подсказкой `?inline`) и CSS зависимостей (собирается). Протокол рамки получает сообщение `overlay`; приложение ограничивает запрошенную высоту, иначе расширение смогло бы занять экран.
- Тема Vuetify в рамке зависит от наблюдения за переменными `<html>`: смена способа передачи темы (`frame-theme.ts`) требует правки ядра подпутей.

## Проверка

`pnpm verify:packages` (потолки размера по подпутям), тест `extension-tools` на CSS зависимостей, e2e-панели в светлой и тёмной темах с axe, юнит `frame-bridge` на потолок высоты оверлея.
