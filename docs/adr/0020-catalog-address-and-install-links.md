# 0020. Адрес каталога — пользовательская настройка с областью доверия «один каталог»; ссылки `dolphy://` только открывают диалог

Один ADR — одно решение. Дополняет ADR 0004 (каталог) и ADR 0013 (метаданные записи): добавляются смена адреса каталога, схема `dolphy:` и пометка `deprecated`. Реализация интерфейса на Vuetify — отдельная фича `extension-ui-vuetify`.

## Контекст

- Адрес каталога был константой установщика (`DEFAULT_EXTENSION_CATALOG_URL`) с переопределением переменной окружения; автору и мейнтейнеру нужен локальный и тестовый каталог без пересборки.
- Расширения исполняются с правами, подтверждёнными пользователем в диалоге установки; каталог — цепочка доверия (ревью, `sha256`, отзыв). Смена адреса не должна переносить доверие и отзывы одного каталога на расширения другого.
- Ссылки с сайта и из чатов удобны, но ссылка — ввод извне: она не должна ставить код.
- Подписей индекса и проверки издателя нет (решение владельца), доверие держится на HTTPS и origin каталога.

## Решение

Мы принимаем четыре связанные части.

- **Адрес каталога — поле контракта `ExtensionSettingsDto.catalogUrl`** (`null` — умолчание), проверка в сервисе (`https:`, `http:` только на loopback, до 2048 знаков, без логина и фрагмента, путь `.json`), применяется сразу через переключаемый установщик (`createSwitchableInstaller`). Переменная окружения сильнее настройки, при ней `setCatalogUrl` отказывает.
- **Область доверия — один действующий каталог.** `.dolphy-install.json` хранит `catalogUrl` установки и не переписывается. Расширения из прежнего каталога работают, помечены «Из другого каталога» и не получают обновлений, отзыва и предупреждений об устаревании нового каталога (сверка `catalogUrl` в установщике). Запись нового каталога с тем же id показана как «Уже установлено из другого источника» и не ставится поверх.
- **Ссылки `dolphy://extensions/install/<id>` только открывают диалог установки.** Строгий разбор (схема, хост, путь, `id` по `EXTENSION_ID_PATTERN`, без параметров), остальное игнорируется с записью в журнал; установка — только нажатием «Установить» после показа прав. Ссылка не несёт адреса каталога и не меняет настроек.
- `deprecated` в записи индекса — предупреждение с причиной и альтернативами (диапазон `versions` как у `revoked`), не блокировка и не изменение статуса.

## Рассмотренные варианты

- Ссылка, ставящая расширение сама, — любая веб-страница получила бы установку кода одним нажатием в браузере; диалог с правами обязателен.
- Несколько каталогов одновременно — нужна идентичность `id` между каталогами, слияние версий, отзыв и устаревание по источнику, выбор при конфликте; для одного пользователя это сложность без сценария. Сейчас переключение и пометка «из другого каталога».
- Подпись индекса и проверка издателя — требуют ключей, их распространения и ротации; отложены владельцем, смена адреса от них не зависит.
- Адрес только в переменной окружения — недоступно обычному пользователю и не переживает перезапуск из ярлыка.
- Перенос расширений при смене каталога (переписать `catalogUrl`) — молча передал бы доверие и отзыв чужому каталогу.
- Блокировка устаревших — решение владельца: предупреждение, установка разрешена.

## Последствия

- Пользователь, указавший чужой каталог, принимает его правила целиком; приложение предупреждает только о происхождении (`origin`, «Из другого каталога»), а не проверяет издателя.
- При смене каталога обновления и отзыв прежних расширений прекращаются до возврата адреса; их можно удалить и поставить заново из нового каталога.
- Схема `dolphy:` регистрируется установщиками; проверяется автоматически только `Info.plist` собранного `.app` (`pnpm smoke:packaged`), перехват ссылки ОС — вручную.
- Репозиторий каталога должен поднять `@dolphy-app/extension-tools` и подключить `deprecated.json` (см. `Outcomes` спеки).
