# 0023. Интерфейс расширений на любом фреймворке: монтируемые компоненты и пресеты сборки

Один ADR — одно решение. Дополняет ADR 0022 (общий интерфейс в окне на Vue): Vue остаётся фреймворком по умолчанию, ADR 0022 не отменяется.

## Контекст

- После ADR 0022 расширение рисует интерфейс Vue-компонентами в дереве окна. Авторы хотят писать на React и других фреймворках, а Vue — ещё и в виде `.vue` (SFC).
- Окно и расширение работают в одном документе без песочницы: любой фреймворк может рисовать в выданный элемент.
- Сборщик расширений — vite 8 (`dolphy-ext build`), общие `vue` и `vuetify` подменяются чтением из `globalThis.__dolphy`.

## Решение

1. **`Mountable`.** Везде, где регистрация принимает `component` (`addPanel`, `addInjection`, `addAnswerView`, `addMarkdownRenderer`), допустим Vue-компонент или `Mountable`: `mount(el, ctx)`, возвращающий очистку. `MountContext` не зависит от Vue: `props` (снимок) и `onProps`, `emit`, `app`, `engine`, `callRpc`, `theme`/`onTheme`, `locale`/`onLocale`, `extensionId`, `signal`, `reportError`, `handle`. Хост окна один (`MountableHost.vue`), ошибка `mount` и `reportError` заменяют только область компонента карточкой ошибки.
2. **Пресеты сборки.** `dolphy-ext.config.json` принимает `frameworks`: `vue` включён всегда (SFC через `@vitejs/plugin-vue`, `<v-*>` шаблона превращаются в импорты `vuetify/components`, стили собираются в один `<style data-dolphy-ext>` на расширение), `react` добавляет автоматический JSX без `@vitejs/plugin-react`. Пресеты применяются только к `client.mjs`; серверный бандл фреймворк не получает. Новый фреймворк — новый пресет, а не плагины автора.
3. **Адаптеры в SDK.** Подпуть `@dolphy-app/extension-sdk/react` (`reactComponent`, хуки). Необязательные peer-зависимости `react` и `react-dom`; SDK не тянет фреймворки в корень.
4. **Свой рантайм у каждого расширения.** Один общий React для расширений не делается; позже возможен пакет-расширение (`dependencies`), которое выдаёт общий модуль.

## Рассмотренные варианты

- Отдельные методы `addPanelElement` и т. п.: API удваивается, один `component` проще.
- Произвольные плагины vite автора (`dolphy-ext.config.ts`): гибко, но конфиг становится кодом; пресеты закрывают случаи без этого.
- Вшитый список в сборщик: сборщик тянет все плагины фреймворков; выбран пресет по конфигу с опциональными зависимостями.

## Последствия

- Каждое не-Vue расширение несёт свой рантайм (React без минификации ≈ 106 КиБ gzip, SFC с кнопкой ≈ 0,6 КиБ gzip); минификации клиентских бандлов у сборщика нет.
- Во фреймворках, кроме Vue, нет Vuetify и оверлеев приложения; тема доступна через `ctx.theme` и CSS-переменные `--v-theme-*`.
- Стили SFC попадают в документ окна глобально: нужен `scoped`; `<style module>` не поддерживается.
- Имена `frameworks` — закрытый список: `vue`, `react`; добавление пресета (Svelte, Solid) — новая запись и опциональная зависимость.

## Проверка

e2e `extension-react` и `extension-sfc` (оба в одном окне, сбой React не трогает Vue), тесты `extension-tools` на пресеты, `mountable-host.test.ts`, `generated-project.test.ts` для `react-panel` и SFC-шаблона, `pnpm verify:packages`.
