# MVP на Trane vs MVP на vanderbilt-data-science/knowledge-spaces

Основа: `docs/research/trane.md`, `trane-source-audit.md`, `trane-spike.md`, `knowledge-spaces.md` + короткая проверка `kst_utils.py` (запущена ниже). Метки: `[ОЦЕНКА]` — расчёт, не измерение; `[ВЫВОД]` — наше умозаключение; `[НЕ ПОДТВЕРЖДЕНО]` — не проверено.

## 1. Вердикт

Это не два конкурирующих движка, а два разных слоя.

- **Trane — рантайм обучения**: граф, gating, планировщик, состояние, CLI-цикл «дай упражнение → оцени».
- **knowledge-spaces (KS) — конвейер авторинга и диагностики**: 10 LLM-промптов (Agent Skills для Claude Code) + один Python-скрипт на 749 строк + одна JSON-схема. Планировщика, повторений, времени, цикла обучения и хранилища прогресса в нём нет.

MVP «на базе KS» как учебная система невозможен без написания всего рантайма (F4–F7) с нуля — то есть это был бы наш вариант C (`build-vs-port.md`) плюс валидатор из KS. Осмысленное сравнение: **что берём у каждого**. Ответ: рантайм — Trane (или своё ядро), авторинг-схему и часть валидатора — KS (лицензия MIT позволяет копировать).

## 3. Что показала проверка `kst_utils.py`

Скачан `scripts/kst_utils.py` (749 строк, 15 функций). Тестовые графы — мои синтетические, не из репозитория.

1. **На системном Python 3.9.6 модуль не импортируется**: `TypeError: unsupported operand type(s) for |: 'type' and 'NoneType'` (строка 359, `-> str | None`). README заявляет Python 3.9+. Подтверждает вывод из чтения кода. На 3.11 работает.
2. **Валидатор**: цикл `it-000→it-001→it-002→it-000` найден с путём (FAIL, exit 1); ссылка на несуществующий item — FAIL; orphan — WARN; WARN-only выходит с кодом 0. Ребро `0→4`, избыточное при цепочке `0→1→…→4`, **не помечено как избыточное**; вместо этого скрипт пишет «7 implied relations missing» — требует материализовать замыкание.
3. **`relation_type` игнорируется**: ребро `related-to` между `it-001` и `it-002` породило предупреждение о «недостающей» связи `it-000→it-002`, то есть считается жёстким пререквизитом.
4. **Взрыв состояний**: случайный разреженный DAG (1–2 пререквизита на вершину, seed 1): 20 items → 3 153 состояния; 30 items → **181 107** состояний (при cap 10 000 перечисление обрывается, результат частичный). Перечисление 181k заняло 1.4 с. Реальные учебные графы обычно более цепочечные, чем случайные, поэтому цифры — потолок для «широких» структур `[ВЫВОД]`; по ALEKS домены ~100 items дают ~57–60 тыс. состояний.
5. **BLIM на этих 181k состояний**: 350–400 мс на шаг в чистом Python (выбор вопроса O(|Q|·|K|)). Симуляция: истинное состояние выбрано случайно, вопросы 30, по одному на item, g = s = 0.1 (дефолт скрипта):
   - без шума ответов: энтропия после 30 вопросов 5.5–8.1 бит из начальных 17.5; top-вероятность 0.16–0.31; точное состояние = argmax в 5/5;
   - с шумом 10%: точное состояние восстановлено в 2/5.
   Критерий остановки «энтропия < 1 бит» **не достигнут ни разу**. Причина арифметическая: при g = s = 0.1 один бинарный ответ несёт не более ≈0.53 бита, так что для 17.5 бит нужно ≥ ~33 ответов. Заявленные «15–25 вопросов» достижимы лишь при почти нулевых g/s (открытые ответы в стиле ALEKS) и/или компактных пространствах. Проверено на 1 синтетическом графе, 5 запусков на режим — это иллюстрация, не бенчмарк.

## 4. Что в KS ценно, а что нет

**Ценно и переносимо** (MIT, можно копировать):
- Схема item/edge с `confidence`, `rationale`, `source`, `provenance.change_log` — аудит LLM-выводов.
- Пороги confidence и «на ревью человеку».
- Набор именованных проверок PASS/WARN/FAIL + exit code (~350 строк Python, легко портируется).
- Bloom × Webb DOK на item как проверка гранулярности.
- Fringes как UX-примитив, если считать по DAG без перечисления состояний.
- Протокол слияния expert-рёбер и data-derived-рёбер (IITA) как будущий цикл.

**Не переносить**:
- Хранение замыкания в файле, игнор `relation_type`, `student_states` внутри курса.
- LLM как судья ответов.
- Перечисление пространства состояний для курсов больше ~25–30 items (сам SKILL.md это признаёт, но альтернатив в коде нет).
- Заявление «QUERY» как гарантию: это LLM-эвристика, а не процедура Koppen–Doignon.

## 5. Что даёт Trane сверх KS

- Полный цикл обучения и хранилище состояния.
- Проверенное поведение крайних случаев (353 теста).
- Масштаб на 3 порядка выше по числу узлов.
- Encompassing-веса (KS такого не знает; у KS только отношение «подразумевает»).

Чего у Trane нет, а у KS есть: диагностика (F3), провенанс рёбер, LLM-конвейер извлечения из силлабуса, схема с Bloom/DOK, MIT-лицензия.

## 7. Ключевые решения

| Решение | Решает | Ухудшает | Менять, когда |
|---|---|---|---|
| Рантайм — Trane, не KS | Готовые gating/планировщик/состояние | AGPL, Rust, один мейнтейнер | FSRS/лицензия/sync упираются → свой рантайм (`build-vs-port.md`) |
| Авторинг-схему и проверки брать из KS | Аудируемость LLM-рёбер, MIT | Двойной формат: KS-JSON → Trane-KB, нужен компилятор | Схема разрастётся сверх нужд MVP |
| Диагностику F3 не брать из KS в MVP | Избежать взрыва состояний, LLM-судьи и облака | В MVP нет placement-теста | Есть курс > 100 items и нужен вход-тест → fringe/байес по DAG на темах, с детерминированной проверкой |
| Не использовать LLM в петле обучения | Локальность, воспроизводимость | Нет открытых ответов без раннера | Появится измеренно надёжная оценка открытого ответа |

## 8. Рекомендация

**Trane-рантайм + компилятор курса, взявший из KS схему и валидатор.** Порядок:
1. Взять из KS поля `bloom_level`, `dok_level`, `confidence/rationale/source`; хранить рёбра минимальными; замыкание считать при загрузке.
2. Портировать проверки `validate_graph` (refs, cycles, orphans, >7 prereq, Bloom-инверсии) в валидатор F2; добавить редукцию и missing-dep; **не переносить** требование замкнутости.
3. LLM использовать только на этапе авторинга (черновик рёбер), с обязательным ревью-статусом в Git и детерминированным гейтом.
4. Диагностику отложить.

## 9. Границы проверки

- `kst_utils.py` запущен на синтетических графах; реальных курсов в репозитории нет (`graphs/` пуст).
- Навыки (`SKILL.md`) не исполнялись: LLM-часть не тестировалась. Не читались `generating-learning-materials` и `planning-adaptive-instruction` (см. `knowledge-spaces.md`).
- BLIM-симуляция: один граф, 5 запусков на режим, g = s = 0.1 по умолчанию скрипта.
- Trane-числа — из спайка на синтетическом курсе, не на реальном.
