# MVP на движке Trane: покрытие требований, границы, решение

> **Статус артефактов (2026-09-29).** Код спайка `spike/trane-mvp/` удалён по решению владельца; отчёт `trane-spike.md` остаётся. Тестовый курс сохранён в `engine-ts/reference/sql-course/`, эталонный Trane — в `engine-ts/reference/trane-pristine/`. Проект дальше идёт по пути TS-порта (`engine-ts/design/engine-ts.md`), этот документ описывает вариант «Trane как библиотека».

Основа: `docs/research/trane.md` (чтение репозитория/книги), `trane-source-audit.md` (чтение исходников v0.34.1 с file:line), `trane-spike.md` (реальный прогон 6 сценариев на публичном API; код в `spike/trane-mvp/`, одноразовый). Метки: `[НЕ ПОДТВЕРЖДЕНО]` — не проверено; `[ВЫВОД]`/`[ОЦЕНКА]` — наше умозаключение, не измерение.

## 1. Вердикт

Trane закрывает **ядро расписания**: DAG уроков с gating, веса encompassing, окна мастерства, relearn pile, перемешивание. Всё остальное из F1–F7 — надстройка **снаружи** движка. **Форк для MVP не нужен** (все 6 сценариев спайка собраны на публичном API), но три вещи потребуют форка позже: FSRS-скорер, метаданные упражнения, публичные frontier/due.

Самое рискованное место MVP — **не Trane, а раннер проверок** (в Trane его нет вообще) и несоответствие семантики gating «самооценке на повторах» и «детерминированной проверке».

## 2. Покрытие требований

| Треб. | Что даёт Trane | Чего нет | Форк? | Кто закрывает | Покрытие |
|---|---|---|---|---|---|
| F1 курс в Markdown/Git | Манифесты JSON + Markdown-ассеты; `KnowledgeBase`-генератор: каталоги `*.lesson`, `q.front.md`, `lesson.dependencies.json` (в спайке: 37 файлов против 43 у ручного JSON) | Одного файла на тему с frontmatter нет; кастомные JSON-поля в манифестах **молча теряются** (нет `deny_unknown_fields`); опечатки в ключах не ловятся | Нет | Взять KB-формат как исходник курса; при желании — тонкий компилятор `topic.md → KB-каталог` | Частично (~70%) |
| F2 валидатор | Бесплатно: цикл **с путём**, self-dependency, вес ∈ [0,1], существование asset-путей | Ссылка на несуществующий unit **принимается молча**; транзитивная редукция не проверяется; orphan; «у упражнения есть check»; гранулярность | Нет | Внешний код на публичном `UnitGraph` (`get_dependencies`, `get_encompasses`…) | ~40% бесплатно `[ОЦЕНКА: +150–300 LOC]` |
| F3 диагностика | Ничего (grep `diagnostic\|placement` → 0) | Placement-теста нет | Нет | В MVP — отложить или «пропустить известное»: blacklist (но «известное» тогда не повторяется никогда) либо синтетические `Five` ×≥2 на упражнение (подчиняются забыванию; помечать в своём логе) | ~0% |
| F4 план дня | Батч: gating по frontier, окна new/target/current/easy/mastered 20/20/30/20/10, relearn pile 10%, shuffle (интерливинг), 1500 уроков × 3 упр. → open 0.17 с, батч 2–8 мс (до ~50 мс на первом вызове при полностью освоенном графе), RSS 24–28 МБ | Frontier и due **раздельно не отдаются** (приватные `Candidate`/`urgency`); repetition compression фактически не работает в малых курсах: review knocker срабатывает при `score ≥ 4.5 и суммарный вес ≥ 10` (или `≥ 3.75 и ≥ 5`) — в спайке на 7 уроках не сработал ни разу | Нет для MVP (для дашборда — ~30–60 LOC форка `[ОЦЕНКА аудита]`) | Frontier считать снаружи по `get_unit_score` + графу (~100–200 LOC, повторяя `passes_threshold`) | ~60% |
| F5 раннеры | `score_exercise(id, MasteryScore, ts)` публичен — точка подключения детерминированной проверки | Раннера нет; Trane судит только по числу 1–5 | Нет | Внешний раннер → маппинг pass/fail → `MasteryScore` | Крюк есть, семантика с нюансами (см. §4) |
| F6 ремедиация | Фильтры `LessonFilter`/`Dependencies` для выдачи материала prerequisite; review list | **Механизма упражнение → prerequisite нет**; негативный reward идёт к **dependents**, а не к prerequisites (`reward_propagator.rs`); в спайке провал `where` не понизил `join` (причина не изолирована `[НЕ ПОДТВЕРЖДЕНО]`) | Нет | Надстройка: своя таблица `exercise → key_prereqs`, счётчик подряд идущих провалов, выдача через `LessonFilter` `[ОЦЕНКА: 80–150 LOC]` | ~0% |
| F7 sync без Git-конфликтов | Состояние отделено от контента (`new_local_with_vfs` кладёт `.trane` вне репо курса) | Нет device/event id, нет ключей дедупа, `unit_uid` различается между устройствами; rewards/deltas — побочные эффекты записи, кода пересборки нет; `.db` в WAL — синхронизировать нельзя | Нет | Свой append-only лог событий + полный replay (см. §5) | Не из коробки; решаемо без форка |

Нефункциональные: офлайн и локальность — да (SQLite+JSON, телеметрии в прочитанных источниках нет; формального заявления о приватности нет — `[НЕ ПОДТВЕРЖДЕНО]`); воспроизводимость — да при replay (§5); открытые форматы — контент да, SQLite Trane — только кэш.

**Итого:** из 7 функциональных требований движок «сам» закрывает 0 полностью; F4 и gating-половину F5 — в основном. Разумная формулировка: Trane снимает с нас граф + gating + базовый планировщик + тесты (353 `#[test]`, CI с clippy `-D warnings`), а F2, F3, F5-раннер, F6, F7 — наш код вокруг.

## 3. Что показал спайк (наблюдения, не предположения)

1. **Gating работает**: в начале в батче только корневые уроки; ромб `join` открывается только после прохождения обоих родителей.
2. **Порог разблокировки жёстче, чем кажется.** При дефолтах (`min_score` 3.0, `min_avg_trials` 1.8) для урока из 3 упражнений нужно **≥ ceil(1.8·N) = 6** оценённых попыток `Four/Five`. Одна верная попытка не открывает зависимые никогда; 5 попыток не хватило; непопробованные упражнения входят в среднее как 0.
3. **`Three` не открывает зависимое.** Оценка ≈ `min_score` даёт «мигающий» gating: зависимый урок пропал из батча на следующий день (score `where` ≈ 3.0–3.08 и падает под порог из-за decay; причина — гипотеза, decay отдельно не измерялся).
4. **Score зависит от времени**: `Four` на следующий день 4.00 → 3.87.
5. **Encompassing работает через unit score**: успех `join` поднял `aggregate` на +0.34…+0.62 (вес 1.0), `where` на +0.14…+0.40 (вес 0.5). В батче эффект в малом курсе виден только через окна/`select_candidates`, не через knocker.
6. **Кастомный check в упражнении без форка возможен только через frontmatter Markdown-ассета** (MarkdownAsset / InlinedAsset / `.front.md`): Trane файл не парсит, мы читаем сами. Новый вариант `exercise_asset` — ошибка парсинга (закрытый enum); у `ExerciseManifest` нет `metadata`.
7. **Replay детерминирован только в отсортированном порядке**: одни и те же 60 trial'ов дали `join` 2.97 (sorted by ts, дважды одинаково), 2.94 (лог A затем лог B), 2.63 (обратный порядок). Значит, инкрементально дописывать чужие события «в прошлое» нельзя — только полный replay.
8. **Скорость `score_exercise`**: 9000 вызовов за 223 мс (24.8 мкс/вызов).

## 4. Проблема: gating рассчитан на самооценку, а нам нужна проверка

Trane предполагает, что упражнение оценивается многократно и мягко. Детерминированный раннер даёт бинарный сигнал (`pass`/`fail` + число попыток). Следствия для MVP:

- **Маппинг.** В спайке: pass с 1-й попытки → `Five`; со 2-й → `Three`; с 3-й → `Two`; fail → `One`. Со `Three` gating не открывался (см. §3). Предлагаем: со 2-й попытки → `Four`. Границы — наши калибровки без данных `[ГИПОТЕЗА]`, вариант с `Four` не запускался `[НЕ ПОДТВЕРЖДЕНО]`.
- **`min_avg_trials = 1.8` избыточен**, если каждый ответ проверен тестом: «прошёл с первого раза» защищался от завышенной самооценки. Ослабить через `set_scheduler_options(passing_score.min_avg_trials)` — API есть в трейте, **в спайке не запускался** `[НЕ ПОДТВЕРЖДЕНО]`; проверить первым делом.
- Для SQL нужно **≥ 3–6 упражнений на урок** и, по умолчанию, ≥2 прохода на каждое: либо параметризованные варианты одного вопроса (разные фикстуры), либо снижение порога.

## 5. F7 без форка: лог событий + replay

```text
progress/<device_id>.jsonl   # append-only, по одному файлу на устройство, живёт в Git
  {event_id (UUIDv7), device_id, exercise_id, mastery:1..5, ts, source: "runner"|"self"|"placement", attempt, course_hash}

.trane/   # кэш, не источник истины, вне репо курса (new_local_with_vfs)
  пересоздаётся: rm -rf .trane && sort_by(ts, event_id) && score_exercise(...) для каждого события
```

- Файл на устройство + только дозапись ⇒ Git-слияние не конфликтует по построению `[ВЫВОД]`.
- Стоимость полного replay: 24.8 мкс × 10⁵ событий/год ≈ 2.5 с `[ОЦЕНКА по спайку, не измерено на 10⁵]`. Достаточно для MVP; снапшоты не нужны.
- `score_exercise` считает `existing_score` через текущие часы, а не через переданный `timestamp` ⇒ перед каждым событием вызывать `override_current_timestamp(Some(ts))` (публично; **replay с override целиком не запускался** `[НЕ ПОДТВЕРЖДЕНО]` — первый тест).
- События `source: placement` отличаем от реальных, чтобы синтетическое знание можно было пересмотреть.
- Не нужен CRDT: журнал = множество событий (G-Set). Ограничение: разные часы устройств влияют на порядок → клэмпить «будущие» ts.

## 6. Границы MVP

**Домен:** SQL (проверка — выполнить запрос в in-memory SQLite и сравнить множество строк с ожидаемым; `rusqlite` с bundled SQLite уже в зависимостях Trane; timeout через progress handler). Детерминированно, без Docker/Wasm.

**Входит:**
1. Курс ≈ 30 уроков × 3–6 упражнений в KB-формате; check-спека в frontmatter `.front.md`.
2. `validate`: всё, что Trane не проверяет (несуществующие зависимости, транзитивная редукция, у каждого упражнения есть check, orphan) + вызов проверок Trane.
3. `next`: батч Trane → показ → ввод SQL → раннер → маппинг → запись в JSONL → `score_exercise`.
4. `rebuild`: полный replay лога.
5. `status`: frontier/освоено (посчитанное снаружи).

**Не входит (сознательно):** диагностика (F3), ремедиация (F6), FSRS, LLM-генерация курсов, UI кроме CLI, транспорт sync кроме Git.

## 7. Ключевые решения (solves / worsens / когда менять)

| Решение | Решает | Ухудшает | Менять, когда |
|---|---|---|---|
| Trane как библиотека, без форка, версия зафиксирована | Граф, gating, планировщик, тесты — готовы | 0.x, идёт активная переработка скорера (PR #419–#438), семантика меняется между релизами; публичного issue-трекера нет; один мейнтейнер, PR в ядро закрыты | Нужны exercise-metadata / frontier API → форк-вендоринг. Для FSRS форк уже проверен: патч +71/−7 строк и адаптер ≈200 строк (`fsrs-in-trane.md`), но он тоже переводит нас на сопровождение собственной копии |
| Своя надстройка вместо правок ядра | Обновления апстрима не ломают | Дублируем логику `passes_threshold` для frontier; риск расхождения | Расхождение frontier с реальным батчем на практике |
| JSONL-лог как источник истины, `.trane` — кэш | F7 без форка, воспроизводимость | Полный replay при каждом merge; правило «нельзя дописывать в прошлое» | Replay > нескольких секунд |
| SQL-раннер в SQLite | Детерминизм за ~сотни LOC | Домен узкий; диалект SQLite ≠ Postgres | Второй домен → раннер как плагин (Wasm/контейнер) |
| Проверка через frontmatter в `.front.md` | Без форка | Спека не видна движку и фильтрам; путь относителен корня библиотеки | Нужна фильтрация по метаданным упражнения → форк |
| Ослабить `min_avg_trials` | Один верный ответ имеет вес | Теряется защита «случайно угадал» | Данные покажут высокий guess rate |

## 8. Лицензия

`Cargo.toml`: `AGPL-3.0-or-later`; `LICENSE` — полный текст AGPL v3 (прочитано). Расхождение «GPLv3» — только в тексте книги. Последствия:
- Встраивание как библиотеки ⇒ **весь производный продукт под AGPL** (§5c: «license the entire work as a whole»). Для открытой платформы допустимо; **исключает закрытую SaaS/проприетарную модель без разрешения автора** — сменить лицензию нельзя (PR принимаются только в issues, мейнтейнер один).
- Публичный сервис на модифицированной версии обязан отдавать исходники пользователям сервиса.
- Курсы отдельные от ядра: официальные — GPL-3.0; своя лицензия контента возможна `[ВЫВОД: юридически не проверялось]`.

Это решает открытый вопрос №1 из `platform-synthesis.md` §12 по факту лицензии; **юридическую совместимость с вашей моделью распространения** проверяет юрист, не мы.

## 9. Риски

| Риск | Вероятность/эффект | Митигация |
|---|---|---|
| Дрейф поведения апстрима между 0.x | Высокий: 6 релизов за 2026-08-19 … 09-11 | Пин версии; регрессионный набор «курс → ожидаемые батчи» на нашем спайке |
| Gating «мигает» при оценках ≈3 | Подтверждён в спайке | Маппинг без `Three`; порог через опции; UX: показывать причину закрытия |
| Encompassing почти не даёт compression в малых курсах | Подтверждён (knocker не сработал) | Не обещать; замерить долю рёбер на реальном курсе до вложений в FIRe |
| Один мейнтейнер, закрыт для PR | Средний | Вендоринг в случае форка; изолировать интеграцию за нашим trait |
| Не проверено: replay с `override_current_timestamp`, `set_scheduler_options`, crates.io-зависимость, многокурсовые графы, `Trane` из нескольких потоков (`RefCell` + ручной `unsafe impl Sync`) | Неизвестно | Первые тесты MVP; однопоточный доступ |

## 10. План проверок (до кода продукта)

1. Replay: два JSONL-файла → rebuild дважды → одинаковые `get_unit_score` (с `override_current_timestamp`).
2. `set_scheduler_options(min_avg_trials = 1.0)`: открывается ли зависимое после одного прохода `Five`/`Four`.
3. Валидатор: 5 негативных курсов (цикл, missing dep, redundant edge, exercise без check, orphan) → каждый отвергается.
4. Реальный SQL-курс на 30 уроков: авторинг-время на тему (метрика из `platform-synthesis.md` §11).
5. Доля encompassing-рёбер в этом курсе → решение, нужен ли FIRe-слой.

## 11. Что делать при упоре в потолок

| Симптом | Действие |
|---|---|
| Хочется FSRS вместо `PowerLawScorer` | Сделано в песочнице, см. `design/fsrs-in-trane.md`: патч +71/−7 строк (3 файла Trane) + адаптер `fsrs-scorer` ≈200 строк на крейте `fsrs` 6.6.2; 353 апстрим-теста + 2 новых проходят. Основание (измерено на Anki-логах, `research/fsrs-vs-trane.md`): вероятность `1−urgency` у Trane уступает FSRS-6 default по Log Loss на 0.053–0.365 и хуже константы «среднее по пользователю». Форк нужен до любых заявлений об эффективности повторений и до FIRe-математики, требующей калиброванных вероятностей; для проверки gating/авторинга/раннера — не нужен |
| Нужны раздельные frontier/due | Форк: сделать `Candidate`/`get_candidates_*` публичными (~30–60 LOC) |
| Нужны check/metadata на упражнении | Форк: поле в `ExerciseManifest` (~20–40 LOC) и/или вариант `ExerciseAsset` (~30–60 LOC) |
| Нужны зависимости на уровне упражнений | Не форк: сотни LOC, ломает архитектуру lesson/course; вместо этого «один урок = атом» |
| Упёрлись в несколько из этого | Пересмотреть: писать собственное ядро, заимствуя идеи Trane (граф, windows, reward propagation) — без лицензионной связки |
