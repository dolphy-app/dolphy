# FSRS-6 vs скорер Trane: предсказание вероятности вспоминания на реальных логах

Вопрос: даёт ли FSRS измеримое преимущество над собственным скорером Trane (`PowerLawScorer`, v0.34.1)? Метки: `[ВЫВОД]` — наше умозаключение; `[НЕ ПОДТВЕРЖДЕНО]` — не сделано или не проверено.

Эксперимент остановлен по решению пользователя до расчёта FSRS с оптимизацией параметров. Числа ниже посчитаны из сохранённых результатов (`spike/fsrs-vs-trane/*.csv`); парные сравнения (столбцы «FSRS wins», ΔLL с доверительным интервалом) посчитаны отдельно по файлам `peruser_all_*.csv`.

## 3. Выводы

1. **Как предсказатель вероятности вспоминания FSRS-6 даже с параметрами по умолчанию заметно лучше скорера Trane.** По Log Loss FSRS выигрывает у всех 8 вариантов `1−urgency` (4 маппинга × 2 типа) и у всех 8 вариантов `value/5`; доверительный интервал разности исключает ноль во всех 16. FSRS лучше у 90.8–96.9% пользователей (`1−urgency`) и у 95.4–100% (`value/5`). Разрыв для `1−urgency`: от 0.053 нат на отзыв (лучший вариант, M2 Proc) до 0.365 (худший, M3 Decl); для маппингов M0–M2 — 0.053–0.126. Границы CI пересчитывались бутстрэпом и плавают в третьем знаке между запусками.
2. **`R` у Trane хуже константы.** Вариант `1−urgency` обгоняет «среднее по пользователю» (AVG) по Log Loss лишь у 1.5–23.1% пользователей в зависимости от варианта (основной M0 Proc — у 23.1%, M2 Proc — у 21.5%). Ошибка систематическая: после долгих интервалов Trane занижает вероятность (при > 90 дней предсказывает 0.61–0.68 при фактических 0.83), на интервале в 1 день завышает (0.84–0.85 при 0.79). FSRS в тех же корзинах отклоняется не более чем на ~0.04. Согласуется с комментарием в коде Trane: константы «can be tuned to calibrate», не обучены.
3. **`R` Trane ранжирует хуже, чем FSRS, в каждой корзине интервалов**: AUC ниже на 0.054–0.136 (Procedural против FSRS). Внутри корзин он ниже, чем у AVG, во всех шести; в двух последних (31–90 и > 90 дней) разница не больше 0.008.
4. **Преимущество FSRS default над разумными базовыми линиями мало.** Против AVG ΔLL +0.011 с CI, включающим ноль; против LAST-OUTCOME +0.0009 (ноль в CI, RMSE(bins) у LAST-OUTCOME даже лучше); значимо лучше только HIST-MEAN (+0.020). Основная польза default-FSRS — ранжирование (AUC 0.650 против 0.551 и 0.500). Схожая картина в официальном бенчмарке: MOVING-AVG имеет Log Loss 0.3369 против 0.3460 у FSRS-6 (меньше — лучше), но AUC 0.7001 против 0.7034 (`srs-benchmark` README). Большой выигрыш даёт оптимизация параметров по логам пользователя: в том же README FSRS-7 default — Log Loss 0.3620, RMSE(bins) 0.0910; FSRS-7 после оптимизации — 0.3401 и 0.0634. **Это цитата, не наше измерение**: оптимизацию FSRS мы не запускали.
5. **`value/5` Trane — сигнал ранжирования, сопоставимый с FSRS при маппингах M0, M1, M3, но не вероятность.** Попарный AUC 0.646–0.659 против 0.650 у FSRS default (ΔAUC в пределах ±0.009); при M2 хуже: 0.628–0.630. Это величина, по которой планировщик Trane строит окна мастерства. Не проверено: AUC `value` внутри корзин интервалов и доля сигнала, приходящаяся на историю оценок (сложность карточки), а не на время `[НЕ ПОДТВЕРЖДЕНО]`.
6. **Скорер Trane чувствителен к маппингу оценок.** Порог провала 3.0 встроен в расчёт сложности: маппинг M3 (Hard=2, Good=3) даёт Log Loss 0.60–0.77 против 0.46–0.51 у M0/M2. Для нашей проверки тестами (провал → One, успех → Four/Five) релевантны M0/M2.

## 4. Что это значит для платформы

- **Для проверки гипотез MVP** (gating, авторинг, раннер, плотность encompassing) слабость скорера Trane не мешает: gating и окна опираются на `value`, а он ранжирует на уровне FSRS.
- **Для заявлений об эффективности повторений** (меньше повторений при целевой доле удержания) и для FIRe-математики, которой нужны **калиброванные вероятности**, скорер Trane непригоден: он не откалиброван и не умеет целевую долю удержания (не планирует по интервалам — так и заявлено автором).
- **Преимущество FSRS появляется в двух местах**: (а) время-зависимая калиброванная `R` для срока повторения и целевого удержания; (б) оптимизация параметров под пользователя, но она требует накопленной истории (порог ≥ 1000 отзывов в отчёте по RemNote). До этого FSRS работает на параметрах по умолчанию, где его выигрыш над простыми базами мал (п. 4). `[ВЫВОД]`
- **Замена скорера Trane на FSRS требует форка**, но он невелик: измерено +71/−7 строк в 3 файлах Trane и адаптер ≈200 строк (`docs/design/fsrs-in-trane.md`; оценка аудита была 15–30 и 150–300 строк). Собрано и прогнано в песочнице, в продукт не встроено. Альтернатива — собственное ядро (вариант C, `build-vs-port.md`). Ценность Trane сдвигается на граф, gating, окна и relearn (около 1–1.3 тыс. строк), а не на скорер.

## 5. Ограничения (что нельзя выводить из этих чисел)

1. **Домен.** Anki-карточки с фактами и четыре кнопки. Trane рассчитан на навыки с самооценкой 1–5; наша цель — упражнения, проверенные тестами, с бинарным исходом. На таких данных проверки не было.
2. **Интервалы выбраны другим планировщиком** (Anki), то есть длина интервала зависит от сложности карточки; оба предсказателя оцениваются на данных, сформированных чужим расписанием `[ВЫВОД]`.
3. **Trane запущен без `practice_deltas` и `rewards`**, которые в полном конвейере корректируют оценку. Полный конвейер не воспроизводился.
4. **Измерялось предсказание, не обучение.** Симуляции расписания (число повторений на единицу удержания) нет.
5. **FSRS с оптимизацией не запущен**; код `metrics.py` содержит перекалибровку Platt для разделения ошибки калибровки и ранжирования — не выполнялась (`results_all.csv` без этих строк). Вклад калибровки и ранжирования в разрыв разделён только косвенно, по AUC внутри корзин.
6. **RMSE(bins)** — приближение определения бенчмарка; сравнимо внутри этого отчёта, но не с таблицами `srs-benchmark`.
7. **Одна выборка**: 65 пользователей, ≤ 4000 карточек на человека, доверительные интервалы только по пользователям; более старый набор данных.

## 6. Воспроизведение

Файлы в `spike/fsrs-vs-trane/`: `prep.py` (фильтрация, разбиение, вход для Trane), `tranescore/` (Rust-обвязка над `PowerLawScorer`), `fsrs_pred.py`, `metrics.py`, результаты `results_all.csv`, `calibration.csv`, `by_bucket.csv`, `peruser_all_*.csv`, список файлов набора данных `data_files.txt`. Порядок: скачать перечисленные файлы `revlog_history-*.tsv` в `raw/`; `python prep.py`; `cargo run --release --manifest-path tranescore/Cargo.toml < trane_in.tsv > trane_out.tsv` (в `Cargo.toml` путь к клону Trane v0.34.1 нужно поправить); `python fsrs_pred.py default`; `python metrics.py`. Сырые данные, окружение Python, `target/` и промежуточные `*.tsv`, `*.parquet`, `*.npy` удалены после выводов.
