# Реестры сочетаний клавиш: TanStack Hotkeys, VS Code, Theia, Joplin

> Исследование на 2026-10-05; решения приняты в `specs/archive/2026-10-05-keybindings-registry/SPEC.md` и ADR 0015.

Вопрос: как устроить в Dolphy общий реестр сочетаний клавиш, который (1) хранится в базе и меняется пользователем и расширениями, (2) работает на macOS, Windows и Linux и на разных раскладках, (3) проверяет пересечения, (4) даёт одному сочетанию разное поведение в разных условиях.

Факты — по исходникам (ветка по умолчанию на 2026-10-04–05) и документации; выводы о применимости наши. Не проверено: `[unverified]`.

## TanStack Hotkeys

Пакет `@tanstack/hotkeys` 0.11.0, MIT, alpha («actively developing»), зависит от `@tanstack/store`. Отдельные адаптеры для React, Vue, Solid и других.

Что полезно взять:

- **`Mod` и запись `Mod+Shift+S`.** `resolveModifier('Mod', platform)` — `Meta` на macOS, `Control` иначе; платформа определяется по `navigator`. Типы исключают дубли вроде `Mod+Control`, где `Mod` уже равен `Control`.
- **Физическая запись `[KeyS]`** рядом с логической: сочетание привязывается к положению клавиши, а не к символу (`parse.ts`, `validate.ts`).
- **Алгоритм сопоставления** (`_match.ts`): пропуск при `isComposing` (IME); AltGr не считается Ctrl+Alt; ASCII-буква `event.key` считается окончательной (Dvorak, Colemak, AZERTY работают по символу); если `event.key` не ASCII-буква (русская раскладка, мёртвые клавиши macOS Option+буква, `Shift+цифра`), используется запасной путь по `event.code`; для печатных не-букв неявный `Shift` допускается.
- **Умолчание `ignoreInputs`**: сочетания с Ctrl/Meta и `Escape` срабатывают в полях ввода, одиночные клавиши и `Shift`/`Alt` — нет.
- **Запись в интерфейсе** (`hotkey-recorder.ts`): Esc — отмена, Backspace/Delete — очистка, колбэк `validate` может отклонить запись с сообщением.
- **Форма API проверки конфликтов**: `excludeIds` (редактируемая запись), `includeDisabled`, сравнение общего префикса (короткая цепочка конфликтует с длинной).

Почему не берём как зависимость:

- Регистрация привязана к **колбэку** и к DOM-узлу. Реестр у нас данные (команда ↔ сочетание ↔ `when`), которые движок хранит в БД и проверяет без DOM; конфликты в `findHotkeyConflicts` ищутся только среди смонтированных обработчиков (документация: «does not discover unmounted handlers»).
- Нет ни `when`, ни источников и приоритетов, ни пользовательских переопределений, ни персистентности, ни переопределений по платформам — всё это пришлось бы строить поверх.
- Разбор и проверка записи нужны движку (утилитный процесс без DOM) и расширениям (`extension-host`), а модули пакета читают `navigator`/`document` и тянут менеджер через общий вход.
- Alpha: формат и API ещё меняются; завязывать на него хранимые данные рискованно.

Берём идеи и алгоритмы, пишем свой маленький чистый пакет.

## VS Code

- **Правило** — `{ key, command, when, args }`. Диспетчер идёт от последней подходящей записи к первой: первая, у которой совпали клавиши и `when`, выполняется, остальные не смотрятся. Пользовательские правила добавляются в конец встроенных (`keybindingResolver.ts`).
- **Удаление** — запись `{ command: "-cmd", key: … }` убирает встроенную привязку (по ключу и `when`; `whenIsEntirelyIncluded`); это единственный способ «снять» умолчание.
- **Источник и вес** (`keybindingsRegistry.ts`): `weight1` — приоритет источника (`EditorCore` 0 … `BuiltinExtension` 300, `ExternalExtension` 400), `weight2` — порядок внутри. Внешнее расширение весит **больше** ядра, то есть может перебить встроенную привязку; пользовательские записи добавляются после всех и побеждают всех. Вклад расширения: `key` плюс `mac`/`linux`/`win`, `when`, `command`.
- **Цепочки.** Результат разбора — `NoMatchingKb | MoreChordsNeeded | KbFound`; при нескольких кандидатах ждёт следующую клавишу.
- **`when`.** Язык: `!`, `&&`, `||`, `==`, `!=`, `<`, `>`, `=~`, `in`, скобки; контекстные ключи ставит приложение (`editorTextFocus`, `inDebugMode`, `isMac`, `isLinux`, `isWindows`, `config.*`) и расширения (`setContext`). Неизвестный ключ — ложь.
- **Конфликты.** Редактор показывает записи с тем же сочетанием; сам движок конфликт не запрещает — побеждает последняя подходящая. Модель удобна, но пользователь узнаёт о «теневых» привязках только из поиска.
- **Раскладки.** Запись хранится логически (`cmd+/`), при диспетчеризации сверяется с картой раскладки; на раскладках, где символа нет на нужной клавише, редактор показывает `Ctrl+Shift+Alt+Cmd+7`. Есть режим режим по коду.
- **Модель «удалить/переопределить»** требует перекрёстной сверки пользовательских записей с умолчаниями по ключу и `when` — это главный источник путаницы (`-cmd` с неверным `when` ничего не убирает молча).

## Theia

- `KeybindingRegistry` хранит карты по областям `DEFAULT`, `USER`, `WORKSPACE`; дерево привязок строится заново при каждом изменении и при смене раскладки (`keybinding.ts`).
- Сопоставление идёт от высшей области к низшей, внутри — от более позднего; при нескольких подходящих предпочитаются записи с `when`, использующим **локальные** ключи сфокусированного элемента.
- Проверка пересечений: `KeySequence.compare` → `FULL` (совпадение), `PARTIAL` (одна — префикс другой), `SHADOW` (перекрывает); `containsKeybindingInScope` спрашивает о конфликте в заданной области (по умолчанию `USER`) — это основа диалога «сочетание уже занято».
- `setKeymap(scope, bindings)` заменяет область целиком, `resetKeybindingsForScope` — сбрасывает; пользовательская область хранится одним документом.

## Joplin и другие

- Joplin хранит **только отличия** от умолчаний платформы; при загрузке пользовательская карта проверяется целиком (`validateKeymap`), дубликаты запрещены, при ошибке всё откатывается. Плагин не перезаписывает записанный пользователем акселератор. Простая модель «команда → одно сочетание» удобна для интерфейса, но не знает об условиях.
- Obsidian — несколько сочетаний на команду, редактор показывает конфликт и позволяет всё равно назначить; [unverified: по документации, исходников нет].
- Zed и Atom задают условия через контекст/селектор (`context: "Editor && mode == vim"`, CSS-специфичность) — сильнее `when`, но тянет разметку интерфейса в ключи [unverified].

## Выводы для Dolphy

1. **Данные, а не колбэки**: сочетание — запись `{ команда, клавиши, when }`; команды уже лежат в реестре окна (ADR 0012).
2. **Три источника с приоритетом** `user > extension > default` (как у VS Code и Theia); внутри источника — порядок регистрации.
3. **Хранить только пользовательские отличия** (Joplin, VS Code). Вместо записи «удалить» (`-command`) — **замена набора команды целиком**: пользовательский набор команды вытесняет умолчания этой команды, пустой набор — «снято», удаление записи — «по умолчанию». Нет перекрёстной сверки с умолчаниями по `when`.
4. **Условия — `when`** с урезанным языком (`!`, `&&`, `||`, `==`, `!=`, скобки) и **проверкой пересечения условий** (две записи конфликтуют, только если оба `when` могут быть истинны одновременно) — этого нет ни у VS Code (молча берёт последнюю), ни у TanStack.
5. **Три вида пересечений** (Theia): совпадение, префикс цепочки, перекрытие приоритетом; различие между «запрещено» (пользователь против пользователя — движок отклоняет, как Joplin) и «показано» (между источниками решает приоритет, интерфейс предупреждает и предлагает переназначить).
6. **Платформы и раскладки**: `Mod` по платформе (строго, не «Ctrl или ⌘»), вклад с `mac`/`windows`/`linux` (VS Code), сопоставление по `key` с запасом по `code` и физическая запись `[KeyS]` (TanStack), AltGr, IME.
7. **Расширения**: вклад привязывает **только собственные команды** расширения (ADR 0012: расширение не управляет командами приложения); в VS Code расширение может привязать любую команду и весит больше ядра, у нас — нет: приоритет ниже умолчаний приложения, чтобы стороннее расширение не перехватывало клавиши приложения.
8. **Запись клавиш**: рекордер с отменой, очисткой и показом конфликтов до сохранения.
