Метки уверенности: **[В]** — наблюдал сам (команда/вывод ниже) или первичный источник прочитан целиком; **[С]** — первичный источник прочитан частично / вывод из фактов; **[Н]** — НЕ ПОДТВЕРЖДЕНО.
Все версии проверены через `npm view`; пробы запускались во временном каталоге `engine-ts/spike/stack-probe` (удалён после работы) на macOS arm64, Node v22.22.3.

## 0. Как проводились пробы (воспроизводимость)

```
cd stack-probe && npm i better-sqlite3@13.0.3 electron@44.4.5 ts-fsrs@5.4.2 @open-spaced-repetition/binding@0.5.0 zod@4.6.5 valibot arktype
npm i -D typescript@7.0.2 vitest@5.0.2 @types/node@22 tsx tsdown ; npm i node-sqlite3-wasm
node probe.cjs                                                                  # Node 22.22.3
ELECTRON_RUN_AS_NODE=1 ./node_modules/electron/dist/Electron.app/Contents/MacOS/Electron probe.cjs   # Electron 44.4.5 как Node
./node_modules/electron/dist/Electron.app/Contents/MacOS/Electron main.cjs      # настоящий main + utilityProcess
```

Установленные версии (`npm ls`): vite 8.3.1 (peer vitest, подтянут npm), rolldown 1.2.11, esbuild 0.28.2, tsdown 0.23.0, tsx 4.23.15, valibot 1.5.0, arktype 2.2.5. Электрон-бинарь скачан вручную (`node node_modules/electron/install.js`), т.к. postinstall при `npm i` не отработал [В].

### 2d. Замеры для нашего паттерна (append-only 500k строк, range read ORDER BY (ts,id), WAL, synchronous=NORMAL)

Схема: `ev(id INTEGER PRIMARY KEY, ts INTEGER NOT NULL, unit TEXT NOT NULL, score REAL NOT NULL) STRICT` + `INDEX ev_ts(ts,id)`; файл во `/tmp`; вставка 500 000 строк одной транзакцией; затем `SELECT id,ts,unit,score FROM ev WHERE ts>=? ORDER BY ts,id` (`.all()` и `.iterate()`), и 300 отдельных автокоммит-INSERT. Одноразовый прогон (не бенчмарк-статистика).

| Драйвер / рантайм | SQLite | insert 500k, мс | `.all()` 500k, мс | `.iterate()` 500k, мс | 300 autocommit-INSERT, мс |
|---|---|---|---|---|---|
| better-sqlite3 13.0.3 / Node 22.22.3 | 3.53.4 | 334 | 104 | 109 | 3 |

### 2e. Рекомендация по SQLite (ранжирование) и обратимость

1. **better-sqlite3 13.0.3 (основной)** — prebuilt N-API в тарболле, один бинарь для vitest и Electron (проверено), SQLite зафиксирован 3.53.4 в обеих средах, есть `transaction()`/`pragma()`/`backup()`/`serialize()`. Риски: один maintainer; нативный модуль в упаковке (asar unpack, подпись); win32/linux не проверял [Н].
2. **`node:sqlite` (запасной)** — ноль нативных зависимостей, но stability 1.1 в Node 22 (RC только с Node 24.15), SQLite различается между dev (3.51.3) и Electron (3.53.4), нет `transaction()`, null-prototype строки, ExperimentalWarning на Node 22. Годится как альтернативная реализация порта после перехода CI на Node 24.
3. `node-sqlite3-wasm` — аварийный вариант без нативного кода (медленнее, нет WAL, ручные `close/finalize`). `@sqlite.org/sqlite-wasm`, `sql.js` — не подходят; `libsql` — без выгоды.

**Как сделать выбор обратимым**: узкий синхронный порт (интерфейс в домене, драйвер — адаптер):

```ts
export interface SqlStatement<Row = Record<string, unknown>> {
  run(...p: SqlParam[]): { changes: number; lastInsertRowid: number | bigint };
  get(...p: SqlParam[]): Row | undefined;
  all(...p: SqlParam[]): Row[];
  iterate(...p: SqlParam[]): IterableIterator<Row>;
}
export interface SqlDatabase {
  exec(sql: string): void;
  prepare<Row = Record<string, unknown>>(sql: string): SqlStatement<Row>;
  transaction<T>(fn: () => T): T;            // BEGIN IMMEDIATE / COMMIT / ROLLBACK; во вложенности — SAVEPOINT
  pragma(stmt: string): unknown;             // node:sqlite: prepare('PRAGMA …').all()
  backupTo(path: string): Promise<void>;     // единственный async-метод
  close(): void;
}
```

Правила: (а) адаптер нормализует строки в обычные объекты (`{...row}`) — устраняет null-prototype; (б) `readBigInts` выключен, epoch-ms и `id` хранятся как `INTEGER` ≤2^53; (в) один контрактный тест-сьют (`describe.each([betterSqlite3Adapter, nodeSqliteAdapter])`) на append/range/transaction/rollback/WAL; (г) миграции — обычные `.sql`-строки + `PRAGMA user_version`, без драйвер-специфичных фич; (д) in-memory реализация `EventStore` для доменных тестов (SQLite вообще не нужен в vitest-юнитах); (е) драйвер выбирается на composition root, `better-sqlite3` — `external` в сборке.

Если понадобится минимальный вес (напр. общий код в renderer) — переход на `zod/mini` (тот же API-стиль) или valibot.
