### Особенности серде-формата, потребовавшие специальной обработки
1. `Option<T>` с `#[serde(default)]`: ключ отсутствует **или** `null` → `.nullable().default(null)` (в embedded-библиотеке `"description": null`).
2. Внешне тегированные enum'ы (`{"FlashcardAsset": {...}}`, `{"BasicAsset": {"MarkdownAsset": {...}}}`, `{"KnowledgeBase": {}}`): обёртка **всегда** объект ровно с одним ключом, даже в нестрогом режиме (serde отвергает лишние ключи обёртки). Реализовано `z.union` из `z.strictObject({Variant: payload})`. Побочный эффект: ошибка zod для неверного варианта — гигантский `invalid_union` (пример в §4.4); для продукта нужен собственный tagged-хелпер с точным сообщением/путём.
3. Кортежи: `encompassed: [[id, weight]]` → `z.tuple([string, number])`; `(String, Option<String>)` в литеральных примерах → `[string, string|null]` ровно длины 2; `HashMap<usize,(String,String)>` → объект с ключами-цифрами (`regex(/^\d+$/)`).
4. `strict`-режим (`z.strictObject`) отвергает неизвестные ключи структур; нестрогий режим **вырезает** их (zod по умолчанию) — для сквозной передачи неизвестных полей нужен `z.looseObject` [не реализовано].
5. Веса `encompassed` вне [0,1] отвергает **граф**, не схема (как в Rust, `graph.rs:376`); f32 в Rust сравниваются с f64 в TS через `Math.fround`.
6. Пути ассетов приводятся к относительным от корня библиотеки; существование файлов проверяется как в `VerifyPaths` (`data.rs:210`) — для файлов из того же каталога по уже прочитанному листингу (без лишнего `stat`), для путей вне каталога — `statSync`.
7. Зависимости на несуществующие юниты допустимы (обрабатываются логикой dependency sinks); проверено на ручной библиотеке (§4.3).
8. `Trane::new_local` вызывает `init_config_directory` (`lib.rs:311`) и создаёт `.trane/` внутри библиотеки; чтобы не писать в read-only тестовые библиотеки, дамп использует `LocalCourseLibrary::new` напрямую (тот же код открытия, `lib.rs:321`) + публичные методы `UnitGraph`.

- **(a)** Итеративный трёхцветный DFS, линейный, сообщает путь цикла как Rust. На плоских DAG Rust-подобный (клонирование пути на каждый push, `graph.rs:451`) не хуже, но на глубоких цепях квадратичен: цепь из 3 000 уроков в худшем порядке ключей — **8.8 мс** (мой: 0.4 мс); плотная цепь 3 000×4 зависимостей (11 990 рёбер) — 10.5 мс против 0.5 мс (`results/extra-chain.json`). Порядок обхода в Rust — произвольный порядок хеш-таблицы, поэтому на практике попадается любой между лучшим и худшим.
- **(b)** Алгоритм (`algo.ts: transitiveReduction`): топосорт Kahn; для каждого узла зависимости просматриваются от ближайшей к дальней (по убыванию топо-позиции), зависимость, уже лежащая в накопленном битсете достижимости, отбрасывается, иначе сохраняется и её битсет OR-ится: `O(kept·n/32)` времени, `n²/8` байт (1.1 МБ на 3 000). Проверен против наивного эталона O(V·E) на префиксе из 400 узлов: совпадение полное на A1–A4. Худший случай (плотная цепь, 11 990 рёбер, сохраняется 2 999): 0.6 мс. Память растёт как n²/8: 30 000 узлов ≈ 112 МБ [экстраполяция формулой, не измерено].
- **(c)** Порт `get_candidates_from_graph_helper` (`scheduler.rs:726-880`) и `get_all_starting_units` (:219-252): начальный стек из dependency sinks, перемешанные стартовые уроки, `pending_course_lessons`, «валидные» зависимые (все зависимости удовлетворены), `shuffle_to_stack` (Fisher–Yates, seed `mulberry32`), без раннего выхода по `max_candidates` (случай «всё освоено»: посещаются все 3 000 уроков и 12 курсов; pops = 8 761–12 476). **Что НЕ входит:** скорер, фильтры, review knocker, кэш оценок — предикат «зависимость удовлетворена» моделируется 3–4 поиском в `Map/Set`. Поэтому 1.5–3.5 мс — нижняя граница только графовой части, а не замена 4.4–54 мс Rust `get_exercise_batch`.

### 4.4 Паритет ошибок и мутационный тест

Паритет ошибок с Rust (16 кейсов, `errorParity` в `compat.json`) — обе стороны отвергают все 16; формулировки совпадают для ошибок графа/кросс-проверок:
- самозависимость: `unit c::a cannot depend on itself` (совпадает);
- цикл зависимостей: `cycle in dependency graph detected: c::a -> c::c -> c::b -> c::a` — идентичный путь в TS и Rust; цикл курс↔урок `c -> c::a -> c`; цикл superseded `c::a -> c::b -> c::a`; цикл только по encompassed `c::a -> c::b -> c::a`;
- дубликат урока, конфликт типа, вес 1.5, неверный `course_id`/`lesson_id`, пустой id, отсутствующий файл ассета — тот же смысл (в TS сообщение дополнено путём файла);
- расхождения только в тексте парсера JSON/схемы (`malformed JSON`, `missing field course_id`, две ключа в enum-обёртке, завершающий `/` в пути) — обе стороны отвергают, текст разный. Пример «enum-обёртка с двумя ключами»: Rust `expected value at line 8 column 6`; zod — вложенный дамп `invalid_union` из `unrecognized_keys` по каждому варианту (нечитаем, нужен собственный tagged-хелпер).

Мутационный дифференциал (`mutationDiff`): 222 проверки (удаление/подмена типа/`null` каждого поля курса, урока, упражнения; неизвестный вариант, обёртка с двумя ключами, кортеж неверной длины, вес-строка, лишний ключ в структуре и др.) × режимы loose/strict: **0** расхождений zod↔рукописный, **0** расхождений с ожидаемым поведением serde.

## 6. Замечания и ограничения
- **Не измерено:** реальный холодный диск (`purge` не выполнялся); Windows/Linux; Node, встроенный в Electron 44 (замеры на Node 22.22.3); `worker_threads`-параллелизм; real-world курсы кроме тестовых библиотек Trane и синтетики; сквозная передача неизвестных полей (`looseObject`).
- Скорер/фильтры/knocker отсутствуют в (c); Rust-числа 4.4–54 мс — не сопоставимы (§2.2, §3).
- Пиковый RSS async-загрузчика на 3 000 уроков ≈ 209 МБ (Δ ≈ 120 МБ) против ≈ 129 МБ (sync); удержанная куча ≈ 22–26 МБ. Пик определяется буферами/промисами в очереди, а не структурой данных.
- Прогон с `UV_THREADPOOL_SIZE=16` на L3 при zod дал единичный холодный выброс 1 902 мс (warm 532 мс); причина не выяснена, повторов не делалось.
- Загрузчик при `onGenerator: "skip"` пропускает `generator_config` курсы и записывает их в `stats.generatedCourses`; при `"error"` — падает, как поступил бы плоский загрузчик без генераторов.
- Для Rust-сравнения использован `LocalCourseLibrary::new`, а не `Trane::new_local` (см. §1, п. 8); открытие библиотек и граф — тот же код.
- Rust-бенч `trane-mvp` и этот эксперимент используют одинаковую banded-раскладку только у L1; L2–L4 — новые.
- Правила: `trane-pristine` и каталоги `docs`, `trane-mvp`, `trane-fsrs`, `fsrs-vs-trane` не изменялись (дамп только читает).
