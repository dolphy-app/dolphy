# packages

Packages of the `engine-ts` business-logic layer (the project lives in `engine-ts/design/`). All packages are ESM and `private`, with sources in `src/` and tests in `test/`. Packages import each other's sources directly (`exports` → `./src/*.ts`), there is no build: `dist/` contains only `.d.ts` files for `tsc -b`. Four packages are published (`extension-api`, `keybindings`, `extension-sdk`, `extension-tools`, `create-extension`) — not the workspace packages themselves but the `dist-publish/` directories built from them (see "Publishing packages").

`@dolphy-app/engine` exports the subpaths `./ports`, `./app`, `./node` (fs adapters: `createNodeFsCourseSource`), and `./authoring` (scanner, course compiler, artifact, `LibraryHolder`; `yaml` is loaded only by the compiler). The compiler CLI is `pnpm -F @dolphy-app/engine engine-cli validate|compile <library directory>` (`src/cli`, exit code 1 on errors, 2 on invalid arguments). `@dolphy-app/testkit` is wired into the root `package.json` (`workspace:*`), so tests of any package import it without an `engine ↔ testkit` dependency cycle.

`@dolphy-app/engine/sync` — journal merging: `createReplica` (a set of entries + quarantine of conflicts `id-content`/`seq-two-ids`/`clock-skew`, the vector is a contiguous prefix, `exportSince`/`import` ≤ 5 000 entries, local `resolveConflict`), segments and `head.json` of the shared folder (`encodeSegment`, `decodeSegment`, `parseHead`), `importFromTrane` (the `TraneSource` read port), `parseEntry`/`canon`/`compareEntries`. The merge algorithm is written once on top of the synchronous `StoreTx` primitives of the `EventStore` port (`engine/src/ports`): storage adapters implement only those. Stores: `createMemoryEventStore` and `createFolderSync` (shared segment folder, `deviceId` protection: `checkRestore`, `SYNC_DEVICE_ID_CLASH`) live in `@dolphy-app/engine/node`; `openSqliteEventStore` (WAL, `synchronous=FULL` + `fullfsync` on macOS, `durability: 'normal'`, the `SqlDatabase` port, migrations as `.sql` strings, `STORE_BUSY`/`STORE_READONLY`/`STORE_CORRUPT`) and `readTraneDirectory` (`.trane/*.db`) live in `@dolphy-app/engine-sqlite`. A single `EventStore` contract test suite (`engine/test/store/contract.ts`), the merge properties, and the `FolderSync` matrix (`engine/test/sync/`) run against both stores.

Answer verification (M5, F5): `@dolphy-app/engine/verify` — `GradePolicy` (`passAtN`: pass@1 → 5, pass@2 → 4, pass@3+ → 3, `gave-up` → 1, `null` — self-assessment needed; `error` verdicts are not counted) and verdict helpers. Exercise types are extensions (`docs/design/extensions.md`, `docs/adr/0001-exercise-types-as-extensions.md`): the engine knows the `ExerciseTypes` port (`@dolphy-app/engine/ports`: `describe/validateSpec/validateAnswer/project/grade/referenceAnswer`), and verification is performed by the extension host; `@dolphy-app/extension-host` provides discovery, the catalog, the runtime, and the client (`createRemoteExerciseTypes` — with a deadline of `timeoutMs + 2 s` and `error/worker_crash`/`error/timeout` when the host fails), `./local` — the same code path in a single process for the CLI and tests. `@dolphy-app/engine-sql-runner` — `createSqlVerifier({ source, logger, spawnWorker?, workerPath? })`: a pool of `min(4, cores − 1)` child processes (`recycleAfter`, background respawn, kill after `timeoutMs + 100 ms` and on RSS, the RSS watcher is mandatory); `check({ spec, answer, timeoutMs, authorMode })` returns a `GradeResult`. The driver is chosen by a capability probe: `node:sqlite` with `setAuthorizer` and `db.limits` (the `full` profile) or better-sqlite3 (fallback profile: `query_only`, read-only handle, prefilter). `fixture` and `expected` are read from the library through `source` (paths from the root), `spec.reference` is the reference solution. The compiler with `compile(source, { checks: { exerciseTypes }, runChecks: { exerciseTypes } })` runs the references (`referenceAnswer` → `grade`) and emits `E_REFERENCE_FAILS` (`@dolphy-app/engine/authoring`: `checkReferences`), `E_EXERCISE_SPEC`, and `W_UNKNOWN_EXERCISE_TYPE`; the CLI is `engine-cli validate|compile <directory> --run-checks --extensions <root directory>` (the `@dolphy-app/extension-host` package is loaded dynamically: the core does not depend on it). The T-44 budget (1 000 checks ≤ 1 s on a warmed-up pool): `pnpm -F @dolphy-app/engine-sql-runner bench`, not part of `pnpm test`. The default extensions `@dolphy-app/ext-sql` and `@dolphy-app/ext-choice` are built into `dist-ext/` directories (`pnpm -F <package> build`).

Extension contribution ports (`@dolphy-app/engine/ports`): `GradePolicies` (`list`, `evaluate(id, input)` → a grade 1–5 or `null`, throws `GradePolicyError`; the fallback `passAtN` policy is chosen by `resolveGradePolicy` from `@dolphy-app/engine/verify`, it is not a port), `ExtensionRegistry` (`list` — all discovered extensions, including overridden and invalid ones; `contributions()` — contributions of the loaded extensions for the window: types, themes, content renderers, grade policies, commands, panels), and `ExtensionCommands` (`invokeCommand(extensionId, commandId, args?)` → `CommandOutcome`; the `extensions.invokeCommand` service runs outside the engine command queue, [ADR 0008](../docs/adr/0008-extension-commands-and-panels.md)), and `ExtensionTransfers` (`runImporter(extensionId, importerId, input)` → the files of a new course directory, `runExporter(extensionId, exporterId, input)` → the file to save; throws `ExtensionTransferError`; the result is already checked by `normalizeImportResult`/`normalizeExportResult`). Scheduler (M3, F4): `@dolphy-app/engine/scheduler` — the Trane scheduler port. `createDepthFirstScheduler`: DFS over the graph → `ReviewKnocker` → `CandidateFilter` (mastery windows adjusted by success rate, weighted sampling without replacement through the `Rng` port) → repetition pool → `Shuffler`; a single options holder `createSchedulerOptionsHolder` (`verify`, atomic `set`, subscribers; components read the options on every computation instead of keeping clones); `SessionState` (shown map, repetition pool, success counters; `reset()` — `startSession`); pure `getFrontier` (no data = closed; a unit without valid exercises is transparent) and `getDue` (R from `MemorySource`); Trane filters and zod wire codecs (`filters.ts`, `filter-codec.ts`); `toScoringGraph` (`UnitGraph` → `ScoringGraph`). Adaptive layer (M6, F3/F4): `@dolphy-app/engine/placement` — diagnostics: `buildTopicGraph` (lessons on the transitive reduction, CSR up/down), `createDiagnosticSession` (V3 only, with hard closure λ = 1, K = ∞: the probe is the middle of the longest chain of unresolved topics; logits, thresholds 0.15/0.85, `minPass = 2` for probes with guessing; `nextProbe` is idempotent until answered, determinism by (seed, answers) — probe selection and propagation match the `spike/diagnostic` spike bit for bit), `buildPlacementTopics` (empty and blacklisted lessons are transparent, a probe is an exercise with `engine.verification`), `placementAttempts` (2 attempts per exercise of `known` lessons, grade 4, rounds in order). `@dolphy-app/engine/planning` — `createPlanner` (due by R, greedy coverage with a lazy heap, a 25% reserve for new material, remediation before new material, `interleave` interleaving; the state comes from outside as `PlanState`), `createMulberry32`/`createSeededRng` (a uint32 seed → `Rng`), `createFractionalStepper` (`stepFractional` over the `MemoryModel` port; the forgetting curve is given explicitly and checked against the model), `buildPlanGraph` (`declared` — only declared `encompassed`; `graph` — with the Trane auto-rule), `createCreditModel` (`λ`, `minCredit`, `κ`), `createMemoryIndex` (a `{S, D, lastAt}` projection; credit is off by default and does not change `D` in v1), `collectDue`. Application services (`@dolphy-app/engine/app`, `app/services/{library,curation,settings}.ts`): `createLibraryService(ctx)` (`getInfo`/`getDiagnostics` — diagnostics of the last `reload` attempt plus `W_ORPHAN_EVENTS` from the journal; `validate` does not replace the graph and does not write the artifact, the page cursor is bound to the result of the last `validate`; `compile` writes the artifact if there are no errors and no fresh one exists; `reload` — `ignored_paths` from preferences, if a version is rejected the previous graph stays; `getGraph` — the neighborhood of `rootIds` at `depth`, limit 500/2000), `createCurationService(ctx)` (flags are `unit_flag` journal entries, idempotent by state; filters and sessions — the settings store + `ctx.savedFilters`), `createSettingsService(ctx)` (scheduler options through `ctx.options`, preferences; `restartRequired` — when `schedulerBatchSize` changes). State and composition root (M4, `@dolphy-app/engine/app`, `src/state/`): `createEngine(deps, config)` (`EngineDeps` — ports plus optional `folderSync`, `logReader` and `openTraneSource`; `createContext` → library, settings and options, projections, scorer, rebuild from the journal without an event; `createEngineFromContext(ctx)` — services and the facade over a ready `EngineContext`, which is how tests are assembled) and `nodeDefaults(config)` (`@dolphy-app/engine/node`: clock, `CryptoRng`, uuidv7, JSON logger to stderr, fs course source, JSON settings, `MemoryModel` on ts-fsrs, the shared-folder port, and `createFileLogReader(config.logsDir)` as the `LogReader` behind `extensions.readLogs` when `logsDir` is set). Projections (`createProjections`): `AttemptIndex` stores all attempt entries per exercise, sorted by `(at, deviceId, seq, id)`, insertion is idempotent and order-independent; non-cancelled attempts are those with a key greater than the latest `progress_reset` of the exercise, lesson, or course (boundaries are computed against the graph of the current library at read time); the `numTrials` window is applied at read time (`getTrials`), while `count` counts all survivors; `FlagState` — LWW by entry key; rewards and `MemoryIndex` are derived projections: an entry newer than all applied ones updates them on the fast path, an old entry or a reset marks them stale, and they are recomputed on read, so incremental application in any order and with duplicates equals `rebuild` (property test in `test/state`). `RemediationTracker` (F6): the trigger is a run of `failThreshold` grades ≤ 2 in a row among non-cancelled attempts (the last such run), the steps are the exercise's `engine.keyPrerequisites`, otherwise the lesson's direct dependencies in ascending order of mean R at trigger time; per step, exercises in ascending R (not started — R = 0, by id), at most `remediation.maxItems` in total; a step is closed by success (grade ≥ 3) on each of its exercises after the trigger. Practice (`createPracticeService`): `recordAttempt` — steps 1–6 of the "Attempt recording flow" (verification → `ctx.commit` with seq/HLC and `append` in a single transaction → projections and scorer caches → `progress`), a repeated `requestId` returns the earlier entry with `duplicate: true` and no remediation; a projection failure after `append` sets `dirty`, and the next command does a `rebuild` first; `submitAnswer` runs outside the queue: an answer longer than `MAX_ANSWER_CHARS`, not JSON, or not matching the type's schema (`validateAnswer`) gives `INVALID_ARGUMENT` without spending an attempt, the `grade` deadline is held by the extension host client (`timeoutMs` + 2 s); `getBatch` inserts remediation items before new material and evicts the tail of `new` (with an explicit filter, remediation is not inserted); `getProgress` computes statuses by the frontier (`locked` — the lesson is not started and not on the frontier, `mastered` — the grade is not below the lower bound of the `easy` window, otherwise `in-progress` if there are attempts). Diagnostics: `exerciseHitRatio` — the share of library exercises with a grade in the `UnitScorer` cache.

## Publishing packages

The packages `@dolphy-app/extension-api`, `extension-sdk`, `extension-tools`, and `create-extension` are published to npmjs (`https://registry.npmjs.org`, organization `dolphy-app`, `--access public`); they install with a plain `npm install`, with no token and no `.npmrc` ([ADR 0005](../docs/adr/0005-npm-publishing.md)).

- `pnpm build:packages [--version X.Y.Z]` (`tools/build-packages.mjs`) builds each package into `dist-publish/<package directory>/`: `dist/` (a `tsdown` bundle: JS and `.d.ts`; private monorepo packages are inlined, dependencies from `node_modules` stay external), a generated `package.json` (without `workspace:` and `private`; `extension-tools` and `create-extension` get a `bin`), and `README.md` (from the template `tools/templates/package-readme.md`). The default version is the version of the root `package.json`.
- `pnpm verify:packages [--keep]` (`tools/verify-packages.mjs`) verifies the build output: `npm pack` and the tarball contents, installing all four into an empty project, generating a project with the installed `create-dolphy-extension` and running its `build`, `validate`, and tests. It needs network access (third-party dependencies are installed from npmjs) and is not part of `pnpm test`. `dist-publish` is in `.gitignore`.
- On pull requests, `.github/workflows/packages.yml` builds, verifies, and runs `npm publish --dry-run` without a token; after a tag, `.github/workflows/release.yml` publishes the packages with the release version (repository secret `NPM_TOKEN`; an already published version is skipped).

## TypeScript 7 and the root typescript

`typescript-eslint` and `vue-tsc` (`apps/desktop`) do not work with TS 7, so the root `typescript` stays at `^6.0.3` (for ESLint and desktop). TS 7.0.2 is a `devDependency` of every `packages/*` package; `tsc` runs from the package (`pnpm exec tsc`, the nearest `node_modules/.bin`) and picks up version 7. Calling `node_modules/.bin/tsc` in the root gives TS 6.

Configs: `tsconfig.base.json` (`strict`, `erasableSyntaxOnly`, `verbatimModuleSyntax`, `module esnext`, `moduleResolution bundler`); in a package, `tsconfig.json` is the `src` project (`composite`, `emitDeclarationOnly`, output to `dist/`), and `tsconfig.test.json` is the `test` project (`noEmit`, references to `src` and `testkit`). The root `tsconfig.json` is a "solution" referencing everything. `tsconfig.vitest.json` (contract, engine) is the config for vitest's typecheck mode without references: it reads the sources, not a stale `dist/`.

## Tests

Type tests are `test/**/*.test-d.ts` (in `engine-contract`, `engine`): they fail both in `pnpm typecheck` and in `pnpm test`. `RPC_METHODS` is checked against the `LearningEngine` methods (`test/rpc-keys.test-d.ts`): an extra or missing key is a type error. The py-fsrs reference for `MemoryModel` is `engine/test/fixtures/reference.json` (600 histories, 18 564 reviews; `gen_reference.py` is the generator), checked by `engine/test/contract/memory-model.test.ts`.

Heavy runs are controlled by environment variables: `ENGINE_FULL_PROPERTIES=1` (merge with 3 000 runs on SQLite, `FolderSync` convergence with 150 runs on each store, ≈ 1.5 min), `ENGINE_CRASH_ITERATIONS=300` (the SQLite SIGKILL test: 300 kills per `NORMAL` and `FULL` mode, ≈ 205 s per mode in the spike; 15 by default). The full campaign with a summary: `pnpm -F @dolphy-app/engine-sqlite crash NORMAL 300 1 10` (arguments: mode, iterations, seed, number of "large" transactions, rows in them).

CI: the `typecheck` and `test` jobs run on Node 22 and 24, `lint` on the version from `.nvmrc`.
