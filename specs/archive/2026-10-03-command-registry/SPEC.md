# Общий реестр команд приложения

Живой документ, пока `status` — `draft` или `active`: `Progress`, `Surprises & Discoveries`, `Decision Log` обновляются вместе с кодом. По завершении фичи переносится в `specs/archive/` и не меняется. Правила — скилл `spec-workflow`.

## Цель

В окне приложения один реестр команд, как в VS Code: в нём лежат команды самого приложения (переходы, смена темы, смена языка) и команды расширений. Палитра (Ctrl/⌘+K), раздел «Сочетания клавиш» и сочетания клавиш читают только реестр и не знают, откуда команда. Добавить команду в приложение — значит зарегистрировать её в реестре; расширения попадают туда же без отдельной ветки кода.

## Не цели

- Вызов команд приложения из расширений: расширение из каталога не должно управлять приложением. Если понадобится, добавим явный флаг «открыта расширениям» на конкретных командах отдельным решением.
- Пользовательская настройка сочетаний клавиш (аналог `keybindings.json`) остаётся отложенной: сочетания у команд приложения заданы в коде, раздел «Сочетания клавиш» только показывает их; у команд расширений `keybinding` остаётся подсказкой.
- Подсказка о палитре при первом запуске (онбординг).
- Двухшаговая палитра с выбором значения: выбор значения — это отдельные команды на каждый вариант («Тема: Светлая»).
- Команды, которым нужно состояние страницы («Начать занятие»: план дня загружается страницей), и смена курса (нужен выбор из списка).
- Контекстные условия `when` в виде выражений: доступность команды задаёт реактивная функция в коде приложения.
- Изменения `engine-contract`, RPC и `engine.db`: всё в окне.

## Требования

Наблюдаемое поведение. Проверки — юнит-тесты `apps/desktop/test`, e2e `apps/desktop/e2e`.

- R1. Реестр. Один реактивный реестр команд окна. Команда: ключ (уникальный, `app:<id>` или `extension:<extensionId>:<id>`), источник (`app` или `extension`), название, необязательная категория, необязательное сочетание клавиш, признак «выбрано» (для вариантов вроде текущей темы), реактивная доступность и обработчик. `register` возвращает функцию отмены; повторная регистрация того же ключа — ошибка. Список читается реактивно и не кэшируется по идентичности.
- R2. Команды приложения (первый набор). Переходы: «План дня», «Курсы», «Граф знаний», «Настройки» и каждая вкладка настроек («Обучение», «Библиотека», «Внешний вид», «Расширения», «О движке»). Смена темы: одна команда на каждую тему из реестра тем — «Как в системе», «Светлая», «Тёмная» и темы установленных расширений; команда текущей темы помечена как выбранная. Смена языка: «Русский», «English», «Как в системе»; текущий выбор помечен. Названия команд приложения, категории («Переход», «Тема», «Язык») и пометки — через `vue-i18n` (`ru`, `en`); названия тем расширений — данные без перевода.
- R3. Темы расширений как команды. Команда смены темы появляется сразу после установки или включения расширения с темой и пропадает при удалении или отключении, без перезагрузки окна (живое применение). Если выбранной темы больше нет, поведение прежнее («Как в системе», сохранённое не меняется).
- R4. Команды расширений. Адаптер регистрирует в реестре команды из хранилища вкладов с `palette: true`, обновляет их по `contributions-changed` и снимает при удалении; команда выполняется прежним путём (`extensions.invokeCommand`, эффекты `notify` и `openPanel`, сообщения об ошибках по причинам). Команды с `palette: false` в реестр не попадают (остаются доступны панелям). Ключ учитывает источник, поэтому совпадение `id` команды приложения и расширения не затирает записи.
- R5. Палитра. Читает только реестр: поиск без учёта регистра по названию, категории и (для команд расширений) идентификатору расширения; группировка по категории; у команд расширений показан идентификатор расширения, у команд приложения — нет; выбранные варианты помечены (текст и `aria`-состояние), недоступные команды не показываются; выбор и состояние «выполняется» сохраняются по ключу при живом изменении списка. Без установленных расширений палитра не пуста. Доступность (combobox, listbox, фокус) прежняя.
- R6. Сочетания клавиш. Один диспетчер на уровне приложения: Ctrl/⌘+K открывает палитру на любой странице, в том числе из полей ввода и рамок; командам приложения можно задать сочетание, оно выполняется, если фокус не в поле ввода, редактируемом элементе, открытом диалоге или рамке (исключение — Ctrl/⌘+K) и клавиша не повторяется. Рамка расширения по-прежнему пересылает родителю только Ctrl/⌘+K. Сочетания показаны в палитре с учётом платформы (⌘ или Ctrl).
- R7. Кнопки палитры в боковом меню нет (решение владельца 2026-10-03). Палитра открывается Ctrl/⌘+K и кнопкой «Открыть палитру команд» на странице «Настройки → Сочетания клавиш».
- R8. Смена языка и темы командой и с экрана «Внешний вид» работает через одно и то же вызываемое API (`theme-selection` уже есть; логика языка выносится из композабла `useAppearanceSettings` в `shared/api/engine/locale-selection.ts` с сохранением в настройках и откатом при ошибке); экран «Внешний вид» использует его же, поведение экрана не меняется.
- R9. Расширения не могут вызвать команду приложения: в протоколе вызовов и в результатах команд нет способа обратиться к реестру приложения (проверка: тест на то, что результат `openPanel`/`notify` не умеет запускать команды приложения, и документация).
- R10. Раздел «Настройки → Сочетания клавиш» (вкладка после «Внешний вид», маршрут `settingsShortcuts`). Только чтение; строится из реестра: все команды приложения с сочетанием, по категориям, название локализуется реактивно, клавиши в `<kbd>` по платформе (⌘/Ctrl/⇧/⌥), доступная таблица; подсказки расширений не показываются. Вверху пояснение «Палитра команд ищет команды приложения и расширений» и кнопка «Открыть палитру команд» с подсказкой клавиш. Набор сочетаний (команды приложения, все с `Mod`): `Mod+K` — «Открыть палитру команд» (категория «Приложение»; скрыта из палитры флагом, видна в разделе), `Mod+,` — «Перейти: Настройки», `Mod+1` — «Перейти: План дня», `Mod+2` — «Перейти: Курсы», `Mod+3` — «Перейти: Граф знаний»; остальные команды без сочетаний. Проверки: юнит модели страницы и флага скрытия, e2e: пять строк с клавишами платформы, сочетания навигируют и не срабатывают в поле ввода, кнопка открывает палитру.

## Решения

- **Реестр — общий слой.** Чистый реестр без зависимости от Vue-страниц лежит в `shared/lib`; команды приложения описываются в отдельной фиче (`features/app-commands`) и регистрируются в корне композиции `app/main.ts`, где доступны маршрутизатор, `i18n`, выбор темы, выбор языка и движок; адаптер расширений остаётся в `features/extension-commands` и использует прежний исполнитель. Палитра (виджет) и раздел «Сочетания клавиш» зависят только от реестра.
- **Значение — отдельная команда.** «Тема: Полночь» и «Язык: English» — самостоятельные записи, а не параметр одной команды: это не требует двухшаговой палитры и естественно живёт с реактивным списком тем.
- **Приоритет по ключу, а не по id.** Ключ включает источник; совпадение `id` не перезаписывает чужую запись, и ни одно расширение не может заменить команду приложения.
- **Сочетания клавиш только у команд приложения.** Один диспетчер на `document`, без передачи произвольных клавиш из рамок (рамка пересылает только Ctrl/⌘+K), чтобы враждебная рамка не могла вызывать команды.
- **Контракт не меняется.** Расширения из каталога не получают доступа к реестру; решение ограничивает будущее и фиксируется ADR 0012.
- **Палитра без кнопки в меню.** Решение владельца: меню не должно быть перегружено. Палитра открывается сочетанием и кнопкой в разделе «Сочетания клавиш»; «Открыть палитру команд» — команда приложения с `Mod+K`, скрытая из самой палитры.

## Surprises & Discoveries

Разведка до начала работ: палитра напрямую читает хранилище вкладов и жёстко типизирована под `CommandContributionDto`; Ctrl/⌘+K слушает сам компонент палитры; логика смены языка находится внутри композабла `useAppearanceSettings` и работает только в контексте `setup`; выбор темы уже имеет вызываемое API (`theme-selection`); план дня хранится в состоянии страницы, поэтому «Начать занятие» глобальной командой без рефакторинга не сделать.

- Палитра, открытая из поля ввода (например, из поиска по каталогу), оставляла фокус в поле под диалогом: `autofocus` работает только при монтировании. Исправлено явным `focus()` после появления диалога.
- Axe `scrollable-region-focusable` (serious) на списке палитры появился, когда команд стало больше высоты списка: `tabindex="-1"` правило не снимает, нужен `tabindex="0"`; щелчок по строке фокус не забирает (`mousedown.prevent`).
- Фокус после закрытия палитры иногда оставался на `body`: `after-leave` приходит, пока фокус ещё внутри закрывающегося диалога, и прежняя проверка «фокус потерян» его не считала потерянным. Теперь фокус в диалоге палитры тоже считается потерянным. Воспроизводилось в сценарии design review, e2e без исправления проходил, поэтому гонку регрессионный тест не ловит.
- Сокращённая подпись клавиш (`⌘K`) скринридером читается набором символов: символы скрыты (`aria-hidden`), рядом лежит озвучивание словами («Command K», «Control запятая»).
- Конфликтов сочетаний `Mod+,` и `Mod+1…3` с умолчаниями Electron нет: меню приложения нет. Сочетания проверены в e2e только с `Control` (macOS-`⌘` отдельно не прогонялся: `Mod` принимает и Ctrl, и ⌘).
- Состояние раздела «Сочетания клавиш» без сочетаний (пустой реестр) в настоящем приложении недостижимо: реализовано (`v-if`), в живом окне не проверялось.

## Decision Log

- 2026-10-03. Команды приложения недоступны расширениям. Причина: расширение из каталога не должно управлять приложением; флаг открытости на отдельных командах добавим при реальной потребности.
- 2026-10-03. Выбор значения — отдельные команды. Причина: проще двухшаговой палитры, хорошо ложится на реактивный список тем.
- 2026-10-03 владелец: кнопку из меню убрать, сочетания показывать в настройках. Причина: меню не должно быть перегружено, сочетания живут в настройках. Компромисс: пользователь узнаёт о палитре из раздела «Сочетания клавиш» и по описанию; возможная доработка — подсказка при первом запуске (не делаем).
- 2026-10-03. Палитра, открытая из поля ввода, явно забирает фокус (`after-enter`): `autofocus` срабатывал только при первом монтировании, и ввод оставался в поле под диалогом.

## Outcomes

Один реактивный реестр команд окна (`shared/lib/command-registry.ts`): палитра, диспетчер сочетаний и раздел «Сочетания клавиш» читают только его. Команды приложения (`features/app-commands`): переходы, темы (динамически по списку тем, включая темы расширений), языки, «Открыть палитру команд» (скрыта из палитры). Адаптер команд расширений (`features/extension-commands`) регистрирует `palette: true` по `contributions-changed`; расширения не вызывают команды приложения (R9, тест и документация, ADR 0012). Смена языка вынесена в `locale-selection`, экран «Внешний вид» использует его же. Сочетания: `Mod+K`, `Mod+,`, `Mod+1…3`, один диспетчер на `document`; из рамок по-прежнему только Ctrl/⌘+K. Кнопки палитры в меню нет, она есть на странице «Сочетания клавиш». Не сделано, по решению: пользовательские сочетания, подсказка при первом запуске.
