# Обновления курсов из git: проверка при запуске, уведомление и плашка на экране «Курсы»

Живой документ, пока `status` — `draft` или `active`: `Progress`, `Surprises & Discoveries`, `Decision Log` обновляются вместе с кодом. По завершении фичи переносится в `specs/archive/` и не меняется. Правила — скилл `spec-workflow`.

## Цель

Пользователь узнаёт, что курс из git-репозитория обновился, без захода в «Настройки → Библиотека → Репозитории»: приложение само сверяется с сервером, на экране «Курсы» показывает плашку с кнопкой «Обновить» и пометку на карточках затронутых курсов, а при открытии приложения один раз сообщает, какие курсы можно обновить. Сейчас обновление курса видно только тому, кто сам нажал «Обновить» в настройках.

## Не цели

- Автоматическое обновление: приложение только сообщает, скачивание и подмена снимка — по нажатию «Обновить» (как `repositories.update`).
- Настройка отключения проверки и интервал проверки: проверка при запуске всегда включена; отдельная настройка — новая спека, если понадобится.
- Периодическая проверка в работающем приложении и проверка по фокусу окна: только запуск и кнопка «Проверить обновления».
- Показ списка изменений (changelog, diff коммитов): сравниваются только идентификаторы коммитов.
- Проверка расширений (у них своя: `runStartupUpdateCheck`) и приватных репозиториев с учётными данными (их в приложении нет).
- Сохранение результата проверки между запусками: после перезапуска проверка выполняется заново.

## Требования

Наблюдаемое поведение. Проверки — юнит-тесты `packages/engine`, `packages/engine-rpc`, `apps/desktop/test`, e2e `apps/desktop/e2e`.

- R1. Проверка репозитория. `repositories.checkUpdates()` для каждого зарегистрированного репозитория спрашивает у сервера коммит ветки или тега (`ref` репозитория) без скачивания объектов и возвращает те же `RepositoryDto`, что `repositories.list()`. Если коммит сервера отличается от загруженного, у репозитория есть `availableCommit` (полный SHA); если совпадает — поля нет. У каждого проверенного репозитория есть `checkedAt`. Проверка: тест сервиса `repositories` на фейковом `GitSnapshotFetcher` (коммит отличается / совпадает / ветка по умолчанию / тег).
- R2. Сбой проверки не ломает остальное. Репозиторий, до которого не достучались (сеть, 404, таймаут, отмена), пропускается: его `availableCommit` и `checkedAt` остаются прежними, остальные репозитории проверяются, вызов не падает; причина идёт в журнал уровня `warn`. Репозиторий с идущей операцией (`updating`) не проверяется. Проверка: тест сервиса с фетчером, который падает для одного из двух репозиториев; тест репозитория в статусе `updating`.
- R3. `list()` отдаёт результат последней проверки. `repositories.list()` возвращает `availableCommit` и `checkedAt` из последней проверки этого запуска движка; до первой проверки полей нет. Результат не пишется в `engine.db` (схема БД не меняется). Проверка: тест сервиса (`list` до и после `checkUpdates`).
- R4. Обновление и удаление сбрасывают пометку. После `repositories.update(id)`, загрузившего новый коммит, и после `update`, который нашёл коммит сервера равным загруженному (`changed: false`), `availableCommit` у репозитория отсутствует; после `remove(id)` результат проверки забыт. Если за время `update` на сервере появился ещё один коммит, пометки нет (она появится после следующей проверки). Проверка: тест сервиса.
- R5. Проверка при запуске. После открытия движка в фоне, не задерживая запуск и не мешая другим вызовам, выполняется то же, что `repositories.checkUpdates()`; сбой только в журнал. Проверка: тест `createEngineFromContext` с фейковым фетчером (событие после открытия, запуск не ждёт фетчер).
- R6. Событие. После каждой завершённой проверки (запуск и ручная) движок публикует `{ type: 'repository-updates-checked'; available: string[] }` — `id` репозиториев с `availableCommit` в порядке `list()`; окно перечитывает `repositories.list()`. Событие приходит и при пустом `available` (кнопка «Проверить» получает ответ), но не приходит, если не проверялся ни один репозиторий. Проверка: тест сервиса и RPC-тест доставки события подписанному клиенту.
- R7. RPC. `repositories.checkUpdates` — метод RPC без аргументов, не в очереди команд (ходит в сеть, как `repositories.update`), идемпотентный; ответ проходит ту же схему, что `repositories.list`. Версия контракта повышается. Проверка: `packages/engine-rpc/test` (схема, `UNQUEUED`, идемпотентность), `exhaustive.test-d.ts` (новое событие).
- R8. Плашка на экране «Курсы». Если у репозитория есть `availableCommit`, над панелью фильтров показана плашка на каждый такой репозиторий: адрес репозитория (без `https://`), названия курсов репозитория и кнопка «Обновить». Нажатие вызывает `repositories.update`, на время операции кнопка заблокирована и показывает ход (фаза `repository-progress`), при успехе плашка исчезает, список и карточки курсов перечитываются (`library-reloaded`), при отказе под плашкой текст ошибки (как в «Настройки → Репозитории»). Проверка: тест модели в `apps/desktop/test` и e2e: репозиторий на локальном git-сервере обновляется кнопкой.
- R9. Пометка на карточке. Карточка курса репозитория с `availableCommit` показывает чип «Есть обновление»; без обновления чипа нет. Проверка: тест модели (курс → репозиторий), e2e.
- R10. Кнопка «Проверить обновления». В шапке экрана «Курсы» есть кнопка; пока идёт проверка, она заблокирована; по завершении показывается уведомление: «Найдено N обновлений» (формы числительных), если эта проверка нашла обновление; «Все курсы актуальны», если все репозитории сверены и обновлений нет; «Не удалось связаться с сервером курсов…», если часть репозиториев сверить не удалось и новых находок нет (находка прежней проверки недоступного репозитория не считается). Если репозиториев нет, кнопки нет. Проверка: тест модели (`checkOutcome`), e2e.
- R11. Уведомление при запуске. Если проверка при запуске нашла обновления, окно один раз за запуск показывает уведомление «Доступно обновление курсов: <названия>» с действием «К курсам» (ведёт на экран «Курсы»); для одной и той же пары (репозиторий, `availableCommit`) повторно оно не показывается после закрытия и после повторных проверок. На экране «Курсы» уведомления нет (там видна плашка), и всё, что есть на нём, считается сообщённым; во время сессии и входного теста уведомление снимается без отметки и появляется после ухода с этих экранов. Если окно открылось после проверки, уведомление всё равно показывается (результат берётся из `repositories.list()`). Проверка: тест модели (`announcementStep`: дедупликация, маршруты, окно после проверки), e2e.
- R12. «Настройки → Библиотека → Репозитории». Строка репозитория с `availableCommit` показывает метку «Есть обновление» (кнопка «Обновить» уже есть). Проверка: e2e (метка в строке репозитория до обновления).
- R13. Все строки интерфейса — через `vue-i18n` (`ru`, `en`, формы числительных); названия курсов — данные движка и не переводятся. Проверка: тест полноты ключей `courses` (`en: typeof ru`) и `pnpm typecheck`.
- R14. Документация. Контракт описан в `engine-ts/design/engine-ts-api.md` (раздел `repositories`, событие), поведение экрана — в `apps/desktop/README.md`. Проверка: просмотр.

## Решения

**Где хранится результат проверки.** В памяти сервиса `repositories` (`Map<id, { commit, checkedAt }>`), а не в `RepositoryRecord`: схема `engine.db` не меняется, а устаревшие данные не переживают перезапуск и не могут показать «обновление», которое уже установлено другим путём. Ключ — `id` репозитория; при чтении `list()` запись игнорируется, если `commit` репозитория уже равен сохранённому `availableCommit` (защита от гонки).

**Как проверять.** `GitSnapshotFetcher.resolve({ url, ref, signal })` — тот же вызов, что открывает `update`: он читает ссылки сервера и объекты не качает (`ls-remote`). Проверка берёт общий `AbortSignal` закрытия движка, не встаёт в цепочку `serial` (чтобы долгая загрузка не блокировала проверку и наоборот), но пропускает репозитории с идущей операцией. Репозитории проверяются последовательно: их обычно единицы, а нагрузка на сервер остаётся минимальной. Таймаут одного обращения задаёт фетчер.

**Событие, а не опрос.** `repository-updates-checked` по образцу `extensions-changed`: окно может открыться раньше или позже конца проверки, поэтому оно и читает `list()` при создании хранилища, и перечитывает по событию. Событие публикуется через `ctx.bus.publish` (вне очереди команд, как `repository-progress`), метод `checkUpdates` в `UNQUEUED`.

**Окно.** Хранилище `features/course-updates` (по образцу `shared/api/engine/extension-updates.ts` и `features/course-scope`): читает `repositories.list()` и `library.listCourses()`, перечитывает по `repository-updates-checked`, `library-reloaded` и после переподключения; раздаётся через `provide` из `app/main.ts`. Оттуда же берутся плашки (`CourseUpdatesBanner`), чип карточки (через `updateOf(courseId)`), кнопка проверки и уведомление запуска (`CourseUpdatesSnackbar`, монтируется в `App.vue` рядом с `NoticeSnackbar`). Признак «уведомление уже показано» — набор `repoId@commit` в памяти окна (при перезапуске приложения показывается снова: так задумано, обновление всё ещё не установлено). Названия курсов репозитория — из `RepositoryDto.courseIds` и `library.listCourses()`; курс, которого нет в библиотеке, показывается по `id`.

**Что не меняется.** `repositories.update` и `fetchFlow` (проверка `upToDate` уже есть); `RepositoryRecord` и порт `RepositoryStore`; настройки.

## Surprises & Discoveries

- Тест «createEngine recovers before the first library load…» утверждал «сети при запуске нет» (`git.calls` пуст). Проверка при запуске вызывает `resolve`, поэтому утверждение сужено: восстановление снимков в сеть не ходит и снимков не качает, допустимы только вызовы `resolve`.
- Первый design review (Electron, e2e-сборка, светлая и тёмная темы): итог ручной проверки при недоступном сервере говорил «Найдено 1 обновление» по прежней находке; чип на карточке сдвигал описание на 42 px относительно соседней карточки; отказ обновления в плашке был оформлен цветом `info`. Исправлено: `checkOutcome` засчитывает находку только ответившему репозиторию, чип стоит в колонке чипов шапки карточки, отказ — `text-error` со значком, тайм-аут уведомления запуска 15 с.
- Второй design review: в узкой карточке (три колонки на 1920) чип «Есть обновление» отнимал ширину у названия, и оно рвалось посреди слова («репозитори/я»). Подпись чипа скрывается container query (карточка уже 24rem), остаётся значок с `aria-label` и `title`. Заголовок «Рекомендуем» у `Choice (KnowledgeBase)` рвёт название так же, но это прежнее поведение, не затронутое этой фичей.

## Decision Log

- 2026-10-05. Результат проверки только в памяти. Причина: не менять схему `engine.db`; пометка не должна пережить перезапуск, после которого её всё равно пересчитывает проверка запуска.
- 2026-10-05. Настройки «не проверять обновления» нет. Причина: проверка — один запрос ссылок на репозиторий, а репозитории добавляет сам пользователь; настройка тянет контракт, адаптеры и тесты адаптеров. Если понадобится, отдельная спека (по образцу `extensions.setCheckUpdates`).
- 2026-10-05. Уведомление запуска не показывается на `/session`, `/placement` и самом экране «Курсы». На сессии и входном тесте оно откладывается без отметки, на экране «Курсы» всё считается сообщённым. Причина: не прерывать занятие; на экране «Курсы» то же самое уже видно в плашке, а показ после ухода с него повторял бы уже виденное.
