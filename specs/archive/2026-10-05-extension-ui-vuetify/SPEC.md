# UI-кит расширений: настоящие компоненты Vuetify в подпутях `@dolphy-app/extension-ui`

Живой документ, пока `status` — `draft` или `active`: `Progress`, `Surprises & Discoveries`, `Decision Log` обновляются вместе с кодом. По завершении фичи переносится в `specs/archive/` и не меняется. Правила — скилл `spec-workflow`.

## Цель

Автор расширения подключает в панели, виджете или виде ответа основные компоненты Vuetify 4 (поля ввода, группы radio и checkbox, статусы, вкладки, оверлеи, таблицы) и получает вид и поведение приложения без своих стилей. Vue и Vuetify собираются в `view.mjs`, `panel.mjs` или `widget.mjs` самого расширения: рамка изолирована (`sandbox="allow-scripts"`, CSP `script-src dolphy-ext://<id>`), общих с приложением модулей у неё нет.

Прежний ванильный набор (`button`, `textField`, `select`, `toggle`, `list`, `card`, `emptyState`) удалён без обратной совместимости по решению владельца (см. `Decision Log`): корневого экспорта у пакета нет.

## Не цели

- Сохранение корневого ванильного набора и его лимита 10 КиБ gzip (отменено решением владельца, см. `Decision Log`).
- Перевод `ext-js`: его редактор кода (прозрачная textarea поверх слоя подсветки) остаётся собственным, в Vuetify такого компонента нет.
- Написание кода расширения на Vue целиком: подпуть даёт функции `mount…`, а не публичный API компонентов и композиблов Vuetify.
- Оверлеи (диалог, меню) за пределами окна приложения; рамка растёт только внутри слота, который ей отдало приложение (R4).

## Требования

Наблюдаемое поведение, не реализация. У каждого требования есть проверка.

- R1. `dolphy-ext build` собирает проект, который импортирует подпуть набора. CSS из зависимостей (`import './VBtn.css'` внутри `node_modules`) попадает в сборку и добавляется на страницу рамки одним `<style>`; собственный `import './x.css'` автора по-прежнему падает с сообщением про `?inline`. Проверка: тест `extension-tools` на фикстуре с зависимостью, импортирующей CSS, и на собственном CSS автора.
- R2. Цвета компонентов совпадают с темой приложения: значения берутся из `--v-theme-*` рамки, смена темы в приложении меняет вид без перезагрузки рамки, светлая и тёмная темы. Проверка: e2e-панель, `getComputedStyle` ключевых цветов равен переменным рамки в обеих темах; axe без нарушений `serious` и `critical` в обеих темах.
- R3. Встроенные строки Vuetify (таблица данных, поле даты) идут на языке интерфейса: `ru` или `en` по `<html lang>` рамки, при смене языка обновляются. Проверка: e2e, `v-data-table` с пустым списком показывает русскую и английскую строки.
- R4. Диалог, меню и подсказка, открытые в рамке режимов `answer`, `markdown` и `widget`, видны целиком: на время открытого оверлея приложение увеличивает рамку, после закрытия возвращает высоту содержимого. Запрошенная рамкой высота ограничена сверху приложением (высота окна), чужое расширение не может занять экран. В режиме `panel` ничего не меняется. Проверка: юнит `frame-bridge` (рост, возврат, потолок), e2e в рамке ответа с открытым меню у нижнего края карточки.
- R5. Подпути набора (по одному на группу компонентов, список в `Решения`) подключаются независимо: расширение, которому нужен `radio`, не получает код `data-table`. Проверка: тест размера сборки отдельных подпутей (R6) и состав бандла по метафайлу.
- R6. Размер зафиксирован проверкой: общее ядро (Vue и ядро Vuetify), любой один подпуть вместе с ядром и все подпути вместе укладываются в потолки из `Decision Log` (gzip, JS и CSS отдельно). Проверка: `pnpm verify:packages` и юнит размера, как у корневого набора.
- R7. Компоненты первой версии (по порядку поставки):
  1. группы `radio` и `checkbox`;
  2. `alert`, `chip`, `progress`, `skeleton`;
  3. `textarea`, `slider`, `switch`, поле даты;
  4. `tabs`, `dialog`, `menu`, `tooltip`;
  5. `table` и `data-table`.

  У каждого: видимое имя, роль и управление с клавиатуры (то, что даёт Vuetify), отсутствие нарушений axe `serious` и `critical`, русский и английский вариант строк. Проверка: юнит монтирования (роль, значение, событие) и e2e-панель на каждую группу.
- R8. ~~Корневой экспорт и его проверки не меняются~~ — аннулировано решением владельца: ванильный набор, его `readme.test.ts` и `size.test.ts` удалены, корневого экспорта нет (`Decision Log`). Остаётся проверка, что у пакета нет корневого экспорта и `exports` перечисляет только подпути (`tools/lib/package-manifest.test.mjs`).
- R9. README пакета описывает подпути, потолки размера и ограничения оверлеев на английском; примеры в README исполняются тестом (как `readme.test.ts`). Проверка: тест README.

## Решения

**Vue и Vuetify в бандле расширения, а не общие.** Рамка живёт на непрозрачном origin, CSP разрешает скрипты только своего расширения; общего модуля с приложением нет. Альтернативы и последствия — `docs/adr/0021-vue-and-vuetify-in-extension-bundles.md`.

**Подпути вместо одного входа.** Предложение: `@dolphy-app/extension-ui/vuetify` (ядро: создание приложения Vue, тема, локаль), `…/vuetify/choice` (radio, checkbox), `…/vuetify/feedback` (alert, chip, progress, skeleton), `…/vuetify/fields` (textarea, slider, switch, поле даты), `…/vuetify/navigation` (tabs, dialog, menu, tooltip), `…/vuetify/table`. Поле `exports` пакета; `sideEffects` перечисляет файлы с побочными эффектами (стили, регистрация). Группировка следует R7 и общим зависимостям: замер показал, что `VDialog`, `VMenu`, `VTooltip` добавляют около 3 КиБ к набору, где уже есть поля и вкладки (`VOverlay` общий).

**Форма API.** Как у ванильного набора, но с жизненным циклом: `mountCheckboxGroup(container, props)` возвращает `{ update(props), destroy() }`. Каждый вызов создаёт маленькое приложение Vue с общим экземпляром Vuetify рамки; `update` меняет реактивные свойства, не пересоздавая дерево.

**Тема и язык.** Vuetify при установке вставляет собственную таблицу `.v-theme--light` / `--dark` с цветами по умолчанию. Рамка отдаёт переменные приложения встроенным стилем на `<html>`, а класс темы на корне компонента объявляет их заново для своего поддерева: [ВЫВОД ИЗ КАСКАДА, НЕ ИЗМЕРЕНО] цвета приложения будут перекрыты. Решение: тема Vuetify строится из значений `--v-theme-*` рамки при монтировании и пересобирается при их смене (`MutationObserver` на стиль `<html>`); тот же приём — для `lang` и локали Vuetify. Первый шаг стадии 2 — измерить перекрытие на настоящей рамке.

**Сборка CSS зависимостей.** `assets-plugin.ts` падает на любом `import './x.css'` независимо от того, кто импортирует. Правка: для импортов из `node_modules` собирать CSS в строку и добавлять в рамку одним `<style>` при первом монтировании; для кода автора правило прежнее. Изменение ограничено этим плагином и одним тестом.

**Оверлеи.** Новое сообщение рамки `overlay` `{ height }` (или `null` при закрытии); `frame-bridge` ограничивает высоту потолком из высоты окна и применяет её вместо `size`, пока оверлей открыт. Срабатывает по событиям из подпутей `navigation` (диалог, меню, подсказка), а не по наблюдению за DOM. Затрагивает `frame-runtime.js`, `frame-bridge.ts`, `IsolatedFrame.vue`, `PanelFrame.vue` (панель не использует) и тест `frame-runtime.test.ts`.

**Пересечения с параллельными ветками.** Файлы, которые меняют и другие активные спеки: `extension-api-breadth-2` (стадия 4c.3: README и `docs/adr` пакета `extension-ui`, `tools/verify-packages.mjs`), `extension-tools` (почти все активные спеки), `frame-runtime.js`. Порядок: стадии 1–3 не трогают `extension-ui` и идут отдельными коммитами с минимальными диффами; стадии 4–5 стартуют после слияния `extension-api-breadth-2`. Номер ADR `0017` оказался занят двумя другими файлами: ADR переименован в `0021`.

## Surprises & Discoveries

- 2026-10-05. Vuetify импортирует CSS по компонентам: `vuetify/lib/components/VBtn/VBtn.js` содержит `import "./VBtn.css"`. Плагин `extension-tools/src/assets-plugin.ts` (строки 66–74) отвечает ошибкой на любой такой импорт: без правки сборщика расширение с Vuetify не собирается.
- 2026-10-05. Размер с tree-shaking (esbuild, `minify`, Vue в режиме production, только Composition API, один экземпляр на расширение): `VBtn` один — JS 126 КиБ (48 КиБ gzip) и CSS 27 КиБ (4 КиБ gzip); `VBtn`, `VRadioGroup`, `VRadio`, `VCheckbox`, `VAlert`, `VChip` — 182 КиБ (65 gzip) и 56 КиБ (8 gzip); те же плюс `VProgressLinear`, `VSkeletonLoader`, `VTextarea`, `VSlider`, `VSwitch`, `VTabs`, `VTab`, `VTable`, `VDataTable` — 428 КиБ (148 gzip) и 149 КиБ (20 gzip); плюс `VDialog`, `VMenu`, `VTooltip` — 431 КиБ (149 gzip) и 153 КиБ (21 gzip). Корневой ванильный набор — до 10 КиБ gzip целиком.
- 2026-10-05. Высота рамки режимов `answer`, `markdown` и `widget` равна высоте содержимого (`apps/desktop/electron/main/shells/frame-runtime.js`, отправка `size` по `ResizeObserver`; `IsolatedFrame.vue` держит `max(reported, 40)` px). Оверлей Vuetify рисуется внутри того же iframe и обрезается его границей; без протокола из R4 диалог и меню в рамке ответа непригодны. Режим `panel` заполняет рамку.
- 2026-10-05. Ограничений размера на скрипты расширения в загрузчике не найдено: потолки есть у ресурсов (`css`, изображения, `woff2`), у скриптов нет (`extension-assets.ts`).
- 2026-10-05. Решение `extension-api-breadth-2` «ванильный TS без зависимостей, пакет ≤ 10 КиБ gzip» (R16 и раздел `Решения` той спеки) верно для корневого экспорта; для подпутей эта фича его не отменяет, а дополняет (ADR 0021). Позже владелец удалил и сам корневой экспорт (`Decision Log`): решение той спеки утратило предмет.

- 2026-10-05. Стили темы Vuetify (`.v-theme--*`, `.bg-*`, `.text-*`) Vuetify пишет в `<head>` документа, а вид ответа живёт в теневом корне и их не видит: таблицу темы копируют внутрь корня при монтировании и обновляют при смене темы (`packages/extension-ui/src/vuetify/root.ts`).
- 2026-10-05. Явный `disabled: false` у дочернего компонента перекрывает `disabled` группы: элемент `VRadio` получает `disabled` только как `true` или `undefined` (`choice.ts`).
- 2026-10-05. Протокол `dolphy-overlay`: компонент навигации шлёт DOM-событие `dolphy-overlay` (`detail.height`: число или `null`), `frame-runtime.js` пересылает его сообщением `overlay`, `frame-bridge` ограничивает высоту окном; из нескольких открытых оверлеев берётся наибольшая высота; режим `panel` событие игнорирует.
- 2026-10-05. Сборка браузерных бандлов без `process.env.NODE_ENV` и флагов Vue тянет в расширение режим разработки Vue: сборщик задаёт `process.env.NODE_ENV=production` и флаги Vue и минифицирует CSS (`bundle.ts`).
- 2026-10-05. Тест расширения с Vuetify под Vitest падает на `.css` из модулей (`Unknown file extension`): нужен `server.deps.inline: ['vuetify']` в `vitest.config.ts` (рецепт и README это показывают).
- 2026-10-05. Замер реального бандла: `view.mjs` у `ext-choice` без минификации — около 549 КБ, 118 КБ gzip (Vue, ядро Vuetify, radio и checkbox, весь `main.css`).

## Decision Log

- 2026-10-05. Подход: настоящие Vue и Vuetify в бандле расширения, не ванильные копии стилей. Причина: полное совпадение вида и поведения с приложением, цена — размер расширения (замеры выше).
- 2026-10-05. Состав первой версии: radio и checkbox (группы), alert, chip, progress, skeleton, tabs, dialog, menu, tooltip, textarea, slider, switch, поле даты, table и data-table. Причина: выбор владельца репозитория.
- 2026-10-05. Лимит 10 КиБ gzip остаётся у корневого экспорта; для подпутей вводятся отдельные потолки, разбивка на подпути. Причина: выбор владельца; единый потолок невозможен при ядре в 48 КиБ gzip. Числа потолков — предложение, фиксируются в стадии 5 по реальной сборке: ядро ≤ 60 КиБ gzip, один подпуть вместе с ядром ≤ 90 КиБ gzip, все подпути вместе ≤ 170 КиБ gzip, CSS отдельно ≤ 25 КиБ gzip.
- 2026-10-05. Оверлеи в `answer`, `markdown` и `widget` поддерживаются расширением рамки по протоколу, а не запретом. Причина: выбор владельца; цена — правка протокола рамки и пересечение с параллельной работой.
- 2026-10-05. Сначала только спека и ADR, код после согласования. Причина: выбор владельца; активные ветки (`extension-api-breadth-1`, `-2`, `extension-authoring`, `extension-distribution-ux`) правят те же пакеты.

- 2026-10-05. Ванильный набор (`button`, `textField`, `select`, `toggle`, `list`, `card`, `emptyState`), корневой экспорт, `readme.test.ts` и `size.test.ts` старого набора удалены без обратной совместимости по просьбе владельца. Это отменяет R8 и решение спеки и ADR «корневой экспорт остаётся»; у пакета остались только подпути `…/vuetify/*`. Причина: два UI-набора с одним назначением не нужны.
- 2026-10-05. `ext-choice` (radio и checkbox) и `ext-sql` (textarea) переведены на кит. `ext-js` остаётся на собственном редакторе кода: он прозрачная textarea поверх слоя подсветки, такого компонента в Vuetify нет. `ext-math` интерфейса не имеет.
- 2026-10-05. Типы `VSwitch`, `VRadioGroup`, `VDataTable` не сходятся с `exactOptionalPropertyTypes` пакета: их передают в `h()` как `Component` (приведение типа), остальное проверяется по свойствам кита.
- 2026-10-05. Плагин CSS зависимостей влит в `assets-plugin.ts`: два плагина Vite, оба разрешающие импорты через `this.resolve`, не складываются (второй не видит результата первого), поэтому один плагин отличает CSS автора (ошибка с `?inline`) от CSS зависимостей (в реестр); см. `dependency-styles.ts`. Идентификатор виртуального модуля кодируется (base64url): id с суффиксом `.css` Vite принимает за таблицу стилей.
- 2026-10-05. Для браузерных бандлов сборщик определяет `process.env.NODE_ENV=production` и флаги Vue и минифицирует CSS (`cssMinify`).
- 2026-10-05. ADR `0017-vue-and-vuetify-in-extension-bundles.md` совпал номером с двумя другими `0017`: переименован в `0021-…`, статус `accepted`, текст исправлен под удаление корневого экспорта.
- 2026-10-05. Потолки размера (gzip, минификация, JS / CSS, КиБ) заданы по замеру `verify:packages` с запасом ~10% и по вариантам, а не единым классом «один подпуть»: ядро 44,6 / 26,7; `choice` 57,6 / 28,6; `feedback` 69,6 / 34,6; `fields` 102,0 / 39,0; `navigation` 92,8 / 36,3; `table` 137,9 / 40,9; все подпути вместе 167,5 / 49,1. Предложенные в начале числа не сошлись: CSS Vuetify (`main.css`, утилиты и сброс) весит ~27 КиБ gzip уже в ядре, а `VDataTable` и поле даты тянут `@vuetify/v0`.
- 2026-10-05. e2e в Electron нашёл и закрыл: `process` в рамке (`@vuetify/v0` читает `process.env.VITE_LOGGER_ENABLED` при загрузке — добавлено в `BROWSER_DEFINE`), markdown-рамки игнорировали `overlay`, диалог измерялся по сжатой рамкой высоте, общие id `input-v-1` у двух приложений Vue на одной странице (теперь уникальный `idPrefix`), имена диалога и подсказки для axe, роли меню, `VDateInput` с `aria-expanded` на `div`; контраст `on-success`, `on-info` (светлая тема) и `on-error`, `on-success`, `on-info` (тёмная) во встроенных темах приложения не проходил 4,5:1 для заливок компонентов — цвета текста на них заменены на тёмные (`builtin-themes.ts`).

## Outcomes

Сделано: подпути `@dolphy-app/extension-ui/vuetify/{choice,feedback,fields,navigation,table}` и ядро `…/vuetify` (Vue и Vuetify в бандле расширения, тема из переменных рамки, язык из `<html lang>`); CSS зависимостей собирается в реестр и попадает в рамку и теневые корни видов; протокол `dolphy-overlay` → `overlay` для рамок `answer`, `markdown`, `widget` с потолком высоты окна; `ext-choice` и `ext-sql` переведены на кит; потолки размера и изоляция подпутей проверяются в `verify:packages`; e2e в Electron (обе темы с axe, ru/en, оверлеи).

Отличия от плана:
- Ванильный корневой набор удалён без обратной совместимости по просьбе владельца, R8 снято.
- `ext-js` остаётся на собственном редакторе кода (подсветка поверх прозрачной `textarea`), `ext-math` без UI.
- Потолки размера заданы по замеру отдельно для каждого варианта, а не единым классом (числа — в Decision Log).
- Контраст текста на заливках `success`/`info`/`error` во встроенных темах приложения исправлен по результатам axe.

Долговечное перенесено в `docs/design/extensions.md` (раздел «UI-кит»), README пакета `extension-ui`, рецепт `recipe-ui-kit.md` и ADR 0021.
