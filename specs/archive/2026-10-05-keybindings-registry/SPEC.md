# Реестр сочетаний клавиш

> Исторический документ. Не источник требований.

Живой документ, пока `status` — `draft` или `active`: `Progress`, `Surprises & Discoveries`, `Decision Log` обновляются вместе с кодом. По завершении фичи переносится в `specs/archive/` и не меняется. Правила — скилл `spec-workflow`.

Исследование: `docs/research/keybindings.md` (TanStack Hotkeys, VS Code, Theia, Joplin). Расширяет ADR 0012 («реестр команд окна»): снимает его пункт «сочетания — только у команд приложения, задаются в коде».

## Цель

Сочетания клавиш — данные, а не код: каждая команда окна (приложения и расширений) имеет набор привязок `клавиши + when`, который пользователь меняет в «Настройки → Сочетания клавиш», а расширения дополняют своими привязками к своим командам. Привязки хранятся в `engine.db`, одинаково работают на macOS, Windows и Linux и на разных раскладках, пересечения находятся и показываются до сохранения, а `when` даёт одному сочетанию разное поведение в разных условиях.

## Не цели

- Глобальные (общесистемные) сочетания и меню Electron с акселераторами — окно не имеет меню (ADR 0008), второй канал команд не нужен.
- Файл `keybindings.json` для правки руками, экспорт и импорт наборов, синхронизация между устройствами: источник правды — `engine.db`.
- Привязка расширением **команд приложения** и чужих команд: расширение привязывает только собственные команды (ADR 0012, «расширения не вызывают команды приложения»).
- Аргументы команды в привязке (`args`) и команда `runCommands`.
- Операции `when` сверх `!`, `&&`, `||`, `==`, `!=`, скобок (нет `<`, `>`, `=~`, `in`); контекстные ключи, которые ставит расширение (`setContext`).
- Определение раскладки через `navigator.keyboard.getLayoutMap()`: сопоставление идёт по событию (`key` с запасом по `code`).
- Клавиши, передаваемые из рамок расширений: рамка по-прежнему пересылает родителю только Ctrl/⌘+K (ADR 0008, 0012).
- Цифровая клавиатура как отдельные клавиши (доступна через физическую запись `[Numpad1]`).

## Требования

Наблюдаемое поведение. Проверки — тесты пакета `@dolphy-app/keybindings` (`pnpm -F @dolphy-app/keybindings test`), сервисов и адаптеров движка, окна (`pnpm -F @dolphy/desktop test`) и e2e `apps/desktop/e2e/keybindings.e2e.test.ts`, если не указано иное.

### Запись, платформы, раскладки

- R1. Запись сочетания: модификаторы `Mod`, `Ctrl`/`Control`, `Alt`/`Option`, `Shift`, `Meta`/`Cmd`/`Command`/`Win`/`Super` (любой регистр, любой порядок), затем клавиша: буква, цифра, знак (`,` `.` `/` `[` …), `F1`–`F24`, `Enter`, `Escape`, `Tab`, `Space`, `Backspace`, `Delete`, `Insert`, `Home`, `End`, `PageUp`, `PageDown`, `Arrow*`; физическая клавиша `[KeyK]`, `[Digit1]`, `[Numpad1]`. Цепочка — до двух сочетаний через пробел (`Mod+K Mod+S`). Повтор модификатора, неизвестное имя, пустая часть, больше двух сочетаний, одиночный модификатор без клавиши — ошибка с кодом причины. Проверка: таблица допустимых и недопустимых записей.
- R2. `Mod` — ⌘ на macOS и Ctrl на остальных платформах, строго: на macOS Ctrl+K не совпадает с `Mod+K`, на Windows и Linux ⌘/Win+K не совпадает. Подписи: macOS — `⌘⇧L`, `⌥` для Alt/Option; Windows и Linux — `Ctrl+Shift+L`; `Meta` — `Win` на Windows, `Super` на Linux, `⌘` на macOS. Озвучивание словами (скринридер) сохраняется. Проверка: таблица по трём платформам.
- R3. Сопоставление события: буква ASCII в `event.key` окончательна (Dvorak, Colemak, AZERTY работают по символу); если `event.key` не ASCII-буква — запасной путь по `event.code` (русская раскладка: `к` на `KeyK` совпадает с `Mod+K`; AZERTY: `Mod+1` совпадает с `Digit1`; macOS Option+буква и мёртвые клавиши — по `code`); физическая запись сравнивается только по `code`; AltGr (`getModifierState('AltGraph')`) не считается Ctrl+Alt; события во время IME-ввода (`isComposing`) не совпадают; неявный `Shift` допустим для печатного знака, если `Shift` в записи не задан. Проверка: синтетические события для раскладок US, RU, DE, AZERTY, Dvorak.
- R4. Запись для хранения нормализуется: основной модификатор платформы записывается как `Mod`, остальные в порядке `Ctrl+Alt+Shift+Meta`, клавиша в каноническом виде (`Mod+K`, `Mod+Shift+ArrowUp`, `[KeyK]`); запись события клавиатуры в сочетание (для рекордера) и обратное разбор→запись дают эквивалентный результат. Проверка: round-trip.
- R5. Сочетание без `Ctrl`/`Alt`/`Meta`, дающее печатный символ (`K`, `Shift+K`, `,`), допустимо только с `when`, который ложен, пока фокус в поле ввода (`inputFocus`); иначе привязка отклоняется (она ломала бы набор текста). Проверка: таблица записей с `when` и без.

### Условия (`when`)

- R6. Выражение `when`: ключ (истинность), `!ключ`, `ключ == значение`, `ключ != значение`, `&&`, `||`, скобки; значение — строка в одинарных кавычках или слово. Приоритеты как в VS Code: `!` сильнее `&&`, `&&` сильнее `||`. Неизвестный ключ — ложь; пустой `when` — всегда истина; длина ≤ 256 символов. Ошибка синтаксиса возвращает позицию. Проверка: таблица выражений и контекстов.
- R7. Пересечение условий: две записи пересекаются, только если существует контекст, в котором истинны обе (`a && !a` не пересекается ни с чем; `page == 'courses'` не пересекается с `page == 'graph'` и с `!page`; `inputFocus` не пересекается с `!inputFocus`). Проверка: таблица пар, включая выражения с `||` и скобками.
- R8. Контекстные ключи окна: `platform` (`mac`, `windows`, `linux`), `isMac`, `isWindows`, `isLinux`, `inputFocus` (фокус в поле ввода или редактируемом элементе), `modalOpen` (открыт диалог или меню), `paletteOpen`, `page` (раздел: `dailyPlan`, `courses`, `graph`, `settings`, `session`, `extension`), `inSession` (идёт сессия обучения). Значения читаются в момент нажатия. Проверка: тест диспетчера и e2e.

### Источники, приоритет, замена

- R9. Источники привязок команды: `default` (в коде приложения), `extension` (вклад расширения), `user` (хранилище). Приоритет при совпадении клавиш и условий: `user` > `default` > `extension`; внутри источника побеждает более поздняя запись. Выполняется одна команда. Проверка: тест `Keymap.resolve`.
- R10. Набор `user` команды **заменяет** все привязки `default` и `extension` этой команды: пустой набор — привязок нет; сброс — запись удалена, действуют `default` и `extension`. Записи команды, которой сейчас нет (расширение удалено), хранятся и не действуют, возвращаются вместе с командой. Проверка: тест сборки карты.
- R11. Цепочки: после первого сочетания окно ждёт второе 1,5 секунды; `Escape` и истечение срока сбрасывают ожидание; клавиша, не продолжающая цепочку, сбрасывает ожидание и не выполняет команду; сообщение «ждём вторую клавишу» озвучивается скринридеру (`aria-live`) и показывается в окне. Если запись высшего приоритета — одиночное сочетание, цепочка с тем же началом недостижима (и это показано как конфликт, R12). Проверка: тесты диспетчера с поддельным таймером.

### Пересечения

- R12. Реестр находит пересечения привязок разных команд. Виды: `same` (совпадают клавиши и условия пересекаются) и `prefix` (клавиши одной — начало цепочки другой и условия пересекаются). Для каждого пересечения известен победитель по R9. Привязки одной команды между собой не конфликтуют. Проверка: таблица наборов привязок.
- R13. При сохранении пользовательских привязок движок отклоняет набор, в котором две **пользовательские** привязки разных команд пересекаются по R12 (с учётом платформы хоста при разборе `Mod`), а также нарушают R1, R5, R6 или лимиты (≤ 8 привязок на команду, ≤ 512 команд, ключ команды ≤ 200 символов, повтор `клавиши + when` в одной команде). Ответ — `INVALID_ARGUMENT` с `details.field`, `details.reason` (`syntax`, `typing`, `conflict`, `limit`, `duplicate`) и при `conflict` — ключи обеих команд. Пересечения пользовательских привязок с привязками `default` и `extension` не отклоняются: решает приоритет, окно показывает предупреждение. Проверка: тесты сервиса `settings`.

### Хранение и контракт

- R14. Привязки пользователя хранятся в `engine.db` (`setting`, ключ `keybindings`) и переживают перезапуск; в контракте `@dolphy-app/engine-contract` версии 20: `KeybindingsSettingsDto`, `KeybindingEntryDto`, `KeybindingsPatch`, методы `settings.getKeybindings()` и `settings.setKeybindings(patch)` (патч: ключ команды → набор или `null` для сброса; применяется целиком или не применяется), событие `settings-changed` со `scope: 'keybindings'`. Адаптеры хранилища — SQLite, JSON-файл и память — проходят общий набор `describeSettingsStoreContract`. Проверка: тесты адаптеров, RPC (`engine-rpc` integration), перезапуск в e2e.
- R15. Повреждённая запись в хранилище не ломает окно: при чтении отбрасываются записи неверной формы, остальные действуют; записи, которые не разбираются на платформе окна (например `Mod+Ctrl+K` на Windows), пропускает карта привязок и сообщает в `issues`. Проверка: тест декодера и адаптера.

### Расширения

- R16. В манифесте у команды: `keybinding` (запись, как раньше — теперь действующая привязка) и `keybindings` — до 4 записей `{ key, mac?, windows?, linux?, when? }`; `mac`/`windows`/`linux` заменяют `key` на своей платформе. Ссылаться на другую команду нельзя (структурно). Привязка команды с `palette: false` — ошибка манифеста. Запись, нарушающая R1, R5 или R6, — ошибка манифеста (как другие поля). Проверка: тесты точки `commands` в `extension-host`, `extension.schema.json`.
- R17. Привязки расширения действуют, пока расширение включено и загружено, и меняются вместе с ним без перезагрузки окна (включение, отключение, обновление, удаление). Нажатие запускает команду тем же исполнителем, что и палитра. Привязки расширений видны в «Сочетания клавиш» с источником «расширение» и пересечениями. Проверка: тест адаптера реестра, e2e с фикстурой `commands-extension`.

### Окно

- R18. Диспетчер — один обработчик `keydown` на `document` в фазе перехвата: берёт события только из окна (не из рамок), игнорирует повтор клавиши и IME, выполняет по `Keymap.resolve` команду, если она доступна (`enabled`); `preventDefault` — только для обработанного сочетания и для ожидания второй клавиши. Палитра — обычная команда `app:palette.open` с привязкой `Mod+K` без `when` (срабатывает и в полях ввода); особого случая в диспетчере нет. Проверка: тесты диспетчера.
- R19. Умолчания команд приложения повторяют прежнее поведение: `Mod+K` (палитра, без `when`), `Mod+1`, `Mod+2`, `Mod+3`, `Mod+,` с `when` `!inputFocus && !modalOpen` (не в поле ввода, не при открытом диалоге или меню). Проверка: тест `app-commands`, e2e `command-registry`.
- R20. «Настройки → Сочетания клавиш» показывает все команды (приложения и расширений) таблицей: команда, привязки (подпись и озвучивание), условие, источник, признак пересечения. Есть поиск по названию, категории, клавишам и ключу команды, фильтр «только с пересечениями» и «изменённые». Проверка: тест модели, e2e.
- R21. Привязку можно изменить с клавиатуры: действие «Изменить» открывает диалог записи (нажатые клавиши превращаются в сочетание; цепочка из двух; `Escape` — отмена, `Backspace`/`Delete` — очистка записи), поле `when` с проверкой синтаксиса и подсказкой ключей, **список пересечений до сохранения**; при пересечении кнопки «Переназначить» (у других команд эта привязка снимается в том же патче) и «Отмена». Можно добавить вторую привязку, снять привязку, сбросить команду, сбросить всё (с подтверждением). Диалог и таблица доступны с клавиатуры и скринридеру, строки на `ru` и `en`. Проверка: тест модели, e2e с проверкой доступности страницы (структурной: имена, подписи, управление с клавиатуры).
- R22. Палитра команд показывает у команды действующую привязку наивысшего приоритета (с учётом платформы и пользовательских изменений), а не значение из описания команды. Проверка: тест палитры.
- R23. Пересечение привязки расширения с привязкой приложения или другого расширения не мешает загрузке расширения: действует приоритет R9, в таблице — предупреждение. Проверка: тест сборки карты, e2e.

### Документы

- R24. Документация описывает формат записи, `when`, контекстные ключи, правила приоритета и замены, вклад расширения и ограничения: `apps/desktop/README.md` (раздел «Command registry»), `docs/design/extensions.md` («Команды»; примеры проходят `docs-contributions.test.ts`), `packages/README.md`, README пакета `@dolphy-app/keybindings`; решение зафиксировано ADR 0016. ## Решения

**Пакет `@dolphy-app/keybindings`** (`packages/keybindings`, без зависимостей, без DOM: события описываются структурным типом `KeyEventLike`). Его используют движок (проверка при сохранении), `extension-host` (проверка манифеста) и окно (сопоставление, рекордер, подписи). Модули: `platform` (`Platform = 'mac' | 'windows' | 'linux'`, `detectPlatform`), `keystroke` (`parseChord`, `tryParseChord`, `chordToText`, `formatChord`, `spokenChord`, `eventToKeystroke`, `matchKeystroke`, `KeybindingSyntaxError` с `reason`), `when` (`parseWhen`, `evaluateWhen`, `whenOverlaps`, `whenToText`), `keymap` (`buildKeymap`, `Keymap.resolve`, `Keymap.forCommand`, `findConflicts`, `findCandidateConflicts`), `user` (`decodeUserKeybindings`, `validateUserKeybindings`, лимиты), `validate` (`validateBinding`: R1, R5, R6). API — чистые функции и неизменяемые данные.

**Своя реализация вместо TanStack Hotkeys.** Берём идеи (`Mod`, физическая запись, алгоритм сопоставления, рекордер); зависимость не подходит: регистрация привязана к колбэку и DOM, нет `when`, источников, хранения, пакет в alpha (подробности — `docs/research/keybindings.md`).

**Замена набора команды вместо записей «удалить» (`-command`).** Пользовательский набор команды вытесняет умолчания этой команды целиком. Нет перекрёстной сверки с умолчаниями по ключу и `when`; интерфейс «изменить, добавить, снять, сбросить» ложится на одну операцию «записать набор». Цена: после обновления приложения у команды с пользовательским набором не появятся новые умолчания; сброс команды возвращает актуальные.

**Приоритет `user > default > extension`.** В VS Code расширение весит больше ядра; у нас сторонний код не должен перехватывать клавиши приложения. Расширение выигрывает только у другого расширения (порядок по `extensionId`, затем по порядку вклада) и в свободных сочетаниях.

**`Mod` строго по платформе.** Прежний `matchesKeybinding` считал `Mod` «Ctrl или ⌘» на любой платформе; это мешало бы отдельным привязкам `Ctrl+K` и `Mod+K` на macOS и совпадало бы с Ctrl+K при подписи ⌘K. Платформа: `navigator.platform` в окне, `process.platform` (внедряется) в движке.

**Пересечение `when` через DNF.** Выражение приводится к дизъюнкции конъюнкций литералов; два выражения пересекаются, если найдётся пара конъюнкций без противоречия по ключам (истинность, равенство, неравенство). Предел 64 конъюнкций; сверх предела выражения считаются пересекающимися (предупреждаем лишний раз, а не молчим).

**Контекстные ключи в окне** — `shared/lib/context-keys.ts`: реактивные значения (`page`, `inSession`, `paletteOpen`) и вычисляемые в момент нажатия (`inputFocus`, `modalOpen`, `platform`). Прежние правила диспетчера «не в поле ввода, не при открытом диалоге» становятся обычным `when` умолчаний.

**Контракт.** `KeybindingEntryDto { key: string; when: string | null }`, `KeybindingsSettingsDto { commands: Record<string, KeybindingEntryDto[]> }`, `KeybindingsPatch = Record<string, KeybindingEntryDto[] | null>`; в `CommandContributionDto` — `keybindings: ExtensionKeybindingDto[]` (`{ key, mac, windows, linux, when }`, поля `null` если не заданы), `keybinding` остаётся строкой-сокращением. `CONTRACT_VERSION` 19 → 20. Каталог расширений не меняется: новых ключей `contributes` нет, привязки лежат внутри `commands` (индексы остаются совместимыми; старое приложение отвергнет манифест с `keybindings` как с неизвестным ключом, как при прежних дополнениях, ADR 0013).

**Окно.** `features/keybindings` — хранилище пользовательских привязок над `engine.settings` (по образцу `theme-selection`: событие `settings-changed` → перечитать, свои записи не перечитываются) и карта привязок, собранная из реестра команд (`CommandDescriptor.keybindings` — умолчания), вкладов расширений (через адаптер реестра) и пользователя. Описание команды получает `keybindings?: DefaultBinding[]` вместо одной строки; `Command` отдаёт умолчания, а действующую привязку читают у карты. `shared/lib/keybinding.ts` удаляется (чистая замена, вызовы переведены на пакет).

**Границы безопасности.** Вклад расширения привязывает только команду, в которой он объявлен; хост проверяет привязку так же, как пользовательскую (R5), палитра и диспетчер выполняют команду расширения тем же исполнителем, что и раньше; из рамки по-прежнему приходит только Ctrl/⌘+K. Известное ограничение: при смене привязки палитры внутри рамки расширения по-прежнему работает Ctrl/⌘+K (рамка не знает привязки).

## Surprises & Discoveries

- 2026-10-05. `matchesKeybinding` в окне считает `Mod` как «Ctrl или ⌘» на любой платформе (`apps/desktop/src/shared/lib/keybinding.ts`): Ctrl+K открывает палитру и на macOS.
- 2026-10-05. В окне нет `axe-core` (не в репозитории и не в lock-файле), поэтому проверка доступности в e2e — структурная (имена кнопок, подписи таблиц и диалога, уникальные id, управление с клавиатуры), а не прогон axe. Добавление `axe-core` — отдельная задача.
- 2026-10-05. Прежний селектор открытого диалога `[role="dialog"][aria-modal="true"]` совпадал и с закрывающимся диалогом Vuetify, ещё лежащим в DOM: сочетания не работали около 200 мс после закрытия. Селектор ограничен элементами без оверлея.
- 2026-10-05. `origin/develop` ушёл вперёд за время исследования (версия контракта стала 18); ветка перенесена на актуальный `develop` до начала работы.

## Decision Log

- 2026-10-05. Пользовательский набор команды заменяет умолчания целиком, записей «удалить» нет. Причина: нет сверки с умолчаниями по `when`; интерфейс — одна операция.
- 2026-10-05. Приоритет `user > default > extension`. Причина: сторонний код не должен перехватывать клавиши приложения (ADR 0012).
- 2026-10-05. Привязки расширения лежат внутри `commands`, а не в новой точке вклада. Причина: структурно привязывают только свои команды; каталог и `ExtensionContributesDto` не меняются.
- 2026-10-05. Конфликты пользователь–пользователь отклоняет движок, остальные показывает окно. Причина: движок не знает умолчаний приложения, но обязан защитить свои данные.
- 2026-10-05. `Mod` строго по платформе. Причина: см. «Решения».
- 2026-10-05. Свой пакет вместо `@tanstack/hotkeys`. Причина: см. «Решения» и исследование.

## Outcomes

Сделано всё по требованиям R1–R24: пакет `@dolphy-app/keybindings` (201 тест), контракт 20 с `settings.getKeybindings/setKeybindings`, проверка и хранение в `engine.db` (memory, json и sqlite проходят общий набор), привязки команд расширений (`keybinding`, `keybindings`) с проверкой на трёх платформах, окно с одним диспетчером, контекстными ключами, цепочками, страницей «Сочетания клавиш» (рекордер, `when`, пересечения, «Переназначить», сброс), палитра показывает действующую привязку. Проверено: `pnpm lint`, `pnpm typecheck`, `pnpm test` (6030 тестов; 4 теста симуляции, графа и `engine-git` падают по таймауту при общей нагрузке и проходят по отдельности), e2e `keybindings` и `command-registry` в настоящем Electron (22 теста).

Отличия от плана: проверка доступности в e2e структурная, без `axe-core` (его нет в репозитории); `platform` движка — поле `EngineDeps`, а не контракта; `ChordStatus.vue` лежит в `app/layouts`; Save блокируется, пока на ту же клавишу есть пользовательская привязка другой команды (движок бы отклонил), «Переназначить» остаётся доступным.

Осталось: фактическая публикация `@dolphy-app/keybindings` в npmjs — её делает `release.yml` при релизе (токен `NPM_TOKEN` есть только в CI; на рабочей машине `npm whoami` без авторизации); `axe-core` в e2e — отдельная задача.
