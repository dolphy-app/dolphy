# Метаданные каталога: названия вкладов и теги

Живой документ, пока `status` — `draft` или `active`: `Progress`, `Surprises & Discoveries`, `Decision Log` обновляются вместе с кодом. По завершении фичи переносится в `specs/archive/` и не меняется. Правила — скилл `spec-workflow`.

## Цель

В каталоге и в списке установленных расширений вклад показан человеческим названием («Темы: Полночь»), а не техническим идентификатором (`dolphy.theme-midnight`). У расширения есть теги из закрытого словаря, каталог фильтруется быстрыми группами («Обучение», «Оформление и интерфейс», «Для разработчиков») и по тегам. Выпущенные приложения продолжают видеть каталог.

## Не цели

- Названия видов заданий (у них нет `title` в манифесте; новое поле — отдельная задача): виды заданий и языки рендереров остаются идентификаторами.
- Проверка названий при установке: названия — отображаемые данные, как `name` и `description`, и не входят в `manifestMismatch`.
- Теги от пользователей, свои теги, переименование словаря «на лету».
- Рейтинги, счётчики установок, скриншоты.
- Изменения репозитория каталога `dolphy-extensions` (тег-разметка тем и подъём версии инструментов — отдельный PR после релиза).

## Требования

Наблюдаемое поведение. Проверки — юнит-тесты пакетов, замороженный разбор выпущенной схемы, e2e `apps/desktop/e2e`, `docs-contributions.test.ts`.

- R1. Названия. Запись расширения в `index.v2.json` необязательно содержит `titles` — карту «точка вклада → {id → название}» для `themes`, `gradePolicies`, `settings`, `commands`, `panels` (названия — `label`/`title` из манифеста новейшей версии, 1–60 символов; ключи — существующие id вкладов). `catalog build` заполняет её сам, пустые точки и весь ключ при отсутствии названий опускает; пересборка без повышения версии обновляет названия. Строгий разбор отвергает названия для id, которых нет в `contributes`; терпимый разбор в приложении молча отбрасывает непонятную карту, не пропуская запись.
- R2. Совместимость. В `index.json` (формат для выпущенных приложений) `titles` никогда не попадает: `legacySubset` его вырезает, запись остаётся видимой. Проверка: замороженный разбор выпущенной схемы (`released-schema-v1.ts`) принимает выход `catalog build` для расширения с названиями и тегами и показывает его прежние версии.
- R3. Названия в приложении. `ExtensionInfoDto.titles` и `CatalogEntryDto.titles` (`ContributionTitlesDto`, `{}` без названий). Для установленных расширений названия берёт реестр из разобранного манифеста (в том числе у отключённых), для карточек каталога — из записи индекса. Чип вклада показывает название; `id` доступен как подсказка (`title`-атрибут) и скринридеру; виды заданий и языки рендереров показываются идентификатором моноширинно; события показываются локализованным названием (`session.started` → «Начало занятия» и т. д., неизвестное событие — исходное имя). Длинные группы по-прежнему сворачиваются до первых значений. Если у расширения единственный вклад — тема с названием, равным названию расширения, строка вкладов не показывается.
- R4. Теги в манифесте. `extension.json` необязательно содержит `tags` — до 5 уникальных значений из закрытого словаря `learning`, `language`, `content`, `theme`, `interface`, `productivity`, `developer` (`EXTENSION_TAGS` в `@dolphy-app/extension-api`). Неизвестный, повторный или шестой тег — ошибка манифеста (`parseManifest`, `validate`, `catalog check`).
- R5. Теги в индексе. Теги записываются в запись версии `index.v2.json` (как `icon`): версии с тегами не попадают в `index.json`, более старые версии без тегов остаются; установщик сверяет теги манифеста с записью (`manifestMismatch`, без учёта порядка). Терпимый разбор приложения отбрасывает теги, которых нет в его словаре, а не запись или версию.
- R6. Теги в приложении. `ExtensionInfoDto.tags`, `CatalogEntryDto.tags` (теги показанной версии). Эффективные теги в окне: явные теги автора, а если их нет — вычисленные по вкладам (`themes` → `theme`, `interface`; `exerciseTypes`, `gradePolicies`, `events` → `learning`; `markdownRenderers` → `content`; `commands` → `productivity`; `panels` → `interface`; `settings` ничего не добавляет; `language` и `developer` только явные). Явный список заменяет вычисленный, а не дополняет. Теги показаны компактными чипами в карточке каталога, диалоге установки и списке установленных.
- R7. Фильтры каталога. Над существующими чипами видов вклада — три группы: «Обучение» (`learning`, `language`, `content`), «Оформление и интерфейс» (`theme`, `interface`, `productivity`), «Для разработчиков» (`developer`), с числом расширений; пустые группы скрыты. Остальные фильтры (виды вклада и теги) — в сворачиваемом блоке «Ещё фильтры», который раскрыт, пока выбран какой-либо из них. Логика: внутри ряда «или», между рядами и с поиском «и». Чипы — кнопки с `aria-pressed`, счётчики — отдельным текстом и в доступном имени; список объявляет число найденных. Существующие чипы видов вклада сохраняют имя и `data-testid`.
- R8. Контракт и документация. `CONTRACT_VERSION` 12 → 13, новых RPC нет. Примеры в `docs/design/extensions.md` проверяются тестом; расширение `create-dolphy-extension` показывает `tags` в шаблоне манифеста.

## Решения

- **Названия — карта рядом с `contributes`, а не объекты в массивах.** Массивы строк разделяют формат v1 и v2, ими пользуются десятки фикстур и фильтры; объекты сломали бы эту форму. Карта по точкам не требует схемы вклада: id вкладов уникальны внутри вида.
- **Названия не проверяются при установке и живут на уровне записи.** Они берутся из новейшего манифеста, а установка может выбрать запасную более старую версию; сверка дала бы ложные расхождения. После установки пользователь видит названия из настоящего манифеста.
- **Теги на уровне версии, как `icon`.** Ключ `tags` в манифесте новый, а манифест разбирается строго: приложение без поддержки отвергнет такой `extension.json`. Версия с тегами должна исключаться из старого индекса, не скрывая расширение целиком.
- **Запасные теги вычисляются в окне** (чистая таблица `pages/settings/lib/tags.ts`), чтобы 14 уже опубликованных тем получили группы без новой версии. Явные теги заменяют вычисленные.
- **Группы — одна чистая таблица «тег → группа»** с тестом, что каждый тег словаря входит ровно в одну группу.
- **Новой проверки каталога нет:** ошибки тегов уже ловит `CHECK-001` через `parseManifest`.
- **Словарь маленький намеренно:** новый тег в манифесте — тот же риск для приложений без поддержки, что и сам ключ; расширять словарь осторожно.

## Surprises & Discoveries

Разведка до начала работ: `ExtensionContributesDto` и запись индекса содержат только списки id, названия есть лишь в `ContributionsDto` включённых расширений; терпимый разбор по умолчанию пропускает запись целиком при ошибке в голове записи, поэтому для новых необязательных ключей нужен `catch`; `legacySubset` копирует запись целиком и утекла бы любая новая ключевая запись в `index.json`.
