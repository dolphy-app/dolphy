# API расширений, волна 1: настройки, локализация, секреты, статистика, виджеты, уведомления и расписания

Живой документ, пока `status` — `draft` или `active`: `Progress`, `Surprises & Discoveries`, `Decision Log` обновляются вместе с кодом. По завершении фичи переносится в `specs/archive/` и не меняется. Правила — скилл `spec-workflow`.

## Цель

Расширение получает то, без чего нельзя написать «серию дней», трекер привычек или интеграцию с внешним сервисом: богатые настройки, переводимый интерфейс, хранилище секретов, агрегированную статистику обучения, виджеты на экране «План дня», системные уведомления и расписания. Всё видно пользователю: в «Настройки → Расширения», в плане дня, в палитре и в диалоге установки (разрешения `learning.stats` и `notifications`).

## Не цели

- Планировщик и модель памяти (хуки в планировщике), сервисы между расширениями, автообновление — отложены (Decision Log).
- Сетевой доступ через посредника движка: `network` остаётся информационным разрешением, секреты не делают его ограничивающим.
- Локализация строк, которые код расширения возвращает во время работы (`notify`, текст уведомлений), и данных курсов.
- Сырые идентификаторы заданий, ответы и содержимое в статистике; доступ к журналу целиком.
- Фоновая работа при закрытом приложении (трей, автозапуск, воспроизведение пропущенных срабатываний).
- Выражения `when`, пользовательские сочетания клавиш, импорт и экспорт, UI-кит — следующие волны.
- Независимый аудит, песочница ОС, ограничение сети и подпись: уровень безопасности — как у Obsidian (обзор, безопасный режим, диагностика).

## Требования

Наблюдаемое поведение. Проверки — юнит-тесты пакетов, контрактные тесты адаптеров, `apps/desktop/test`, e2e `apps/desktop/e2e/extension-breadth-1.e2e.test.ts`, `docs-contributions.test.ts`.

- R1. Типы настроек. `contributes.settings` принимает `text` (многострочная строка, `maxLength` ≤ 10 000), `color` (`#rrggbb`, значение хранится в нижнем регистре) и `list` (список строк: `maxItems` 1–50, `itemMaxLength` 1–200). Диалог «Настройки» показывает textarea, выбор цвета с полем ввода hex и редактор списка (добавить, удалить, переупорядочить с клавиатуры); неподходящее значение отклоняет движок с `details.reason` (`type`, `format`, `max-items`, `max-length`), `default` проверяется при разборе манифеста. Код получает `string` и `string[]`; `onDidChange` срабатывает как у прежних типов. Проверка: юнит `findSettingValueProblem`, манифеста, `state.ts`, `ExtensionSettingField`, e2e (ввод цвета, правка списка, перезапуск, значение у работающего расширения).
- R2. Структура формы. Необязательные поля настройки `group` (заголовок раздела, 1–60), `order` (целое 0–1000) и `visibleWhen: { setting, equals }`. Форма сортирует по `order` (нет — 0), затем по порядку объявления; разделы идут в порядке первого вхождения, настройки без `group` — первым разделом без заголовка. Поле с `visibleWhen` скрыто, пока значение указанной настройки того же расширения не равно `equals`; скрытое значение сохраняется и доходит до кода. Ссылка на несуществующую, на саму себя, цикл, на `list` и несовпадающий по типу `equals` — ошибка манифеста. Проверка: юнит модели формы и манифеста, e2e (переключатель показывает и прячет поле, скрытое значение читается кодом).
- R3. Названия видов заданий и рендереров. Необязательное `title` (1–60) у записей `exerciseTypes` и `markdownRenderers`; чипы вкладов в списке установленных, каталоге и диалоге установки показывают его, `id` остаётся подсказкой; без `title` — идентификатор моноширинно, как сейчас. `catalog build` кладёт названия в `titles` записи индекса. Расширения из поставки (`dolphy.choice`, `dolphy.sql`, `dolphy.math`) получают названия. Проверка: юнит сборки каталога и `contributionGroups`, e2e (чипы).
- R4. Локализация манифеста. Строка вида `%ключ%` (целиком, ключ `[A-Za-z0-9_.-]{1,64}`) в `name`, `description`, `label`/`title`/`description`/`category` вкладов, `group` и подписях вариантов `enum` подставляется из `locales/<язык>.json` (плоский объект строк; языки `ru`, `en`). Цепочка: текущий язык приложения → `en` → исходный `%ключ%`. Подписи пересчитываются при смене языка без перезагрузки окна: палитра, боковое меню, диалог настроек, плитки тем, чипы, заголовки виджетов. Отсутствующий в `en` ключ показан как есть и даёт структурированное предупреждение `locale.missing-key` (`{ key }`) в строке расширения. Битый файл перевода игнорируется с предупреждением, расширение работает. Проверка: юнит `resolveText` и разбора таблиц, e2e с фикстурой на всех точках: смена языка меняет подписи, ключ без перевода виден сырым.
- R5. Локализация в инструментах. `dolphy-ext validate`, `build` и `catalog check` требуют `locales/en.json`, если в манифесте есть `%ключ%`, и сообщают об ошибке для ключа, которого нет в `en`, о длине результата сверх лимита поля, о недопустимой форме файла и ключе вне манифеста (предупреждение); `catalog build` пишет в индекс (`name`, `description`, `titles`) значения на `en`. Файлы `locales/*.json` ставятся установщиком как обычные файлы версии, но по `dolphy-ext://` не отдаются. Проверка: юнит сборки и проверок каталога, установка фикстуры, протокол отвечает 404.
- R6. Секреты. Код получает `ctx.secrets.get/set/delete` без разрешения. Значение переживает перезапуск приложения, у каждого расширения своё пространство (чужие ключи недоступны и из ограниченного процесса), в `engine.db` лежит только шифртекст, в логах значений нет. Лимиты: ключ ≤ 128 символов, значение ≤ 4 КиБ, ключей ≤ 32 (`StorageQuotaError`). Без системного хранилища ключей (на Linux — режим `basic_text`, до готовности приложения) `set` и `get` существующего ключа бросают `SecretsUnavailableError` (`name: 'SecretsUnavailable'`, `code: 'SECRETS_UNAVAILABLE'`), `get` несуществующего ключа даёт `undefined`, `delete` работает. «Очистить данные» и «Удалить данные расширения» стирают секреты; `dataUsage` показывает их число. Проверка: контрактный тест `ExtensionDataStore.secrets` (память и SQLite), юнит службы и шифра, тест моста main с подменой `safeStorage`, процессный тест ограниченного расширения, e2e с подменённым хранилищем ключей.
- R7. Разрешение `learning.stats`. Новое значение `EXTENSION_PERMISSIONS`; метка («Статистика обучения» / «Learning statistics») показана в диалоге установки, карточке каталога и списке установленных. `ctx.stats` без разрешения бросает `PermissionError('learning.stats')`, в ограниченном процессе тоже. Проверка: юнит рантайма, i18n-тест, e2e диалога.
- R8. Статистика. `ctx.stats.streak({ courseId? })` даёт `{ current, longest }` в днях, `ctx.stats.daily({ from, to, courseId? })` — по записи на каждую дату диапазона (≤ 366 дней) `{ date, attempts, correct, accuracy }` (`accuracy` — `correct / attempts`, `null` без попыток). Дни — по часовому поясу пользователя (локальные сутки), попытка «верна» при оценке ≥ 3, `current` не обрывается, пока сегодня ещё нет попыток (считается серия до вчера), дни без попыток разрывают серию. Идентификаторы заданий, курсов и тексты в ответ не входят; неизвестный курс — нули. Проверка: юнит службы на журнале с границей суток, переходом на летнее время и фильтром курса; e2e через команду фикстуры.
- R9. Виджеты. `contributes.widgets` (`id`, `title`, `slot: 'dailyPlan'`, `minHeight`/`maxHeight` 80–320, `module`, ≤ 3 на расширение) показываются на экране «План дня» отдельным блоком в изолированных рамках с мостом панелей: рамка вызывает только команды своего расширения, высота рамки зажата в диапазон, при переполнении — прокрутка внутри. Включение, отключение, удаление и обновление расширения меняют блок без перезагрузки окна (`contributions-changed`); блока нет без виджетов. Проверка: юнит модели и манифеста, e2e (появление, высота, чужая команда отклоняется, отключение), axe светлой и тёмной темы.
- R10. Значки и контекст панелей. Необязательный `icon` у `commands` и `panels` — имя из закрытого списка `EXTENSION_ICONS` (24 имени, умолчание `puzzle`) — показан в палитре и боковом меню (декоративно, `aria-hidden`); неизвестное имя — ошибка манифеста. `PanelContext.context` (`{ courseId: string | null }`, только чтение) и `onContextChange` дают панели и виджету активный курс; смена курса в приложении доходит без перезагрузки рамки. Проверка: юнит манифеста и моста рамки, e2e.
- R11. Уведомления. Разрешение `notifications` («Системные уведомления»). `ctx.notifications.show({ title, body })` (название ≤ 80, текст ≤ 300 символов, чистый текст) показывает уведомление ОС и разрешается `true`; `false` — ОС их не поддерживает или пользователь отключил их расширению. Не более 3 в минуту и 30 в час на расширение, сверх лимита — `NotificationRateLimitError`. Без разрешения — `PermissionError('notifications')`. Уведомление называет расширение; клик показывает окно приложения. Работает, только пока приложение запущено. Строка расширения имеет переключатель «Уведомления» (выключен — `show` даёт `false`). Проверка: юнит службы и лимитов, тест main-стороны с подменой `Notification`, e2e с журналом уведомлений.
- R12. Расписания. `contributes.schedules` (`id`, `every: 'daily' | 'hourly'`, `at: 'HH:MM'` только для `daily`, умолчание `09:00`; ≤ 4 на расширение) и `ctx.schedule.on(id, handler)`. Срабатывание — по местному времени: `daily` в `at`, `hourly` в начале часа; расширение активируется лениво в момент срабатывания, обработчик ограничен 10 с. Срабатывание, обнаруженное позже чем через 2 минуты (приложение было закрыто или спало), пропускается и не воспроизводится; обработчик, ещё работающий с прошлого срабатывания, срабатывания не получает. Отключённое расширение и расширение с выключенным переключателем «Расписание» в строке не срабатывает; строка показывает расписания человеческим текстом. Проверка: юнит планировщика на управляемых часах (сон, пересечение суток, перекрытие, отключение), e2e с ускоренными часами.
- R13. Сквозная полнота. Каждый новый ключ, точка и разрешение присутствует в: манифесте и `normalize`, `ExtensionContributesDto` и записи каталога (необязательные ключи, пустые опускаются), `dolphy-ext types` (идентификаторы `widgets`, `schedules`, типы значений настроек), SDK (`defineExtension({ schedules })`, `defineExtensionWidget`, ключ `widgets[<id>]` сборки) и помощниках `@dolphy-app/extension-sdk/testing` (`createMemorySecrets`, `createMemoryStats`, `createMemoryNotifications`, `createMemorySchedule`), примерах `docs/design/extensions.md`, подписях диалога установки ru/en. Проверка: `docs-contributions.test.ts`, юниты `extension-tools`/`extension-sdk`, `settings-extensions-i18n.test.ts`.
- R14. Настройки пользователя. Переключатели «Расписание» и «Уведомления» хранятся в `engine.db` (`ExtensionSettingsDto.schedulesOff`, `notificationsOff`: отсортированные id без повторов), переживают перезапуск и обновление расширения. Все новые строки интерфейса — ru и en через `vue-i18n`. Проверка: общий набор `describeSettingsStoreContract` для обоих адаптеров, тест службы `settings`, схема RPC, `i18n.test.ts`.

## Решения

**Мост к main.** `safeStorage` и `Notification` есть только в main: в `electron.d.ts` 44.4.5 пространство `Utility` их не содержит (только `net` и типы), а хост движка и хост расширений — `utilityProcess` с единственным каналом `process.parentPort` к main (`apps/desktop/electron/host/index.ts`, `ext-host/index.ts`). Цепочка: код расширения → запрос по каналу хоста (`secrets.*`, `notifications.show`, `stats.*` — новые `HostRequest` в `packages/extension-host/src/protocol.ts`, схема `hostRequestSchema`, диспетчер `callService` в `channel.ts`; ограниченный процесс идёт через раннер, который подставляет свой `extensionId`, `restricted-runner.ts`) → служба движка `ExtensionHostServices` (`packages/engine/src/app/services/extension-host-services.ts`: разрешение из манифеста, включённость, лимиты, переключатели) → новый порт движка `PlatformServices` (`cipher`, `notifier`) → `parentPort` хоста движка → main. Протокол: `{ type: 'platform-request', id, op: 'cipher.available' | 'cipher.encrypt' | 'cipher.decrypt' | 'notify', … }` и `{ type: 'platform-response', id, ok, … }`, шифртекст — base64, срок ответа 5 с, при выходе хоста ожидающие запросы отклоняются `UNAVAILABLE`. Адаптер порта — `apps/desktop/electron/host/platform.ts` (передаётся в `boot()` → `createEngine`), обработчик — `apps/desktop/electron/main/platform-services.ts` (зависимости внедряются, как у остальных оболочек, тестируется с подменами; ответ идёт через `engineHost.postMessage`, `index.ts` уже хранит его). Умолчание порта (CLI, тесты) — «хранилища ключей нет, уведомлений нет». Шифртекст хранит движок в `engine.db` (третье пространство `ExtensionDataStore.secrets`, новая миграция `engine-sqlite` — следующий свободный номер на момент слияния): так жизненный цикл данных (`clearData`, удаление с данными, `dataUsage`) остаётся в одном месте, а main — шифровальная машина без состояния. Отвергнуты: хранение блобов в main (второй источник данных и своя очистка); ключ из main и шифрование в движке (ключ в памяти движка и вне `engine.db`); любые варианты через хост расширений (он тоже `utilityProcess`).

**Хранилище ключей.** `isEncryptionAvailable()` ложно, либо на Linux `getSelectedStorageBackend() === 'basic_text'` (фиксированный пароль — не защита), либо до `app.whenReady()`: тогда `SecretsUnavailableError`. Не расшифровывается существующее значение (ключница сменилась) — та же ошибка, автор может `delete` и записать заново. e2e и смоук не обращаются к настоящей связке ключей (на macOS это запрос пароля): в несобранном приложении `DOLPHY_FAKE_SAFE_STORAGE=1` подставляет обратимый шифр, настоящий `safeStorage` покрыт юнитом с подменой и ручной проверкой на macOS.

**Уведомления.** Main проверяет `Notification.isSupported()`, создаёт `new Notification({ title, body, silent: true })`; имя расширения — `subtitle` (macOS), на остальных платформах последней строкой текста; клик показывает окно. Лимиты, длины, очистка управляющих символов и переключатель — в движке, а не в main (ограниченный процесс не доверен). В e2e (несобранное приложение) `DOLPHY_NOTIFICATION_LOG=<файл>` заменяет вызов ОС записью JSON-строки.

**Расписания.** Планировщик — `packages/extension-host/src/scheduler.ts` рядом с `event-dispatcher.ts`, в движке: тик каждые 30 с по внедряемым часам, читает снимок расширений и политику на каждом тике (отключение, безопасный режим W1 и удаление действуют сразу), хранит в памяти только курсор последней проверки — вне приложения ничего не накапливается, поэтому пропущенное не воспроизводится. Срабатывание `occurrence` допустимо, если `now − occurrence ≤ 2 мин`; из нескольких допустимых берётся последнее. Доставка — новый `ExtRequest` `fireSchedule` (ленивая активация, как `deliverEvent`, `restart: false`). Переход на летнее время: отсутствующее местное время за сутки просто не срабатывает. Нового разрешения расписание не просит: оно запускает тот же код с теми же охранами, пользователь выключает его в строке. Для e2e в несобранном приложении `EngineConfig.scheduleTickMs` и `scheduleClockOffsetMs` (из `DOLPHY_SCHEDULE_TICK_MS`, `DOLPHY_CLOCK_OFFSET_MS`).

**Статистика.** Служба `stats` в `ExtensionHostServices` строит индекс «локальная дата × курс → { attempts, correct }» из попыток журнала (`AttemptEntry`, `packages/engine/src/domain/journal.ts`; курс — префикс `<курс>::` в `exerciseId`) при первом обращении и сбрасывает его при новой попытке и смене часового пояса (`Intl.DateTimeFormat().resolvedOptions().timeZone` процесса движка). `progress_reset` в счёт не входит: статистика — история попыток. Порог «верно» совпадает с `PASSING_GRADE_MIN = 3` планировщика (`scheduler/session-state.ts`).

**Локализация на стороне окна.** Движок отдаёт подписи как в манифесте (с `%ключ%`) и таблицы: `ResolvedExtension.messages` (читаются при обнаружении рядом с иконкой, `packages/extension-host/src/discover.ts`; файл ≤ 64 КиБ, ≤ 500 ключей, значения ≤ 500 символов), `messages` в `ExtensionInfoDto` и `ContributionsDto`. Чистая `resolveText(value, tables, locale)` живёт в `@dolphy-app/extension-api`; окно вызывает её из реактивных вычислений, поэтому смена языка не требует запросов. Каталог и `catalog build` разрешают на `en`, `manifestMismatch` `name`/`description` не сверяет, так что расхождения нет. Предупреждение `locale.missing-key` использует механизм структурированных диагностик W1.

**Контракт и пакеты.** Контракт `engine-contract` поднимается каждым этапом, меняющим DTO (следующая версия на момент слияния; числа не фиксируются, волны идут параллельно): варианты `text`/`color`/`list` и поля `group`/`order`/`visibleWhen` в `ExtensionSettingDefDto`; `ExtensionInfoDto.messages`, `ContributionsDto.{messages, widgets, schedules}`; `icon` в `CommandContributionDto`/`PanelContributionDto`; `ContributionTitlesDto` с `exerciseTypes`/`markdownRenderers`; `ExtensionContributesDto.{widgets, schedules}`; `ExtensionDataUsageDto.secrets`; `ExtensionSettingsDto.{schedulesOff, notificationsOff}` и методы `setSchedulesEnabled`/`setNotificationsEnabled`; схема `engine-rpc`. `SettingValue` расширяется до `boolean | string | number | string[]` (`extension-api`, `settingValue` в `protocol.ts`, `fits` в `state.ts`). `EXTENSION_PERMISSIONS` получает `learning.stats` и `notifications`, таблица `GRANT_FLAGS` в `permissions.ts` — пустые записи. Новые точки — `points/widgets.ts`, `points/schedules.ts` в `CONTRIBUTION_POINTS`; `ResolvedExtension` и проверка формы `isResolvedExtension` получают `widgets`, `schedules`, `messages`. Рамка получает режим `widget` (общий код с `panel` в `frame-runtime.js`); модуль по умолчанию `./widget.mjs`, несколько виджетов в одном файле — как у панелей. Размещение виджетов — виджет FSD `widgets/extension-widgets` в `DailyPlanPage.vue`. Манифест остаётся строгим, все новые ключи вводятся сразу.

## Surprises & Discoveries

Разведка до начала работ (по коду `develop`):
- Хост движка и хост расширений — `utilityProcess`, у обоих только `parentPort`; `safeStorage` и `Notification` в пространстве `Utility` `electron.d.ts` 44.4.5 отсутствуют. Запросов «движок → main» с ответом сейчас нет: `onMessage` в `index.ts` обрабатывает единственное одностороннее `restart-ext-host`.
- Запросы кода расширения уже идут одним путём (`engine.request` в `runtime.ts` → `hostRequestSchema` → `callService`), в ограниченном процессе — через раннер с подменой `extensionId`: новые методы добавляются в одном месте.
- В движке нет ни серий, ни часовых поясов; журнал хранит `exerciseId`, `grade`, `at`, `source`.
- `locales/*.json` — допустимые файлы версии каталога (`json`), протокол `dolphy-ext` `.json` не отдаёт: отдельной правки списков не нужно.
- Ключ `when` у команд зарезервирован (`strictObject` отвергает его): `visibleWhen` настроек — отдельная простая форма, не `when` волны 4.

Этап 2a-1:
- `ResolvedExerciseType`/`ResolvedMarkdownRenderer` получили `title: string | null`; запись реестра `contributions()` его не отдаёт (окну нужен только `titles` из `ExtensionInfoDto`). Ключ `titles.markdownRenderers` — язык рендерера (он же элемент `contributes.markdownRenderers`).
- Движок не зависит от `@dolphy-app/extension-api`, поэтому шаблон цвета `#rrggbb` продублирован в `engine/src/domain/extension-setting-values.ts` (рядом с проверкой значений); в `extension-api` он остаётся константой `COLOR_SETTING_PATTERN` для манифеста и тестового помощника SDK.
- Глобальный `:where(h1..h6){margin:0}` не слоёный и перебивает утилиты Vuetify (`mb-4` у `h3` не срабатывал): отступ заголовка раздела задан в `<style scoped>`.

Этап 2a-2:
- Подписи в `ResolvedExtension` и DTO остаются как в манифесте (`%ключ%`); таблицы читает `loadLocales` (`extension-host/src/locales.ts`) при обнаружении только с `verifyFiles` (проверка каталога по исходникам и установщик без файлов таблиц не читают). Ссылка вместо файла и каталог вместо файла — `locale.invalid-file`; файл крупнее 64 КиБ не читается вовсе.
- Предупреждения о переводах лежат в `ExtensionInfoDto.diagnostics` загруженного расширения (раньше там были только причины сбоя и `safe-mode`); коды названы `locale.missing-key` и `locale.invalid-file` (точка в коде — путь ключа сообщения в окне: `settings.extensions.diagnostic.locale.missing-key`). В `ResolvedExtension` они хранятся в `warnings`, чтобы не путаться с `DiscoveryResult.diagnostics` (пропущенные расширения).
- Длину результата проверяет сам разбор манифеста: инструмент подставляет текст языка в копию манифеста (`localizeManifest`) и прогоняет `parseManifest`; нарушения по путям локализуемых полей — ошибки `CHECK-026`. Правила длины не дублируются.
- `%ключ%` подчиняется предельной длине поля (`category` — 40 символов, значит, ключ в нём ≤ 38): схема манифеста не знает о подстановке.
- Подписи заголовков виджетов (`widgets[].title`) уже входят в `LOCALIZED_FIELDS`; точка `widgets` появится в этапе 2b-2, и тогда окно подставит их тем же `useExtensionText().of(...)`.
- `CHECK-026` стоит в конце таблицы правил (после эвристик `CHECK-022`…`CHECK-025`), чтобы вывод `--list-rules` шёл по возрастанию номеров.
- Окно: описание команды в реестре (`CommandDescriptor.description`) стало `MaybeRefOrGetter`, как название и категория: смена языка не перерегистрирует команды.

Этап 2a-3:
- Порт `PlatformServices` пока содержит только `cipher`: `notifier` и операция `notify` протокола `platform-request` добавит этап 2c-1, где они появляются в коде (пустой порт без вызывающего — мёртвый код).
- Таблица `extension_secret` — миграция 5 (после 4, `extension_storage`/`extension_setting`); на момент слияния номер может сдвинуться из-за параллельных этапов.
- В хранилище секретов лежит шифртекст (base64 в JSON-строке), он длиннее открытого значения: потолки адаптера (`SECRET_STORE_LIMITS`) — вдвое выше открытых (значение 8 КиБ, 32 ключа), а 4 КиБ открытого значения, длину ключа и число ключей проверяет служба (`EXTENSION_SECRET_LIMITS`). Общий размер потолком не служит: поэтому контрактные тесты `total-size` для пространства секретов пропускаются (`it.skipIf`).
- Хост движка не знает, готово ли приложение: `app.isReady()` и бэкенд Linux читает только main, поэтому доступность — запрос `cipher.available`, а не кэш в движке.
- Тест, что секрет не попадает в журналы, — `apps/desktop/test/platform-services.test.ts` (файловый журнал main и stderr при враждебном `safeStorage`, который кладёт открытый текст в сообщение ошибки) и `extension-secrets.test.ts` движка (логгер движка). Диагностический отчёт строится из DTO движка, секретов в нём нет по построению.

Этап 2b-1:
- Контракт `engine-contract` не менялся: разрешения в DTO — строки (`ExtensionInfoDto.permissions: string[]`), запросы статистики — внутренний протокол хоста (`HostRequest`), не RPC окна. Версию контракта этот этап не поднимает.
- Отказ службы без разрешения — `INVALID_ARGUMENT` с `details: { reason: 'permission', permission: 'learning.stats', extensionId }` (по образцу `reason: 'disabled'`), нового кода ошибки нет: разрешение — единственный отказ этого вида, а `details.reason` уже различает отказы `INVALID_ARGUMENT` (`disabled`). `createExtensionStats` превращает такой отказ в `PermissionError('learning.stats')`.
- Индекс статистики лежит в `EngineContext.statsIndex` (`app/stats-index.ts`), а не внутри `ExtensionHostServices`: сбрасывать его должны `applyEntries` (запись, синхронизация, импорт) и `rebuild`, а они принадлежат контексту. Проход по журналу повторяется, если запись пришла во время прохода (счётчик поколений), и не залипает на сбое чтения.
- `PASSING_GRADE_MIN` экспортирован из `scheduler/session-state.ts`: порог «верно» один, а не копия.
- Арифметика локальных дат — номера дней по календарю (`domain/learning-stats.ts`), а не разность в миллисекундах: сутки в 23 и 25 часов не ломают серию.
- Помощник SDK `createMemoryStats` дублирует эту арифметику (SDK не зависит от движка, движок — от `extension-api`); паритет держат одинаковые таблицы случаев в тестах обеих сторон.
- e2e этапа лежит в `apps/desktop/e2e/extension-stats.e2e.test.ts`, а не в общем `extension-breadth-1.e2e.test.ts` из «Требований»: остальные этапы волны тоже ведут отдельные файлы (`extension-settings-rich`, `extension-locales`). Дни в e2e создаёт `shiftJournalBack` (сдвиг на целые сутки), поэтому прогон в пределах часа вокруг местной полуночи или перехода на летнее время может дать расхождение на день.

## Decision Log

- 2026-10-04. Уровень безопасности как у Obsidian (обзор, безопасный режим, диагностика) (владелец). Не входят: независимый аудит, песочница ОС, подпись и проверка издателя, ограничение сети, лимит кучи V8, отклонение симлинков, процессные тесты на всех ОС.
- 2026-10-04. Обратная совместимость не обеспечивается (владелец): приложение и расширения сырые, ломаем сразу. Причина: экономия усилий, нет внешних пользователей API.
- 2026-10-04. Отложено (владелец): сайт документации и typedoc, витрина каталога, `dolphy-ext analyze`, постраничный индекс, мастер «новое расширение» в приложении, хуки планировщика и модели памяти (вернуться после статистики и импортёров), сервисы между расширениями, матрица совместимости, автообновление (ADR 0004 остаётся).
- 2026-10-04. Шифртекст секретов хранит движок, main — шифровальная машина без состояния. Причина: единый жизненный цикл данных расширения, отсутствие второго хранилища в main.
- 2026-10-04. Хранилище `basic_text` на Linux считается недоступным. Причина: фиксированный пароль создаёт ложное ощущение защиты.
- 2026-10-04. Секреты без разрешения, расписания без разрешения, `notifications` и `learning.stats` — с разрешением. Причина: собственные данные безобидны (ADR 0007), а чтение журнала и системные уведомления пользователь должен видеть заранее.
- 2026-10-04. `group` и `order` — поля настройки, а не тип `group`; `visibleWhen` — одна ссылка на настройку того же расширения, скрытое значение сохраняется. Причина: плоский список определений остаётся простым, цепочки и циклы запрещены.
- 2026-10-04. Подстановка `%ключ%` только целой строкой, `locales/en.json` обязателен при любом `%ключе%`, каталог показывает `en`. Причина: нет интерполяции и сложного разбора; `en` — единственный корень цепочки для каталога.
- 2026-10-04. Подписи разрешает окно, а не движок. Причина: смена языка применяется без запросов; движок не знает системный язык.
- 2026-10-04. Пропущенные срабатывания расписаний не воспроизводятся, порог 2 минуты, состояние только в памяти. Причина: детерминизм и отсутствие накопленных очередей после сна или простоя.
- 2026-10-04. «Верная» попытка в статистике — оценка ≥ 3, `progress_reset` в счёт идёт. Причина: совпадает с порогом планировщика; статистика — история, а не текущий прогресс.
- 2026-10-04. Порядок формы: сначала весь список сортируется по `order` (затем по порядку объявления), разделы идут в порядке первого вхождения в отсортированном списке. Причина: `order` управляет и порядком настроек, и порядком разделов без второго поля; настройки без `group` остаются первым разделом без заголовка независимо от `order`.
- 2026-10-04. `visibleWhen` не может указывать на настройку, у которой есть собственный `visibleWhen` (цепочки запрещены решением выше), поэтому циклы отвергаются тем же правилом, а условие не нужно вычислять рекурсивно. Цель-`enum` проверяется только по типу `equals` (строка), не по списку вариантов.
- 2026-10-04. Движок принимает цвет в любом регистре и хранит нижний (`normalizeSettingValue`); равный по содержимому список и тот же цвет в другом регистре изменением не считаются.
- 2026-10-04. Названия видов задания и рендереров bundled-расширений (`dolphy.choice`, `dolphy.sql`, `dolphy.math`) написаны по-английски: `extension.json` — публичный файл, перевод появится вместе с локализацией манифеста (2a-2).
- 2026-10-04. Предупреждения о переводах хранятся среди `diagnostics` загруженного расширения и показываются предупреждением (`v-alert`), а не текстом причины сбоя. Причина: расширение работает, а дизайн-ревью показало, что строка обычного текста неотличима от описания.

- 2026-10-05. `DOLPHY_FAKE_SAFE_STORAGE` принимает два значения: `1` — обратимый шифр, `unavailable` — хранилища ключей нет (только в несобранном приложении). Причина: e2e сценария «без хранилища ключей» не может опираться на настоящую связку ключей, а CI Linux и без подмены дал бы `basic_text` недетерминированно.
- 2026-10-05. Предел `valueBytes` открытого значения секрета — 4 КиБ в байтах UTF-8 (а не в символах), ключ — 128 кодовых единиц UTF-16, как у хранилища кода. Причина: единые правила с `ctx.storage`.
