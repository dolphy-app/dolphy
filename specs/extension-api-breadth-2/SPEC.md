# Расширения: импорт и экспорт, `when` и сочетания клавиш, UI-кит и зависимости

Живой документ, пока `status` — `draft` или `active`: `Progress`, `Surprises & Discoveries`, `Decision Log` обновляются вместе с кодом. По завершении фичи переносится в `specs/archive/` и не меняется. Правила — скилл `spec-workflow`.

## Цель

Расширение превращает чужой файл в курс и выгружает курс или прогресс в файл (импортёры и экспортёры); показывает свои команды, панели и виджеты только там, где они уместны (`when`); пользователь сам назначает сочетания клавиш командам приложения и расширений; автор собирает панель из готовых доступных элементов (`@dolphy-app/extension-ui`) и может потребовать другое расширение (`dependencies`). Всё видно в приложении: «Настройки → Библиотека», палитра, «Настройки → Сочетания клавиш», «Настройки → Расширения».

## Не цели

- Бинарные ассеты в импортируемом курсе (только текстовые файлы); импорт из сети и из каталога; пакетный импорт нескольких файлов.
- Новое разрешение для импорта или экспорта: согласие — явный выбор файла в диалоге (владелец).
- Сервисы между расширениями, автоустановка зависимостей, диапазоны версий приложения в зависимостях.
- Явный флаг `exposedToExtensions` и вызов команд приложения из расширений (ADR 0012 стоит).
- Кнопка палитры или пункты импорта в боковом меню; декларативное дерево UI.
- Всё из «Deferred» владельца (запись в `specs/archive/2026-10-04-extension-housekeeping`: единственная парковка).

## Требования

Проверки — юнит-тесты пакетов и `apps/desktop/test`, e2e `apps/desktop/e2e`, `dolphy-ext validate`.

- R1. Манифест принимает `importers` (`{id, title, accept: ['.csv', …], input?: 'text' | 'bytes'}`; `accept` — 1–8 расширений в нижнем регистре, `input` по умолчанию `text`) и `exporters` (`{id, title, scope: 'course' | 'progress'}`); не более 8 записей каждого вида, `id` и `title` по правилам команд. Экспортёр с `scope: 'progress'` без разрешения `learning.stats` — ошибка манифеста. Проверка: юнит `extension-host` (таблица валидных и невалидных записей), `dolphy-ext validate` на фикстуре.
- R2. Точки входа. Для каждого импортёра и экспортёра включённого расширения в палитре есть команда («Импорт: <title>», «Экспорт: <title>», категории локализованы), а в «Настройки → Библиотека» — карточка «Импорт и экспорт» с кнопкой на каждую запись и id расширения. Записи пропадают при отключении и удалении расширения без перезагрузки окна. Проверка: e2e с расширением-фикстурой; юнит адаптера реестра.
- R3. Выбор файла. Импорт открывает системный диалог с фильтром по `accept`; отмена ничего не делает; файл больше 20 МиБ отклоняется сообщением «файл слишком велик» без вызова расширения; при `input: 'text'` файл не в UTF-8 даёт сообщение, а не вызов. Проверка: юнит оболочки `platform` в `electron/main`, e2e (диалог подменён тестовым хуком).
- R4. Обработчик получает `{name, text}` либо `{name, bytes}` ровно по `input` и возвращает `{files: Record<path, string>}` для нового каталога курса. Допустимо до 5000 файлов, до 2 МиБ на файл и до 20 МиБ суммарно; путь относительный, с `/`, без `..`, пустых и начинающихся с точки сегментов, без совпадений без учёта регистра. Нарушение — отказ с причиной `invalid-result`, в библиотеку ничего не пишется. Проверка: юнит `extension-host` на границах (5000/5001 файлов, 2 МиБ+1, путь `../x`, `.git/x`, `A.md`+`a.md`).
- R5. Проверка до записи. Присланное дерево проверяется существующим компилятором курсов; окно показывает сводку (число курсов, уроков, упражнений) и диагностики (ошибки и предупреждения, до 50). При любой ошибке кнопка «Импортировать» недоступна и на диске ничего не остаётся; «Отмена» тоже ничего не оставляет. Проверка: юнит сервиса `extensions` (память), e2e: курс с ошибкой и без.
- R6. Запись. «Импортировать» кладёт курс в `<корень библиотеки>/imported/<id расширения>-<имя файла без расширения, латиницей через дефис>` атомарно и перезагружает библиотеку: курс появляется в «Курсах» без перезапуска. Повторный импорт файла с тем же именем тем же расширением заменяет прежний каталог; сводка заранее говорит «заменит существующий». Если перезагрузка отвергла результат (например, повтор `id` курса из другого каталога), каталог откатывается, библиотека прежняя, пользователь видит диагностики. Проверка: юнит сервиса (замена, откат), e2e: импорт, перезапуск движка, курс на месте.
- R7. Экспорт курса. После выбора курса (по умолчанию активный) обработчик получает снимок `{scope: 'course', courseId, title, files: Record<path, string>}` (текстовые файлы каталога курса, до 20 МиБ, иначе сообщение) и возвращает `{filename, text | bytes}` до 20 МиБ; приложение показывает системный диалог сохранения с этим именем. Расширение пути не видит; имя файла — без разделителей пути и не длиннее 120 символов, иначе `invalid-result`. Проверка: юнит; e2e: файл появился по выбранному пути с ожидаемым содержимым.
- R8. Экспорт прогресса (`scope: 'progress'`). Обработчик получает `{scope: 'progress'}`, данные берёт через `ctx.stats`; возвращает файл как в R7. Проверка: юнит на статистике-заглушке, e2e.
- R9. Сбои. Бюджет обработчика 30 с; таймаут, исключение, отключение и замену набора расширений во время вызова окно показывает понятным сообщением по причине (`timeout`, `handler-failed`, `disabled`, `replaced`, `host-down`, `unknown-importer`); в библиотеку и на диск пользователя ничего не попадает. Поведение одинаково для расширений в процессе хоста и в ограниченном процессе. Проверка: юнит `extension-host` по обоим раннерам, e2e: зависающий обработчик.
- R10. `when`. Команда, панель и виджет (W2) могут иметь `when` — выражение над ключами `route`, `course.active`, `session.active`, `locale`, `theme.dark` с `==`, `!=`, `&&`, `||`, `!`, `in`, скобками, строками в одинарных кавычках, `true`/`false`; длина до 200 символов. Выражение с неизвестным ключом, ошибкой синтаксиса или несовпадением типа — ошибка манифеста с позицией. Проверка: табличный юнит `extension-api` (`parseWhen`, `evaluateWhen`), `dolphy-ext validate`.
- R11. Действие `when`. При ложном `when` команда не показана в палитре и не выполняется сочетанием, пункт меню панели скрыт, виджет не нарисован; значение пересчитывается при смене маршрута, курса в фокусе, сессии, языка и темы без перезагрузки. Панель и команда остаются доступны своему расширению (`ctx.call`, `openPanel`), как у `palette: false`. Проверка: e2e с командой `when: "route == 'courses'"`: видна на «Курсах», нет на «Плане дня».
- R12. Сочетания пользователя. В «Настройки → Сочетания клавиш» каждой команде реестра (приложения и расширений, кроме скрытой «Открыть палитру») можно назначить, изменить, очистить и сбросить сочетание; запись клавиш — захват в строке с подтверждением и отменой Esc; есть «Сбросить всё». Назначения переживают перезапуск. `Mod+K` зарезервировано и не назначается. Проверка: юнит модели; e2e: назначить, перезапустить, нажать.
- R13. Выполнение. Диспетчер выполняет действующее сочетание команды любого источника с прежними охранами (не в поле ввода, не при открытом диалоге или меню, без повтора, команда доступна по `enabled` и `when`). Рамка расширения по-прежнему пересылает родителю только Ctrl/⌘+K; расширение, не получившее назначения от пользователя, клавиш не имеет. Проверка: юнит диспетчера; e2e: враждебная рамка шлёт `keydown` с назначенным сочетанием, команда не выполняется.
- R14. Конфликты. Назначение уже занятого сочетания показывает занявшую команду и предлагает «Заменить» (у неё сочетание очищается) или «Отмена». Если два сочетания совпали при загрузке (например, после обновления приложения), обе строки помечены «Конфликт», ни одна не выполняется. Проверка: юнит модели, e2e.
- R15. Подсказка автора. У команды расширения с `keybinding` и без назначения строка показывает «Предложено автором: …» и кнопку «Назначить» (проходит через R14); подсказка, которую приложение не разбирает, не предлагается. Манифест принимает в `keybinding` только то, что разбирает приложение (`Mod`, `Shift`, `Alt`; `Ctrl` — ошибка). Проверка: юнит; `dolphy-ext validate` на `Ctrl+X`.
- R16. `@dolphy-app/extension-ui`: функции, возвращающие DOM-элементы, — `list`, `button`, `textField`, `select`, `toggle`, `card`, `emptyState`; цвета и отступы берутся из CSS-переменных темы рамки, управление с клавиатуры, видимое имя и роль у каждого элемента; весь пакет не больше 10 КиБ в gzip. Проверка: юнит (роли, клавиши, размер сборки), e2e: панель на нём без нарушений axe уровня serious/critical в светлой и тёмной темах.
- R17. Зависимости. Манифест принимает `dependencies: [{id, range?}]` (до 16; `range` — диапазон semver; без самозависимости, дублей и циклов). Расширение загружается, только если каждая зависимость присутствует, включена, загружена и подходит по версии; иначе состояние «зависимости не выполнены» со структурированной диагностикой (код, id, диапазон, найденная версия) и без вкладов. Включение и отключение зависимости пересчитывает зависимых на лету. Зависимость раньше зависимого получает регистрацию вкладов. Проверка: юнит `extension-host` (три причины, цикл, порядок), e2e: отключить зависимость, строка зависимого меняет состояние.
- R18. Каталог и установка. Индекс, сводка записи и диалог установки показывают `importers`, `exporters` и зависимости (с отметкой «установлено/нет»); установка не ставит зависимости сама и не блокируется. Проверка: юнит `extension-catalog`, e2e диалога.
- R19. Авторские инструменты. `dolphy-ext types` выдаёт id импортёров и экспортёров; SDK принимает `importers`/`exporters` в `defineExtension` и `ctx.importers`/`ctx.exporters.register`; `@dolphy-app/extension-sdk/testing` запускает их (`loadImporters`, `loadExporters`) по тем же правилам результата; примеры в `docs/design/extensions.md` (CSV в курс, экспорт курса, `when`, зависимости, UI-кит) проверяются `docs-contributions.test.ts`, включая компиляцию импортированного курса. Проверка: юнит SDK, `docs-contributions.test.ts`.
- R20. Все строки окна — через `vue-i18n` (ru и en); названия, описания и заголовки записей расширений выводятся как данные расширения. Проверка: проверка ключей `ru`/`en` в юнит-тестах слайсов.

## Решения

**Импорт и экспорт идут отдельным каналом, а не через команду.** `invokeCommand` ограничен 200 000 символов аргументов и 64 КиБ результата (`EXTENSION_COMMAND_LIMITS`, `packages/extension-api/src/index.ts`) и не годится для файлов. Контракт получает `extensions.runImporter(extensionId, importerId, {name, text | bytes})`, `commitImport(importId)`, `discardImport(importId)` и `runExporter(extensionId, exporterId, input)`; вызовы идут вне очереди команд (`UNQUEUED`, как `invokeCommand`, `packages/engine/src/app/facade.ts`), `commitImport` — в очереди (`exclusive`). Ошибка `EXTENSION_TRANSFER_FAILED` с `details: {extensionId, id, kind: 'import' | 'export', reason}`. В протокол хоста (`packages/extension-host/src/protocol.ts`) добавляются запросы `runImporter` и `runExporter`; в ограниченный процесс тело файла и ответ идут частями до 256 КиБ и собираются рантаймом, чтобы не упираться в потолок IPC-сообщения (1 МиБ, W1). Сроки: обработчик 30 с (`EXTENSION_TRANSFER_LIMITS.handlerMs`), раннер 32 с, клиент движка 34 с — внутренний срок короче внешнего, как у команд.

**Диалоги — только в main.** Сейчас в `electron/main/shells/platform.ts` есть лишь `pickDirectory`. Добавляются `pickFile({accept, title})` (читает файл ≤ 20 МиБ в main, возвращает `{name, bytes}`; расширение пути не получает) и `saveFile({suggestedName, bytes})` (берёт basename, пишет в выбранное место); оба доступны окну через `window.dolphy.platform` в `electron/preload/index.ts`. Это и есть согласие пользователя: выбор файла и места сохранения нельзя подделать из расширения.

**Запись курса повторяет путь репозиториев.** `app/services/repositories.ts` уже делает «staging → `compile(stagingSource)` → `install` → `reload` → откат при отказе». Тот же порт `SnapshotInstaller` обобщается корнем назначения (`repositories` или `imported`; сканер обходит дерево от корня библиотеки рекурсивно и пропускает каталоги с точкой, поэтому `.staging` невидим, а `imported/<имя>` — обычный курс). `runImporter` строит staging и считает диагностики (`ExpiringMap`: до 4 ожидающих импортов, TTL 10 минут), `commitImport` подменяет каталог и перезагружает. Нет ни нового разрешения, ни доступа расширения к файловой системе: расширение возвращает только строки.

**Экспорт курса получает снимок от приложения.** `ctx.library` умеет лишь `readText` и `stat`, перечислить каталог курса нельзя, и путь курса расширению неизвестен. Поэтому приложение читает текстовые файлы выбранного курса и передаёт их обработчику; доступ — по явному действию пользователя, разрешение `library.read` для этого не нужно. Экспорт прогресса опирается на `ctx.stats` и разрешение `learning.stats` (W2): сырые попытки расширению не отдаются.

**`when` — один парсер в `extension-api`.** `parseWhen` и `evaluateWhen` с закрытым набором ключей лежат в `@dolphy-app/extension-api` и используются схемой манифеста (`packages/extension-host/src/points/commands.ts`, `panels.ts`, виджеты W2), окном и `dolphy-ext validate`. Ключ `when` в схеме команды (раньше зарезервирован и отвергался `strictObject`) становится обычным, `CommandContributionDto`/`PanelContributionDto`/виджет получают `when: string | null`. Значения ключей поставляет окно (`route` — значение из `ROUTE`, `shared/config/routes.ts`; `locale` — `ru`/`en` после разрешения режима `system`); вычисление реактивное, поэтому `when` встраивается в `enabled` записи реестра и в фильтр пунктов меню.

**Сочетания пользователя — настройка `ui.keybindings`.** По AGENTS.md: поле `UiSettingsDto.keybindings: Record<string, string | null>` в `packages/engine-contract/src/index.ts` (ключ — ключ команды реестра `app:<id>` или `extension:<extensionId>:<id>`, значение — каноническая запись `Mod+Shift+L` или `null` для «очищено»; нет ключа — по умолчанию), проверка в `packages/engine/src/app/services/settings.ts` (до 256 записей, вид ключа и значения по общему шаблону `KEYBINDING_OVERRIDE_PATTERN` из контракта, `Mod+K` отвергается), схема в `packages/engine-rpc/src/host/schemas.ts`, расширение общего набора `describeSettingsStoreContract` (`packages/engine/test/node/settings-store.contract.ts`) для адаптеров памяти, JSON и `engine-sqlite`, событие `settings-changed` со `scope: 'ui'` уже есть. Осиротевшие записи (расширение удалено) не показываются и не удаляются: возвращаются вместе с расширением; «Сбросить всё» очищает всё.

**Реестр отдаёт действующее сочетание.** В `shared/lib/command-registry.ts` `Command.keybinding` становится действующим (`переопределение ?? умолчание`), а подсказка расширения — отдельное поле `suggestedKeybinding`; диспетчер (`shortcut-dispatcher.ts`) перестаёт фильтровать по `source === 'app'` и разбирает сочетания один раз при изменении набора, а не на каждое событие. Исполнитель команд расширений получает источник `shortcut` (`features/extension-commands/model/runner.ts`). Конфликт при загрузке — оба выключены (а не «побеждает первый»), чтобы не выполнять команду втихую не ту. Модель и раздел — `pages/settings/model/shortcuts.ts`, `ShortcutsSection.vue`. Грамматика приводится к одной: парсер приложения дополняется `F1`–`F12`, `Home`, `End`, `PageUp`, `PageDown`, а `KEYBINDING_PATTERN` манифеста теряет `Ctrl` (чистая замена, фикстуры `apps/desktop/e2e/fixtures/commands-extension*` уже используют `Mod`).

**UI-кит — отдельный пакет `packages/extension-ui`.** Ванильный TS без зависимостей, функции вроде `button({label, onClick})` возвращают `HTMLElement`; стили вставляются одним `<style>` на рамку и опираются на переменные темы (`--v-theme-*`, их рамке отдаёт `frame-theme.ts`), поэтому тёмная тема работает без кода автора. Публикуется как остальные авторские пакеты (список `packages.yml`, `pnpm verify:packages`); axe-проверка — новая e2e-панель (сейчас axe есть только в `command-registry.e2e.test.ts`).

**Зависимости — только присутствие, включённость и диапазон.** `dependencies` разбирается в `manifest.ts`, порядок обнаружения становится топологическим, расширение с невыполненной зависимостью получает новое состояние `ExtensionStateDto` («зависимости не выполнены», рядом с `loaded/overridden/invalid/disabled`) и диагностику W1 с кодом и данными (`dependency-missing`, `dependency-disabled`, `dependency-version`); ссылаться на встроенные расширения можно. Ни сервисов, ни сигналов между расширениями нет.

**Контракт.** Каждая стадия 4a, 4b и 4c поднимает `CONTRACT_VERSION` до «следующей версии на момент слияния» (номер не фиксируется: волны идут параллельно). 4a: RPC и код ошибки, `importers`/`exporters` в `ContributionsDto` и `ExtensionContributesDto` (по образцу `commands`/`panels`), DTO. 4b: `when` в DTO, `UiSettingsDto.keybindings`. 4c: состояние и диагностика зависимостей, `dependencies` в `ExtensionInfoDto` и сводке каталога. Документация: разделы «Точки вклада» и «Права» `docs/design/extensions.md` (в том числе строка про зарезервированный `when` и «команды расширений не получают клавиш»), README `extension-ui`, `extension-sdk`, `extension-tools`. ADR (следующий свободный номер на момент закрытия): «Пользовательские сочетания и канал импорта/экспорта»; статус ADR 0012 меняется на частично замещённый (пункты «сочетания только у команд приложения» и отложенные пользовательские сочетания и `when`), ADR 0008 — без правок.

**Каталог (`dolphy-app/dolphy-extensions`) — отдельный PR.** Строгий разбор в `catalog check` приходит из версии `@dolphy-app/extension-tools`, закреплённой в репозитории каталога: после выпуска пакетов нужен PR в `/Users/tinkerbells/projects/dolphy-extensions`, поднимающий её, иначе заявки с `importers`, `when` и `dependencies` не пройдут проверку.

## Surprises & Discoveries

- Подсказка `keybinding` в манифесте (`KEYBINDING_PATTERN`, `packages/extension-api/src/index.ts`) допускает `Ctrl`, `F1`–`F12`, `Home`, `End`, `PageUp`, `PageDown`, а `parseKeybinding` окна (`shared/lib/keybinding.ts`) разбирает только `Mod`/`Shift`/`Alt` и одну клавишу или имя из короткого списка: такие подсказки показываются сырым текстом и не могут быть назначены.
- `Command.keybinding` в реестре — одно статическое значение; диспетчер игнорирует всё, кроме `source === 'app'`, и разбирает запись на каждое событие клавиши.
- Сканер библиотеки идёт по дереву от корня рекурсивно и пропускает каталоги с точкой (`authoring/scan.ts`); поэтому `.staging` и `repositories/<id>` уже работают как образец.
- `ctx.library` — только `readText`/`stat` (`LibraryReader`): перечислить файлы курса расширение не может.
- В `electron/main/shells/platform.ts` единственный диалог — выбор каталога; сохранения файла нет.
- Раздел «Сочетания клавиш» построен только на чтении (ADR 0012), `ui`-настройки уже имеют `UiSettingsPatch` и событие `settings-changed` со `scope: 'ui'`.

## Decision Log

- 2026-10-04. Уровень безопасности «как у Obsidian» (владелец): обзор, безопасный режим, диагностика; вне всех волн — независимый аудит, песочница ОС, подпись индекса, сетевой контроль, лимит кучи V8, отказ от символических ссылок, кросс-ОС тесты процессов. Для этой волны: расширение не получает пути файлов, а только строки; лимиты размера и числа файлов — потолки устойчивости.
- 2026-10-04. Отложено (владелец), список ведёт `specs/archive/2026-10-04-extension-housekeeping`: сайт документации и typedoc, витрина каталога, `dolphy-ext analyze`, постраничный индекс, мастер «новое расширение» в приложении, хуки планировщика и модели памяти, сервисы между расширениями, матрица совместимости, автообновление.
- 2026-10-04. Обратная совместимость не обеспечивается (владелец): приложение и расширения сырые, ломаем сразу. Причина: экономия усилий, нет внешних пользователей API.
- 2026-10-04. Импорт и экспорт без нового разрешения; согласие — явный выбор файла (владелец). Причина: пользователь оценивает согласие на файл, а не на абстрактную возможность; расширение не видит файловую систему.
- 2026-10-04. Тип входа импортёра объявляется (`input: 'text' | 'bytes'`), а не определяется по содержимому. Причина: обработчик получает предсказуемую форму, а сбой кодировки — сообщение до вызова.
- 2026-10-04. Каталог импортированного курса — `imported/<id расширения>-<имя файла>`, повтор заменяет прежний после подтверждения. Причина: один предсказуемый путь, без диалога выбора места и без накопления копий.
- 2026-10-04. Экспорт курса получает снимок текстовых файлов от приложения, а не читает через `ctx.library`. Причина: перечисления нет, а действие инициирует пользователь.
- 2026-10-04. Конфликт сочетаний при загрузке выключает оба, при назначении предлагает «Заменить». Причина: молчаливый победитель выполнил бы не ту команду.
- 2026-10-04. Сочетания пользователя применимы и к командам расширений; рамка по-прежнему пересылает только Ctrl/⌘+K. Причина: назначение — действие пользователя, поверхность атаки из рамок не растёт (ADR 0012).
- 2026-10-04. `Ctrl` убран из грамматики подсказки манифеста; приложение разбирает всё, что принимает манифест. Причина: подсказка, которую нельзя назначить, бесполезна.
- 2026-10-04. Зависимости: присутствие, включённость, диапазон, порядок; услуг нет, установка зависимостей вручную. Причина: минимальная польза без графа услуг (отложено владельцем).
- 2026-10-04. Номер версии контракта не фиксируется. Причина: волны могут идти параллельно.
