# Распространение расширений: страница расширения, «Что нового», обновления, устаревание, ссылка установки, адрес каталога

Живой документ, пока `status` — `draft` или `active`: `Progress`, `Surprises & Discoveries`, `Decision Log` обновляются вместе с кодом. По завершении фичи переносится в `specs/archive/` и не меняется. Правила — скилл `spec-workflow`.

## Цель

Пользователь выбирает расширение осознанно и вовремя узнаёт об обновлениях: у расширения есть страница с README, версиями, правами и ссылками; обновление показывает «Что нового»; о доступных обновлениях говорит значок на пункте «Настройки» без захода в раздел; устаревшее расширение помечено, но ставится; ссылка `dolphy://extensions/install/<id>` открывает диалог установки; адрес каталога можно сменить в настройках. Автор и мейнтейнеры получают `CHANGELOG.md` и `deprecated.json` в репозитории каталога.

## Не цели

- Автообновление, подписи, проверка издателя, рейтинги, счётчики установок, скриншоты, комментарии (отложено владельцем).
- Установка по произвольному адресу или из архива: меняется только адрес каталога, а не источник отдельного расширения.
- Показ README расширений из режима разработчика и скопированных вручную сверх чтения файла `README.md` каталога; поле «домашняя страница» в манифесте (ссылки — из записи каталога).
- Сайт каталога, переименование файла индекса (решает `specs/archive/2026-10-04-extension-housekeeping`), листание индекса, новые разрешения и точки вклада.
- Блокировка установки устаревшего расширения, автоматическая замена на альтернативу.

## Требования

Наблюдаемое поведение. Проверки — юнит-тесты пакетов и `apps/desktop/test`, e2e `apps/desktop/e2e` (`catalog.e2e.test.ts` и новые файлы), тесты `extension-tools`.

- R1. Страница расширения. Карточка каталога и строка установленного расширения ведут на страницу `Настройки → Расширения → <id>`: значок, название, id, автор (ссылка на профиль GitHub), описание, теги, разрешения (как в диалоге установки), вклады с названиями, ссылка «Исходники», README, список версий (не больше 5 из индекса: версия, дата, размер, пометка «совместима / несовместима: причина», «установлена»), кнопка действия карточки (установить, обновить, удалить) и «Назад». Расширение, которого нет в каталоге (скопировано вручную, из режима разработчика, из поставки), открывается без каталожных блоков. Проверка: `settings-extension-details.test.ts` (модель страницы по записи каталога и по установленному), e2e: переход с карточки и со строки, возврат, действие со страницы.
- R2. README безопасен. Markdown выводится без сырого HTML; ссылки `https:` открываются во внешнем браузере, остальные (в том числе `javascript:`, `data:`, относительные) — обычным текстом; картинка показывается, только если это файл `png`/`webp`/`jpg`/`jpeg` из файлов этой версии (до 8 картинок и 256 КиБ каждая), иначе вместо неё — её `alt`; README не запускает рендереры расширений и не получает сетевых ресурсов. Проверка: юнит на враждебном README (`<script>`, `<img onerror>`, `[x](javascript:…)`, внешняя и `data:`-картинка, картинка не из версии, 9 картинок), e2e: страница с таким README не создаёт исходящих запросов и не выполняет скриптов.
- R3. Источник README. README установленной версии читается из каталога расширения; README версии из каталога — скачивается по требованию (размер и `sha256` сверяются с индексом, иначе `integrity`) и кладётся в дисковый кэш. Без сети страница показывает кэш с пометкой «Без связи с каталогом: показаны сохранённые данные», без кэша — «README недоступен» и «Повторить»; остальное на странице работает. Показываются первые 64 КиБ, при обрезке — пометка. Проверка: тесты `extension-install` на `node:http` (скачивание, подмена файла, повтор из кэша без сети, обрезка), модель страницы (три состояния).
- R4. «Что нового». Версия каталога может нести `CHANGELOG.md` (необязательный файл версии рядом с `README.md`). Страница показывает его целиком для выбранной версии; диалог обновления — разделы `## <semver>` для версий новее установленной и не новее целевой (новые сверху); если таких разделов нет, диалог говорит «Описание изменений не найдено» и ссылается на страницу. Проверка: юнит чистой функции выбора разделов (`## 1.2.0`, `## [1.2.0] - 2026-10-01`, `## v1.2.0`, нет разделов, версия не semver), e2e: обновление с `CHANGELOG.md` показывает разделы в диалоге.
- R5. Инструменты каталога и `CHANGELOG.md`. `dolphy-ext catalog build` копирует `CHANGELOG.md` проекта в версию (файл попадает в `files` индекса с размером и `sha256`); `catalog check` (CHECK-030) отвергает `CHANGELOG.md` больше 64 КиБ, не UTF-8 или с NUL и предупреждает, если в нём нет раздела текущей версии манифеста. Проверка: `catalog-build.test.ts`, `catalog-check.test.ts`.
- R6. Устаревание в данных. Репозиторий каталога может содержать `deprecated.json` — массив `{ id, versions?, reason, alternatives }` (`versions` — диапазон как в `revoked.json`, нет ключа — все версии; `reason` 1–200 символов; `alternatives` до 3 id). `catalog build` (в том числе `--reindex`) записывает в запись индекса необязательное `deprecated: { versions | null, reason, alternatives }`; повтор `id`, неизвестный `id`, альтернатива, которой нет в индексе, неверный диапазон — ошибка сборки, ничего не пишется. `catalog check --deprecated <файл>` проверяет форму и (с `--published-index`) существование альтернатив. Проверка: `catalog-build.test.ts` (запись, снятие при удалении из файла, каждая ошибка), строгий разбор индекса принимает выход.
- R7. Устаревание в приложении. Расширение с `deprecated`, действующим для показанной версии (карточка) или установленной версии (строка), помечено значком «Устарело»; карточка, диалог установки, страница и строка показывают предупреждение с причиной и альтернативами (названия из каталога, нажатие открывает страницу альтернативы). Установка и обновление разрешены; статус записи и счётчик обновлений не меняются. Проверка: `settings-catalog-lib.test.ts` (действие по диапазону), e2e: расширение с `deprecated` ставится, предупреждение видно во всех четырёх местах.
- R8. Глобальный индикатор обновлений. Если доступны обновления (число из `extensions.updates()`), пункт «Настройки» бокового меню и вкладка «Расширения» страницы настроек несут значок с числом (9 и больше — «9+»); число доступно скринридеру («Доступно обновлений: N»); значок появляется после фоновой проверки при запуске без захода в раздел и исчезает после обновления всех расширений. Проверка: `extension-updates-store.test.ts` (событие `extensions-changed`, переподключение), e2e (значок после запуска с устаревшей установкой, исчезновение, axe в обеих темах и языках).
- R9. Адрес каталога как настройка. «Настройки → Расширения → Каталог → Дополнительно»: поле адреса (только `https:`, исключение — `http:` на loopback), кнопки «Применить» и «Сбросить», действующий адрес и признак «по умолчанию». Неверный адрес (не URL, не `https`, с логином или фрагментом, не `.json`, длиннее 2048) — ошибка рядом с полем, значение не сохраняется. Применённый адрес действует сразу (список каталога перечитывается, проверка обновлений идёт заново), сохраняется в `engine.db` и переживает перезапуск; адрес, равный умолчанию, хранится как «не задан». В несобранном приложении `DOLPHY_EXTENSION_CATALOG_URL` важнее настройки, поле неактивно с пояснением. Проверка: `describeSettingsStoreContract` (память, JSON, SQLite), тест сервиса (каждая причина отказа), `settings-catalog-source.test.ts`, e2e: смена на второй каталог, перезапуск, сброс.
- R10. Расширения из другого каталога. После смены адреса установленные из прежнего каталога расширения продолжают работать, остаются в списке с пометкой «Из другого каталога», не получают обновлений, отзыва и предупреждений об устаревании нового каталога; их `.dolphy-install.json` не меняется. Запись нового каталога с тем же id показана как «Уже установлено из другого источника» с неактивной кнопкой и подсказкой удалить прежнее. Возврат к прежнему адресу возвращает обновления и отзыв. Проверка: тесты `extension-install` (две установки, два адреса), `extension-host` (отзыв только при совпадении `catalogUrl`), e2e: два сервера каталога.
- R11. Ссылка установки. Адрес `dolphy://extensions/install/<id>` принимается строго: схема `dolphy:`, хост `extensions`, путь ровно `/install/<id>`, `id` по `EXTENSION_ID_PATTERN` до 64 символов, без логина, порта, параметров и фрагмента; всё остальное игнорируется с предупреждением в журнале. Принятая ссылка выводит окно на передний план и открывает диалог установки записи каталога (запрос каталога при необходимости); установка начинается только нажатием «Установить». Неизвестный id — сообщение «Расширение «<id>» не найдено в каталоге»; несовместимое — карточка с причиной; уже актуальное — сообщение; ссылка во время установки — сообщение «Дождитесь окончания установки», сама ссылка отбрасывается. Работает при запущенном приложении, при холодном запуске и (macOS) через `open-url`. Проверка: юнит разбора (таблица враждебных адресов), юнит оболочки на поддельном `app` (`argv`, `second-instance`, `open-url`, ссылка до готовности окна), модель обработки в окне, e2e (Linux/Windows путь): второй запуск с аргументом ссылки открывает диалог в первом, холодный запуск с аргументом.
- R12. Регистрация схемы. Установщики регистрируют `dolphy:` (macOS — запись URL-схемы в `Info.plist`, Windows — запись NSIS, Linux — `x-scheme-handler/dolphy` в `.desktop`), собранное приложение вызывает `setAsDefaultProtocolClient`; несобранное (разработка, e2e) схему не перехватывает. Проверка: юнит по `electron-builder.json` и оболочке; `pnpm smoke:packaged` на macOS читает `Info.plist` собранного `.app` и находит схему (проверка ссылки операционной системой вручную — вне автоматических).
- R13. Всё в интерфейсе — через `vue-i18n` (`ru`, `en`, формы числительных); новая настройка — поле контракта, проверка в сервисе, схема RPC, тест адаптеров (`AGENTS.md`). Проверка: `settings-extensions-i18n.test.ts` (полнота ключей).

## Решения

**Контракт** (`packages/engine-contract/src/index.ts`) повышается дважды, на стадиях 5a и 5c: «следующая версия контракта на момент слияния», число не фиксируется. 5a: `extensions.docs(id, { version? })` → `{ version, readme, changelog, source: 'installed' | 'catalog' | 'cache' }` и `extensions.docImage(id, version, path)` → `data:`-URI; `CatalogEntryDto` получает `versions` (до 5: `CatalogVersionDto` + `compatible`, `hasChangelog`), `deprecated`, `elsewhere`; `ExtensionInfoDto.deprecated` (наложение в сервисе `extensions.list` по `installer.deprecationOf`, реестр `extension-host` не трогаем). 5c: `ExtensionSettingsDto.catalogUrl: string | null` (`domain/extension-settings.ts`: нечитаемое значение → `null`), `extensions.setCatalogUrl(url | null)`, `extensions.catalogSource()` → `{ url, default, origin: 'default' | 'setting' | 'env' }`; схемы RPC — `packages/engine-rpc/src/host/schemas.ts`. Проверка адреса — в сервисе (`https:`, loopback `http:` ради локального каталога и e2e, ≤2048, без логина и фрагмента, путь `.json`; результат — `URL.href`; равный умолчанию — `null`, иначе сравнение `catalogUrl` в `.dolphy-install.json` ломало бы идентичность).

**Файлы версии и кэш.** Новое в порте `ExtensionInstaller` (`packages/engine/src/ports/extension-installer.ts`) и `packages/extension-install`: `versionFile(id, version, path)` скачивает файл из `files` индекса (проверка `size`/`sha256` и origin — прежние `http`/`download`) и хранит его в `<extensions>/.catalog/files/<sha256>`: адресация по содержимому, версии неизменны (`catalog build` отвергает другое содержимое под тем же номером), поэтому ETag и повторные запросы не нужны, а офлайн-режим — просто попадание в кэш; потолок кэша 20 МиБ, лишнее удаляется в `ready()`. README установленной версии читается из каталога расширения без сети. Картинки README окно запрашивает лениво (`docImage`, не больше 8 на страницу, `png`/`webp`/`jpg`/`jpeg`, 256 КиБ), поэтому движку не нужен разбор Markdown. Рендер README — отдельный `markdown-it` (`pages/settings/lib/readme.ts`: `html: false`, ссылки только `https:` с `target="_blank" rel="noopener noreferrer"` — `setWindowOpenHandler` в `electron/main/shells/window.ts` отдаёт `https:` в `shell.openExternal`, картинки — заглушка `data-src` без `src`); общий `shared/lib/markdown.ts` (рендереры расширений) не используется. CSP окна не расширяется.

**Страница** — маршрут `settings/extensions/:id` (`settingsExtensionDetails`, `app/router/index.ts`); свой `useInstall` и `InstallDialog` (сейчас они живут в `ExtensionsSection.vue`). Сопоставление записи каталога и установленного — по id; `versions` и `elsewhere` берутся из `CatalogEntryDto`, поэтому без каталога (нет сети и кэша) страница показывает только установленное. **«Что нового»:** `CHANGELOG.md` — обычный журнал автора, а не отдельный формат на версию; разделы по заголовкам `## [v]<semver>`, чистая функция `changelogBetween(markdown, from, to)` в `pages/settings/lib/changelog.ts`; диалогу достаточно `CHANGELOG.md` целевой версии (один запрос). Новое правило `catalog check` — CHECK-030 (номера 019–029 за `specs/extension-authoring`); `CHANGELOG.md` не требует схемы индекса: `md` уже допустимый тип файла, `catalog build` копирует его, как `README.md` (`copyReadme` в `packages/extension-tools/src/catalog/build.ts`).

**Устаревание.** Запись индекса получает необязательное `deprecated` (строгая схема в `packages/extension-catalog/src/schema.ts`, терпимый разбор приложения его при ошибке отбрасывает, запись остаётся), диапазон — тот же `parseRange`, что у `revoked`. Решение «устарело на уровне записи, а не версии»: причина и альтернативы относятся к расширению; диапазон `versions` позволяет пометить только старые. Название альтернативы движок берёт из индекса (`null`, если записи нет). Это предупреждение, а не отзыв: политика (`createExtensionPolicy`) и статус не меняются.

**Индикатор.** Хранилище `shared/api/engine/extension-updates.ts` (по образцу `contributions.ts`): читает `extensions.updates()` при подключении, после `extensions-changed` и переподключения, раздаётся через `provide`. Значок — `v-badge` на пункте «Настройки» в `app/layouts/ShellLayout.vue` и на вкладке «Расширения» в `SettingsPage.vue`. Событие `extensions-changed` приходит при установке, удалении и находке обновлений стартовой проверкой (`runStartupUpdateCheck`), отдельное событие не нужно.

**Адрес каталога и идентичность.** Установщик создаётся один раз с фиксированным `catalogUrl` (`createExtensionInstaller`, `electron/host/installer.ts`, `electron/host/boot.ts` берёт `revocationOf` один раз), поэтому добавляется переключаемая обёртка: `setCatalogUrl` пересоздаёт установщик (новый origin, кэш индекса по `meta.url`, прежний кэш не используется), сбрасывает метку `updateCheckedAt` и запускает проверку обновлений. Что с `.dolphy-install.json`: не трогается и не переписывается; `catalogUrl` в нём — идентичность прежнего каталога, `installedVersion`, `assertReplaceable` и обновления уже требуют совпадения. Ловушка: `revocationReason` (`packages/extension-host/src/revocation.ts`) сейчас применяет отзыв нового каталога к любому расширению с метаданными установки, поэтому проверка `install.catalogUrl === текущий` добавляется туда же, а в `ExtensionInstallDto` окно сравнивает адрес с `catalogSource().url` для пометки «Из другого каталога». Откат индекса (`assertNotRolledBack`) сравнивается только внутри одного адреса.

**Ссылка установки.** Новая оболочка `electron/main/shells/deep-link.ts`: разбор строгий (чистая функция), источники — `process.argv` при старте (Windows/Linux), `second-instance` (аргументы; существующий обработчик в `window.ts` только фокусирует окно) и `open-url` (macOS, в том числе до `ready`). Принятая ссылка буферизуется и отдаётся окну по каналу `deeplink:install`; мост `window.dolphy.deepLink.onInstall(listener)` (`shared/bridge.ts`, `electron/preload/index.ts`) подписывает окно и забирает отложенную ссылку, поэтому гонка холодного запуска невозможна. Окно ведёт ссылку тем же `review()` (`model/install.ts`), то есть нажатие «Установить» остаётся единственным путём к установке. `electron-builder.json` получает `protocols` (`dolphy`), Linux — `mimeTypes: ["x-scheme-handler/dolphy"]` (AppImage регистрирует схему только при интеграции, например AppImageLauncher: приложение это не обходит); `setAsDefaultProtocolClient('dolphy')` вызывается при `app.isPackaged`.

## Surprises & Discoveries

Разведка до начала работ: `catalog build` копирует из проекта только `README.md`, но `md` уже допустимый тип файла версии; `ExtensionInstaller.updates()` читает только кэш, а `extensions-changed` приходит после установки, удаления и находки обновлений стартовой проверкой; установщик привязан к `catalogUrl` при создании, а `revocationReason` не сверяет `install.catalogUrl`, то есть при смене каталога отзыв нового применился бы к чужим расширениям; `requestSingleInstanceLock` и `second-instance` есть (`electron/main/index.ts`, `shells/window.ts`), но аргументы запуска не читаются, `protocols` в `electron-builder.json` нет, мост `window.dolphy` узкий (`engine.connect`, `platform.pickDirectory`); `markdown-it` в приложении настроен `html: false`, но картинки и ссылки обрабатывает по умолчанию, `img-src` окна — `'self' data:`; `updateCheckedAt` хранится отдельно от настроек и должен сбрасываться при смене каталога; репозиторий каталога передаёт `--revoked revoked.json` в обеих ветках `deploy.yml`, `deprecated.json` проще всего вести так же.

## Decision Log

- 2026-10-04. Уровень безопасности «как у Obsidian» (ревью, безопасный режим, диагностика); вне волн: независимый аудит, песочница ОС, подписи индекса и проверка издателя, сетевые ограничения, лимит кучи V8, отказ от символических ссылок, процессные тесты на всех ОС (владелец).
- 2026-10-04. Отложено (единый список — `specs/archive/2026-10-04-extension-housekeeping`): сайт документации и typedoc, витрина каталога, `dolphy-ext analyze`, листание индекса, мастер «новое расширение» в приложении, хуки планировщика и модели памяти, службы между расширениями, матрица совместимости, автообновление (обновления только вручную, ADR 0004).
- 2026-10-04. Обратная совместимость не обеспечивается (владелец): приложение и расширения сырые, ломаем сразу. Причина: экономия усилий, нет внешних пользователей API.
- 2026-10-04. Кэш файлов версии адресован по `sha256`, ETag не используется. Причина: версии неизменны, ETag не даёт ничего сверх попадания в кэш (отклонение от формулировки «кэш и ETag»).
- 2026-10-04. `CHANGELOG.md` — обычный журнал автора, разделы выбираются по заголовкам; формат на версию не вводим. Причина: авторы так и пишут журнал, нужен один запрос для диалога.
- 2026-10-04. Устаревание — на уровне записи с необязательным диапазоном версий; это предупреждение, не отзыв. Причина: причина и альтернативы относятся к расширению, установка остаётся разрешённой (решение владельца).
- 2026-10-04. Принимаем `http:` для loopback в настройке адреса каталога, остальное — только `https:`. Причина: локальный каталог из `dolphy-ext catalog build` и e2e без отдельного обходного пути.
- 2026-10-04. Страница расширения — отдельный маршрут, а не диалог. Причина: README и список версий длинные, страницу можно открыть со строки и со ссылки на альтернативу.
- 2026-10-04. Картинки README запрашиваются лениво по одной (`docImage`), движок Markdown не разбирает. Причина: проще и безопаснее; потолки 8 картинок и 256 КиБ.
- 2026-10-04. CHECK-030 для `CHANGELOG.md` (019–029 за `extension-authoring`). Причина: не пересекаться по номерам правил.
