# Фундамент расширений: диагностика, устойчивость, CI

Живой документ, пока `status` — `draft` или `active`: `Progress`, `Surprises & Discoveries`, `Decision Log` обновляются вместе с кодом. По завершении фичи переносится в `specs/archive/` и не меняется. Правила — скилл `spec-workflow`.

## Цель

Пользователь видит, почему расширение не загрузилось, и может обезопасить приложение (безопасный режим, перезапуск хоста, журнал, копируемая диагностика). Автор получает JSON Schema манифеста для редактора. Релиз-PR проходит упакованный смоук и e2e в CI, а не только юнит-тесты.

## Не цели

- Терпимый разбор манифеста, `@since`, проверка `minAppVersion` по версиям API, удаление `$schema` из сборки: отменено решением владельца (обратная совместимость не обеспечивается). Манифест остаётся строгим (`strictObject`), новые ключи и точки следующих волн вводятся сразу.
- Независимый аудит, песочница ОС, подписанный индекс и проверка издателей, сетевые ограничения, лимит кучи V8, отклонение симлинков, процессные тесты на нескольких ОС (уровень безопасности «как у Obsidian»: обзор, безопасный режим, диагностика).
- Локализация манифеста, `ctx.secrets`, статистика, уведомления (W2); лимиты и квоты процессора и памяти.
- Отправка журналов и диагностики куда-либо: только копирование в буфер по действию пользователя.
- Отложено (`specs/archive/2026-10-04-extension-housekeeping`, единая «парковка»): сайт документации, разбор индекса постранично, мастер «новое расширение» в приложении и прочее.

## Решения

**Диагностика (1a).** `ExtensionInfoDto.message` заменяется на `diagnostics: ExtensionDiagnosticDto[]` (`packages/engine-contract/src/index.ts`; `{code, data}`, `data` — строки, числа, списки строк; `EXTENSION_DIAGNOSTIC_CODES` — закрытый список). `inspectExtensionDir` и `discoverExtensions` (`packages/extension-host/src/discover.ts`) возвращают диагностику вместо строки; `formatDiagnostic` в `extension-host` строит английский текст для CLI, логов и установщика (`apps/desktop/electron/host/installer.ts`, `packages/extension-tools/src/catalog/check.ts`, `src/index.ts`), так что R3 выполняется без правок вызывающих. `registry.ts` собирает `diagnostics` (`overridden`, `invalid`, безопасный режим); поле `revoked` остаётся отдельным (текст отзыва — данные каталога). Окно: `InstalledExtensions.vue` (строка с `extension.message` ~L361), тексты — `pages/settings/i18n/{ru,en}.ts`. Чистая замена: все потребители `message` (окно, `testkit`, тесты) переводятся в том же PR.

**Схема манифеста (1a).** `z.toJSONSchema(manifestSchema, {io: 'input', unrepresentable: 'any'})` (zod 4.6.5, зависимость `extension-host`) пишется в `packages/extension-api/extension.schema.json` и коммитится; тест `manifest-schema.test.ts` сверяет файл с перегенерацией (обновление: `UPDATE_EXTENSION_SCHEMA=1`). Схема не выразит перекрёстные правила (`id` вида с префиксом, «хотя бы один вклад», разрешение `learning.events` для событий, `check` точек), поэтому источником истины остаются `parseManifest` и `dolphy-ext validate`; это сказано в описании схемы и в `docs/design/extensions.md`. `tools/lib/package-manifest.mjs` копирует файл в `dist/` и добавляет подпуть экспорта, `verify-packages.mjs` проверяет наличие. В `manifestSchema` добавляется `$schema: z.string().optional()`; `normalizeManifest` ключ не переносит. Шаблон `packages/create-extension/src/template.ts` (`manifestJson`) получает `"$schema": "./node_modules/@dolphy-app/extension-api/dist/extension.schema.json"` и зависимость `@dolphy-app/extension-api` (иначе путь не существует при pnpm).

**Безопасный режим (1b).** Эффективный режим = флаг argv/переменная окружения (main читает их и передаёт движку полем `EngineConfig.forceSafeMode`) ИЛИ `ExtensionSettingsDto.safeMode`. Применяется в `createExtensionPolicy` (`packages/extension-host/src/policy.ts`): `isEnabled` для origin не `bundled` возвращает `false`, остальное прежнее; живое применение — прежним `reload()`. Расширения остаются в обнаружении и показываются как `disabled` с `safe-mode`. Баннер — компонент оболочки приложения (`apps/desktop/src/app/layouts`), данные из `extensions.diagnostics().safeMode` (`{active, persisted, forcedBy: 'flag'|'env'|null}`). Поле настройки: контракт (`ExtensionSettingsDto.safeMode`), `packages/engine/src/domain/extension-settings.ts` (умолчание, разбор), проверка в `packages/engine/src/app/services/extensions.ts` (`setSafeMode`), схема RPC `packages/engine-rpc/src/host/schemas.ts` и `RPC_METHODS` (`packages/engine-contract/src/rpc.ts`), тесты адаптеров `packages/engine-sqlite/test/settings-store.test.ts`.

**Здоровье и хост (1b).** Движок накапливает в памяти (`packages/engine/src/app/extension-health.ts`, новый): сбои — по исходам вызовов (`invokeCommand` в `services/extensions.ts`, клиент хоста `packages/extension-host/src/client.ts`, доставка событий `event-dispatcher.ts`); длительность активации, приостановку и убийства — по новому сообщению хоста `health` (`protocol.ts`, `channel.ts`), которое шлют `runtime.ts` (замер активации в обоих режимах) и `restricted-runner.ts` (`suppressedUntil`, сейчас только в логе, ~L278). Сбой не считается дважды: убийства и приостановка — состояние, а не сбой. Сводка сбрасывается, когда `revision` расширения меняется (вытеснение в `ExtensionRuntime.replace`). Супервизор хоста (`apps/desktop/electron/main/ext-supervisor.ts`) получает `reset()` (очищает `gaveUp` и `crashTimes`, вызывает `start()`) и сообщает состояние (`running`/`restarting`/`gave-up`) движку сообщением `ext-host-status` тем же путём, что `reload-extensions`; кнопка «Перезапустить хост» → `extensions.restartHost()` → движок шлёт main `reset-ext-host` (по аналогии с `restart-ext-host`).

**Журнал и пределы (1c).** Файловый писатель — `apps/desktop/electron/main/log-file.ts` (новый); `utilityProcess.fork` процессов движка и хоста расширений получает `stdio: 'pipe'`, main читает их stderr построчно, пишет в файл и повторяет в свой stderr (вывод для разработчика прежний). Каталог журнала движок получает как `EngineConfig.logsDir`; читатель — порт `LogReader` (`packages/engine/src/ports`, новый) с файловым адаптером в `apps/desktop/electron/host/`; `extensions.readLogs({extensionId?, minLevel?, limit?≤500})`. Фильтр по расширению — по полю `extensionId` записи: раннер ограниченного процесса его уже добавляет, а для доверенных расширений в процессе хоста `ctx.logger` оборачивается логгером с `extensionId` в `runtime.ts` (где создаётся `context`). Лимит вывода — скользящее окно 60 с в `restricted-runner.ts` (там, где `onOutput` сейчас пишет каждую строку без предела). Лимиты IPC измеряются в обработчике `child.onMessage`: размер — `JSON.stringify(message).length` после приёма, поэтому мера защищает от лавины, а не от одного огромного сообщения до разбора; частота — фиксированное окно в 1 с. «Скопировать диагностику» — чистая функция `pages/settings/lib/diagnostics-report.ts` над DTO `diagnostics()` и сведениями об экземпляре движка; текст — английский, технический (как логи), кнопки и подписи — `vue-i18n`.

**Контракт.** Каждая стадия, меняющая контракт (1a: `diagnostics`; 1b: `safeMode`, `diagnostics()`, `restartHost()`; 1c: `readLogs()`), поднимает `CONTRACT_VERSION` один раз до «следующей версии на момент слияния»; число в спеке не фиксируется. Новые методы добавляются в `RPC_METHODS`, схемы RPC, `testkit` и тест паритета (`assert-same-keys`).

**CI (1d).** Отдельный `.github/workflows/desktop-checks.yml`, чтобы не замедлять обычный `ci.yml`: задача `smoke-packaged` (матрица `macos-14` и `ubuntu-latest` под `xvfb-run`), задача `e2e` (только Linux, `xvfb-run`; `schedule` ночью, `pull_request` в `main`, `workflow_dispatch`). На Linux Chromium-песочница настраивается шагом workflow (SUID на `node_modules/electron/dist/chrome-sandbox`), а не флагом `--no-sandbox`, чтобы поведение приложения не менялось. `e2e/global-setup.ts` на Linux не готовит `Electron.app` (ветка darwin уже условная); пути Linux в `scripts/smoke.mjs` («не проверено» в README) подтверждаются первым запуском. Документация: раздел E2E в `apps/desktop/README.md`, «CI/CD» в `AGENTS.md`, скилл `git-workflow` (шаг 3 релиза).

**Документы.** `docs/design/extensions.md`: новый раздел «Диагностика и безопасный режим», правка «Пределы» (пункты 3 и 10: лимиты вывода и IPC теперь есть, лимитов кучи по-прежнему нет), раздел «Метаданные и совместимость» (диагностики вместо строки).

## Surprises & Discoveries

Разведка до начала работ (по коду `develop`, 4b68e37):

- Диагностики сейчас — свободный текст: `DiscoveryDiagnostic.message` и `ExtensionInfoDto.message` (`discover.ts`, `registry.ts` `invalidItems`/`overriddenItems`); несовместимость по `minAppVersion` и платформе показывается как `invalid` с текстом `requires app >= X` (`packages/extension-catalog/src/compat.ts`).
- `loadProject` в `extension-tools` копирует байты исходного манифеста в `dist-ext/<id>/extension.json` без разбора (`project.ts`, `copyStatic`): `$schema` сохранится, поэтому приложение обязано его принимать (R5).
- `inspectExtensionDir` используют и приложение (`installer.ts`), и авторские инструменты (`catalog/check.ts`, `validateExtension`): правка формата результата затрагивает обе стороны, текст R3 сохраняется общим `formatDiagnostic`.
- Хост расширений «сдался» (`gaveUp`) только в замыкании `ext-supervisor.ts` и пишет в лог; сброса нет до перезапуска приложения. Приостановка ограниченного процесса (60 с) молча отвечает `activation-failed` (`restricted-runner.ts` ~L408).
- Вывод ограниченного процесса пишется в логгер построчно без предела (`restricted-runner.ts` ~L340); IPC-сообщения проверяются по форме (zod), но не по размеру и частоте.
- `ctx.logger` в процессе хоста (доверенные расширения) — общий логгер хоста без `extensionId` (`runtime.ts` ~L332); `extensionId` добавляет только раннер ограниченного процесса (~L264). Без правки фильтр журнала по расширению пропустит логи доверенных расширений.
- Логгеры main/engine/host пишут только JSON в stderr (`electron/main/logger.ts`), файла и просмотрщика нет.
- CI не запускает e2e, `pnpm smoke`, `pnpm smoke:packaged`; Linux-пути упакованного смоука не проверялись; недавние дефекты (нет `zod` в упакованном приложении, сон macOS в e2e) CI не поймал. На Linux-раннере Ubuntu 24.04 непривилегированные user namespaces могут быть ограничены AppArmor [INFERENCE]: SUID `chrome-sandbox` обходит это.

Стадия 1a (реализация):

- `parseManifest` теперь возвращает `{ok: false, diagnostic}` (код `manifest-invalid`, `data.issues`), а не `message`: текст строит `formatDiagnostic`. Затронуты `project.ts`, `catalog/build.ts` и тесты, читавшие `.message`.
- `copyInfo` в `services/extensions.ts` копировал `contributes`, но не `diagnostics`: массив делился бы с реестром. Добавлено `structuredClone(info.diagnostics)`; тест «returns copies» ловит это.
- `verify-packages.mjs` падал на сгенерированном проекте: `extension-api` стал прямой devDependency, а переопределение `overrides` конфликтовало с ним (`EOVERRIDE`). Прямая зависимость указывает на локальный tarball, `overrides` ссылается на неё через `$@dolphy-app/extension-api`; добавлена проверка, что `$schema` демо-проекта указывает на существующий файл после установки.
- Режим `--local` генератора связывает `extension-api` ссылкой `link:` на каталог пакета, где схема лежит в корне, а не в `dist/`: путь `$schema` в таком проекте не разрешается (в опубликованном пакете и в `verify-packages` — разрешается). Остаётся допущением режима разработки репозитория.
- `extension.schema.json` занесён в `.prettierignore` (генерируется и сверяется побайтно, форматтер ломал бы сверку).
- `ajv` добавлен devDependency `extension-tools` ради проверки примеров `docs-contributions` по схеме.

Стадия 1b (реализация):

- Сообщение хоста `health` сделано запросом хоста `health.report` (`protocol.ts`, `kind`: `activated` | `suppressed` | `reset`), а не отдельным видом сообщения: он идёт готовым путём ограниченный процесс → раннер → рантайм хоста → канал → `ExtensionHostServices.health` и раннер сам подменяет `extensionId` своим, как у `storage.*`. Отдельный тип сообщения потребовал бы второго пути для процесса.
- `ExtensionHealth` (порт `packages/engine/src/ports/extension-health.ts`, реализация `app/extension-health.ts`) создаётся до движка (`boot.ts`): клиенты хоста и диспетчер событий строятся раньше `createEngine` и пишут сбои в тот же экземпляр, который движок отдаёт как `extensionHealth` в `EngineDeps`. Вместе с ним в `EngineDeps` добавлен `extensionHostControl` (порт `restart()`; в `boot.ts` — сообщение `reset-ext-host` в main).
- Спека не называла событие, но окну нужно знать об изменении здоровья и состояния хоста без опроса: добавлено `{ type: 'extension-health-changed' }` (контракт 15, `exhaustive.test-d.ts`). Публикуется `bus.publish` вне очереди команд, потому что сбой приходит не из команды.
- `extensions.diagnostics` и `extensions.restartHost` добавлены в `UNQUEUED`: окно обязано видеть остановленный хост и мочь его запустить, пока в очереди висит долгая команда.
- Порог приостановки в `restricted-runner.ts` был «более 5 выходов» (шестой); R9 требует пятое падение за 60 с, порог стал `>= MAX_EXITS`. Тест цикла падений переписан под пятый выход и проверяет сообщение движку.
- «Убийства и приостановка — состояние, а не сбой» реализовано в самом учёте: `recordFailure` игнорирует отказы, пока `suppressedUntil` в будущем (иначе каждый отказ приостановленному расширению рос бы как новый сбой). Потеря хоста (`host-down`), `replaced` и `unknown-command` сбоями не считаются; правила оценки сбоями не считаются вовсе (спека называет команды, события и виды заданий).
- Безопасный режим не меняет `toggleable` строки: переключатель «Включено» остаётся, но пока режим действует, расширение отключено независимо от него (так же ведёт себя отзыв в каталоге).
- Дизайн-ревью баннера (настоящий Electron, светлая и тёмная темы, 640/900/1280 px): белый текст на заливке `warning` давал контраст около 3,2:1 (P1), переключатель «Безопасный режим» в панели переносил «Обновить» на вторую строку (P2), текст баннера обрезался одной строкой (P2). Баннер теперь на `surface-variant` с рамкой и значком `warning` (контраст текста 5,18:1 и 6,39:1), текст в две строки, переключатель с пояснением — отдельным блоком над списком. Скриншоты не коммитятся.

## Decision Log

- 2026-10-04. Обратная совместимость не обеспечивается (владелец): приложение и расширения сырые, ломаем сразу. Причина: экономия усилий, нет внешних пользователей API. Следствие: «храповик» (терпимый разбор, `@since`, гейтинг `minAppVersion`) отменён, `message` заменяется на `diagnostics` без переходного поля.
- 2026-10-04 владелец: уровень безопасности как у Obsidian — обзор, безопасный режим, диагностика. Вне объёма любой волны: независимый аудит, песочница ОС, подписанный индекс, сетевой контроль, лимит кучи V8, отклонение симлинков, процессные тесты на нескольких ОС. Лимиты вывода и IPC входят сюда как работа над устойчивостью.
- 2026-10-04. Стадия «1b RESILIENCE» из плана разбита на 1b/1c/1d (безопасный режим и здоровье; журнал и пределы; CI): каждый PR ревьюится отдельно. Причина: исходная 1b — шесть независимых подсистем.
- 2026-10-04. Баннер безопасного режима — в оболочке приложения, на всех страницах. Причина: пользователь, запустивший флагом, иначе не узнает, почему расширений нет, не открыв настройки.
- 2026-10-04. Безопасный режим отключает origin `dev` тоже. Причина: цель — запуск без чужого кода; разработчик снимает режим флагом.
- 2026-10-04. Здоровье хранится в памяти и не переживает перезапуск. Причина: счётчики нужны для текущего сеанса; персистентность потребовала бы схемы `engine.db` без запроса.
- 2026-10-04. Журнал пишет main (перехват stderr процессов через `stdio: 'pipe'`), а не каждый процесс сам. Причина: один писатель — одна ротация, нет гонок за файл.
- 2026-10-04. JSON Schema коммитится и сверяется тестом, а не генерируется при сборке. Причина: схема нужна редактору в репозитории и в пакете без шага сборки.
- 2026-10-04. CI-проверки вынесены в `desktop-checks.yml`, а не в `ci.yml`. Причина: они на PR только в `main`, `ci.yml` остаётся быстрым для PR в `develop`.
- 2026-10-04 (1a). Контракт 14: поле `diagnostics` вместо `message`; номер — следующий свободный на момент слияния, при конфликте пересчитывается. Коды `safe-mode` включены в закрытый список сразу (по спеке), использовать их начнёт 1b.
