# Укрепление ограниченного процесса и упаковки

Живой документ, пока `status` — `draft` или `active`: `Progress`, `Surprises & Discoveries`, `Decision Log` обновляются вместе с кодом. По завершении фичи переносится в `specs/archive/` и не меняется. Правила — скилл `spec-workflow`.

## Цель

Ограниченный процесс расширений и упакованное приложение закрыты настолько, насколько это возможно без смены архитектуры: упаковка отключает ненужные возможности Electron (fuses), процесс расширений получает дополнительные ограничения и лимиты, проверяемые обходы закрыты или честно записаны как предел. Решение «оставить `RunAsNode`» и условия, при которых его надо пересмотреть, зафиксированы в ADR.

## Не цели

- Отказ от `ELECTRON_RUN_AS_NODE`: запуск ограниченного процесса через бинарник Electron остаётся (альтернативы — отдельный Node, SEA, песочница ОС — разобраны в ADR 0011 и откладываются до открытия каталога сторонним авторам).
- Ограничение сети кода расширения и квоты процессора и памяти сверх лимита кучи V8: на Node 24 недоступны (`--allow-net` появился в Node 25), нужен Electron с Node 26+ или песочница ОС.
- Подпись индекса и файлов каталога, автообновление.
- Перенос загрузки окна с `file://` на собственный протокол (если `GrantFileProtocolExtraPrivileges` нельзя выключить без этого, остаётся включённым и записывается как предел).

## Требования

Наблюдаемое поведение. Проверки — юнит-тесты, процессные тесты на реальном дочернем процессе, `pnpm smoke`, `pnpm smoke:packaged`.

- R1. Упакованное приложение собирается с явно заданными fuses: `RunAsNode` включён (обязательный компромисс, записан), `EnableNodeOptionsEnvironmentVariable` и `EnableNodeCliInspectArguments` выключены, `OnlyLoadAppFromAsar` и `EnableEmbeddedAsarIntegrityValidation` включены, `GrantFileProtocolExtraPrivileges` выключен, если приложение после этого запускается и окно работает, иначе остаётся включённым с записью причины. Для неподписанных сборок macOS arm64 подпись пересоздаётся. Проверка: `pnpm smoke:packaged` читает схему fuses из собранного бинарника и падает при расхождении с ожидаемой; сценарии `isolated` и `sql` проходят на упакованной сборке.
- R2. `pnpm smoke:packaged` выполняется в CI (macOS arm64 обязательно, Linux, если запуск возможен без дисплея) и перед выпуском; расхождение fuses или падение сценариев блокирует слияние.
- R3. Проверки обходов из ограниченного процесса выполняются настоящим пробником (в e2e/смоуке и процессном тесте): `process._debugProcess(process.ppid)` и вызов инспектора против другого процесса, `process.dlopen` без `native.addons`, `inspector.open()`, `process.kill` по чужому pid, чтение через символическую ссылку из каталога расширения наружу, сетевое соединение (документируется как разрешённое), `process.binding`. Каждый пробник даёт зафиксированный результат (запрещено / разрешено); разрешённое, что можно закрыть флагами и fuses, закрыто, остальное записано в «Пределы» с причиной. Если `_debugProcess` позволяет открыть инспектор хоста расширений из ограниченного процесса, это исправляется или обходится в этой же фиче (выключенный `EnableNodeCliInspectArguments`, флаги дочернего процесса, проверка порта), а не просто документируется.
- R4. Дочерний процесс запускается с дополнительными ограничениями: предел кучи V8 (`--max-old-space-size`, значение выбрано так, чтобы не ломать расширения из поставки и фикстуры, записано как константа), `windowsHide`, фиксированный рабочий каталог, `detached: false`; `--disallow-code-generation-from-strings` добавляется только если расширения из поставки и проверки схем в процессе продолжают работать. Вывод дочернего процесса в лог ограничен по объёму и частоте; сообщения IPC ограничены по размеру и частоте, превышение завершает процесс с понятной причиной в логе.
- R5. Расширения с символическими ссылками (внутри каталога расширения на файл вне него, неправильные типы файлов) отклоняются при обнаружении и при запуске ограниченного процесса с понятной причиной в «Настройки → Расширения»; сам каталог расширения может быть ссылкой (режим разработчика).
- R6. Главный процесс отклоняет все запросы разрешений сеанса (`setPermissionRequestHandler`, `setPermissionCheckHandler`), ответы протокола `dolphy-ext` для страниц рамки несут `Permissions-Policy`, закрывающую датчики, камеру, микрофон, геолокацию и т. п.; навигация и открытие окон блокируются для любых `webContents`, включая подкадры (`will-frame-navigate`), а не только главное окно. Проверка: юнит-тесты оболочки и e2e: рамка расширения не может сменить свой адрес и открыть окно.
- R7. Документация: ADR 0011 (решение по fuses и `RunAsNode`, рассмотренные варианты, критерии пересмотра), раздел «Пределы» в `docs/design/extensions.md` обновлён (предел №4 и сопутствующие, `process.spawn` равнозначен полному доверию, `_debugProcess`, сеть, квоты), README приложения описывает fuses и проверку.

## Решения

- **Принять `RunAsNode` с компенсирующими мерами.** Для запуска ограниченного процесса с `--permission` через `utilityProcess` нет рабочего пути (ADR 0003), отдельный Node или SEA добавляют 50–120 МБ на платформу, подпись и сопровождение и переносят риск «чужого интерпретатора», а не снимают его. Реальный прирост риска от `RunAsNode` — для локального атакующего, уже исполняющего код пользователя (macOS: наследование TCC; корпоративные списки разрешённых программ). Компенсация: выключить `NODE_OPTIONS` и флаги инспектора, ограничить сам дочерний процесс, проверять пробниками.
- **Пробник `_debugProcess` — первым.** По документации Node 24 он не входит в модель разрешений и может включить инспектор в любом процессе пользователя. Пока пробник не запущен на настоящем Electron, нельзя утверждать, что изоляция держится; результат определяет объём работ по R3.
- **Fuses через `electron-builder.json` (`electronFuses`)**, перед подписью (builder переворачивает их до подписи); смоук читает схему из готового бинарника, чтобы молчаливый пропуск настройки не остался незамеченным.
- **Лимит кучи, а не квоты.** `--max-old-space-size` ограничивает только кучу V8; настоящие квоты процессора и памяти требуют песочницы ОС (этап по условию, ADR 0011).
- **Новых контрактов и пакетов нет;** спека нужна как документ решения со списком пробников и условиями пересмотра.

## Surprises & Discoveries

Разведка до начала работ: ни один fuse не настроен (упаковка использует умолчания Electron 44: `RunAsNode`, `NODE_OPTIONS` и флаги инспектора включены); `smoke:packaged` в CI не запускается; по документации Node 24 `process._debugProcess` не ограничен моделью разрешений; в `apps/desktop/electron` нет обработчиков разрешений сеанса и охраны подкадров; сеть не ограничить на Node 24 (`--allow-net` — Node 25+), Electron 44–46 встраивают Node 24.
